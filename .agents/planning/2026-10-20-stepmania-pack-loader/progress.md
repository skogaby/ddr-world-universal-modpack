## Deviations & open questions

- Step 11: the plan's "record the quarantine capability in `index.bin` keyed by the PE
  stamp" and "cap the injected count if the arena patch did not land" were not built — the
  approved design §4.14 / task file don't carry them; the index self-check stays strict, and
  Step 3's `startup_arc_seen` WARN already flags a missed arena patch. Radar acceptance
  criterion is moot on 20260721 (E8 refuted); the exclusion ships anyway as cheap insurance.
  A quarantined final item whose record was already in flight at plan build (never seen —
  the pump opens the first ~4 records) is analysed on its loaded buffer, neutered; a
  non-walkable buffer there would stall the readiness gate like any stock file.

- Step 10: with split discovery active, an unknown basename resolves to `Choice::Base` (the
  mod's documented behaviour), not the stock original. `chart_length` opens only `<b>.ssq`,
  so split-timing injected songs show no wheel LENGTH (pre-existing limitation). Doubles
  whose timing differs from the single of the same level are hidden (design rule).

- Step 9: the collector breaks at the first note past the bound, so a NEGATIVE scroll factor
  (non-monotone offsets) drops later notes from the draw; speed→0 collects every remaining
  note (SM behaves the same; watch frame cost). Per-chart `#SCROLLS/#SPEEDS` that differ
  between declared charts fall back to the song-level tables (renderer seam has no
  difficulty context) with an index-time WARN.

- Parser strictness vs StepMania: an unclosed hold head (`2` without `3`) and an orphan tail
  reject the chart today; StepMania turns the head into a tap and ignores the tail. Two Tech
  Spectrum Super songs (`Tell`, `Glacierfall`) lost to this — adopt SM semantics (warn, keep).
- Cold index time scales ~25 ms/song (15.4 s for 627); the `index_timeout_s` 30 s default
  covers ~1,200 songs cold. Larger libraries inject a partial first boot (by design) — maybe
  raise the default or mention in the README (Step 13).

- Step 8 risk: the progressive writer holds `.part` open for write while the game opens it
  for read; if libavs opens without `FILE_SHARE_WRITE` the game's open fails → fallback
  (WARN `open … was refused`, wait for `done`, rename, serve complete = Step 6 stall). Plan
  B if seen: keep the file closed and serve the in-flight bytes from memory inside the read
  hook (we already own the fd). Rename of an open file is refused on real Windows → `.part`
  served complete until the next boot sweeps it.

- Step 6 run #5: second rejected song not identified (only Cheper's WARN captured — the
  other predates the debughook attach); check `sm_pack_check` over the pack (it reported
  134/134 OK, so the second reject is likely the audio-duration cap too). Audio duration cap
  900 s rejects long stamina songs ("[15] Cheper" 20 min) — consider raising `max_song_minutes`
  to 30 for stamina packs (bank ≈ 3 MB/min → 90 MB) in Step 12.

- Step 6: the injected taint is level-written by the full-bank request stream (injected →
  set, stock → clear) and cleared by `reset_session` — NOT by `reset_song_taint`, because
  in-place quick restarts fire that without re-opening the bank. Slow-cabinet folder/series
  registration happens from `StepmaniaPacksMod::init` (listed before series/folder
  expansion), fast-cabinet from the `startup.arc` fingerprint callback; both idempotent.
  `title_yomi` quotes only parentheticals; `bpmmin`/`property` emitted. No splash line yet.

- Possible hardening outside this feature: `training_mode::scrub` has only a one-in-flight
  guard; key auto-repeat yields ~9 seeks/s (one XACT cue create/teardown each). A minimum
  scrub interval (~250 ms) would bound that. Not implicated by evidence; noted for the
  maintainer.

- Step 5: XSB is NOT byte-identical to the tool's — wave indices are main→0/preview→1 to
  match our main-first XWB (the tool's order would play the preview clip as gameplay audio);
  `write_song_profile_indexed(.., WaveIndices::TOOL)` reproduces the tool's bytes. No seek
  tables (stock ADPCM banks have none; the flag bit is cosmetic). MP3 CBR `Info` frame decoded
  as one frame of silence (StepMania `handle_first_frame` behaviour); Vorbis gapless on (lib-
  vorbisfile semantics), MP3 gapless off (libmad). Lead-in at 44.1 kHz is ±0.5 ms inexact
  (block ≠ whole ms); 48 kHz exact. ADPCM bytes differ from the CLI's by 0.12 % (symphonia vs
  lewton ±1 LSB) — inaudible. Preview length clamped to 20 s with fades (CLI: 24.857 s hard cut).
  `--lead-in auto` is 0 for the test song (td0 241 ms, first note 3.67 s), so the lead-in path
  is exercised on the cabinet with an explicit `--lead-in 2000`.

- Step 4 writer: in the per-chart-timing split case NO base `<b>.ssq` is emitted (only
  `<b>_N.ssq`, N = level+1, pattern A of `split_ssq_research.md`). Until Step 9's `ssq_path`
  chain answers `build_ssq_path(b, N)`, **Step 6 must not declare songs whose bundle lacks
  `files[0].index == 0`** (or must force song timing) — otherwise boot opens `<b>.ssq`, finds
  nothing and risks `ME1529`.
- `Expert` as a simfile difficulty name maps to Challenge (StepMania's own alias table), not
  DDR's Expert slot. `K` cells are empty panels (not stripped). Zero/negative-length warps are
  no-ops; positive warps hide the chart.
- `WriteOptions.lead_in_ms` contract: writer shifts every anchor by `lead_in + sync_bias`;
  the audio side prepends exactly `lead_in_ms` of silence (whole ADPCM blocks); read the real
  `td0` back from the written bytes (delay-at-beat-0 folds into it) rather than recomputing.

- Test pack (`Stamina RPG 5`) is `.sm`-only, Vorbis, one Challenge chart per song, titles
  carry `[level] [bpm]` prefixes and the banner is pack-level (`../srpg5adefbn.png`).
  Good E1 subject; an `.ssc` pack with multiple difficulties will be needed from Step 4 on.
- Clone entries share one SSQ (copied per clone name) and have no audio — E3 only.
- **Jacket PNG members must be stored raw** (LZ77 member ⇒ coloured-square texture).
  Thumbnail DDS members may be compressed. The DLL's `core/arc.rs` writer is uncompressed,
  so the real feature is unaffected; recorded for the design's §4.6 art containers.

## Key facts for a cold resume

- Any remap of `get_offset_y` MUST keep the guideline drawer on the stock function: it is
  the only caller that iterates until the offset exceeds the bound (unbounded by note
  count). The note collector and the tap/freeze pass iterate notes (bounded).

- Race direction differs per cabinet: CrossOver reaches the `startup.arc` open seconds after
  `resolve_all`; the Win7 tester reaches it before. Both paths are covered (pre-repack hook +
  `early_apply`, one static patch state).

- FileManager I/O = one worker thread (E2); never the render thread. XWB reads 1 MiB.
- `/lastplay` leaks the injected mcode; `mod_judge_offsets` leaks tuned basenames only.

- Injection route for the spike: full-file `startup_arc/data/gamedata/musicdb.xml` overlay
  (the `musicdb.merged.xml` fragment route does NOT reach the game's DB).
- Visibility contract under test: `limited_ary 0` + `diffLv 1..19` on existing slots,
  `-1`/`0` elsewhere; basename ≤ 6 chars; mcode 9000001.
- Thumbnails are requested per series at boot; series 30 is an operator custom series in
  `mod-config.json`, so the game asks for `jacket_thumbnails_<ja|ua>_30.arc`.
