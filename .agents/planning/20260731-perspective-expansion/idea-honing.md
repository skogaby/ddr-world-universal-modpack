## D1 — Preset set & enum order

**Question:** Which presets, what order, and do we expose intensity levels?

**Recommendation:** Exactly the Simply Love five: OVERHEAD(0), HALLWAY(1), DISTANT(2),
INCOMING(3), SPACE(4). Values append to the existing enum (wire-compatible with saved
profiles). No fractional variants — Simply Love itself exposes none (its metrics rows
apply the stock mod strings at level 1.0), and the enum row has no natural intensity UI.
Intensity lives in operator config instead (D5).

## D2 — Implementation tier

**Question:** Constants-only, VS edit, or new shader programs?

**Recommendation:** The hallway architecture explicitly anticipated this: "one
parameterized program + constant presets" was the accepted design (hallway design R5 /
Appendix A), and per-perspective programs were rejected as container churn. Analysis
confirms all four presets are expressible in the existing hyperbolic map with different
constants — anchor Y (c48.x), convergence X (c48.y), direction sign (folds into c48.w),
clamp (c49.x) are all already DLL-computed inputs. The only missing degree of freedom is
a base zoom for the positive-tilt presets (D3), hence the one-line VS edit using the
already-reserved c49.y. Blob recompile is routine (`scripts/build_shaders.sh`,
fingerprint cache regenerates containers automatically). Rejected: new programs 2..4
(format supports it, architecture forbids it, and nothing needs it).

## D3 — Positive-tilt anchor strategy (the decision the user likely hasn't considered)

**Question:** Under Distant/Space, where does the field's s=1 fixed point sit? SM
rotates about the mid-field pivot, so its near end renders LARGER than stock (~1.07×
after its own 0.9 zoom) — tolerable there because SM's lane dressing rotates with the
field. DDR's dressing is stock-rectangular (affine-only AFP, an accepted hallway
carve-out), so a field wider than the stock rectangle spills over the filter band.

Options considered:
- (a) Anchor at receptor row (like hallway, sign flipped): entire approach region
  scales > 1, gross overflow. Rejected.
- (b) Anchor at entrance edge: s ≤ 1 strictly, but receptors displace enormously
  (hundreds of px toward the horizon). Rejected.
- (c) **Mid-field anchor + base zoom z0** (SM's own compensation shape): modest
  receptor displacement (matches SM's look), overflow tunable to ≈ 0 by choosing z0
  and k so the entrance-edge scale ≈ 1. Recommended. Defaults derived in design;
  tuned live like `hallway_focal` was.

## D4 — Skew handling

**Question:** Incoming/Space converge on screen center. In versus, a side lane's far
end shifts ~125 px toward center and exits the stock filter band on one side. Accept,
mitigate, or drop the skewed presets?

**Recommendation:** Ship SM-authentic (cx = 640) with an operator `skew_strength`
tunable (0..1 lerp from lane center to screen center; 1.0 default). The spill is a
dressing mismatch of the same class the hallway design already accepted (stock
rectangle vs trapezoid field) — document it. Doubles: lane center is already 640, so
Incoming≡Hallway and Space≡Distant there, exactly as in SM.

## D5 — Config tunables

**Recommendation:** Extend `PlayerPerspectiveConfig`: `distant_focal` (px, analog of
`hallway_focal`), `distant_zoom` (z0, default 0.9), `skew_strength` (default 1.0).
Incoming shares `hallway_focal` (identical vertical geometry); Space shares the distant
knobs. Draw-distance contribution (`hallway_draw_distance`) applies when any side
latches a negative-tilt preset (hallway OR incoming); positive-tilt presets contribute
nothing (their map expands the near field — notes cross the screen edge continuously,
no pop-in; extra contributed distance from the other player is harmless overdraw).

## D6 — Preview/label assets

**Resolved (user-refined):** All assets are generated, fully text-based, by extending
`scripts/gen_option_labels.py` — exactly how the existing overhead/hallway assets are
produced (verified: `seop_op_overhead/hallway` come from the `RIBBONS` list, 132×24
teal text chips; `seop_image_perspective_overhead/hallway` come from `Preview(...,
WIDE, [copy])` entries, 368×172 text panels; no screenshots anywhere). The work:

- `RIBBONS` += `("distant", "DISTANT"), ("incoming", "INCOMING"), ("space", "SPACE")`
- `PREVIEWS` += three `Preview("perspective", <key>, WIDE, [...])` entries with body
  copy in the established voice (cf. hallway: "Arrows scroll in from a vanishing
  point, growing as they approach the STEP ZONE.")
- Regenerate; commit **net-new PNGs only** and `git restore` the encoder churn on
  every pre-existing label (known generator gotcha).
