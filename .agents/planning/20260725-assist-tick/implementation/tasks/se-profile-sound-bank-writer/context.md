## Format facts the SE profile depends on

From `research/xact-bank-format.md` §5.5 (engine validator `FUN_0040e970`, transcribed) and
§5.6 (stock sound-entry profiles, decoded):

- Stock **gameplay SE** sounds (`se_normal.xsb`): `category = 6` for all 138; `flags = 0x00`
  and `entry_length = 12` for 129 of them. That bare 12-byte form is the model.
- Stock **system SE** sounds (`se_system.xsb`): `category = 5`, `volume = 254` (`0xFE`) on
  `SYS_COIN` / `X_sys_OK1`. 254 is the volume this writer uses — an assist tick has to be
  audible against the music.
- The 12-byte SE sound entry, byte for byte (research §8.3, with `wave_index` amended 0):
  `00 06 00 FE 00 00 00 0C 00 | 00 00 | 00`
  = flags 0x00, category 6, volume 0xFE, pitch 0, priority 0, entry_length 12,
    wave_index 0, wavebank_index 0.
- Validator rule 15b: `u16 @ 0x19 == max(16, simple + complex)` ⇒ still **16** with one cue.
- Validator rule 17: every hash bucket must be `0xFFFF` or `< total_cues` ⇒ with one cue the
  only legal occupied value is `0`.
- Validator rules 8 / 11 / 16 / 18 / 19 / 21: every section offset must equal the running
  cursor **exactly**, and the cue-name string table must run **exactly** to EOF, whose last
  byte must be `0`. This is why R5 says recompute rather than assume.
- Cue lookup (`GetCueIndex`) is a byte-exact `strcmp` ⇒ case-sensitive (R4).

## Ambiguities and how they were resolved

| Ambiguity | Resolution |
|---|---|
| Entry-point name/signature ("implementer's discretion") | `pub fn write_se(name: &str, out: &mut impl Write) -> Result<(), XsbError>` — the shape the task file itself suggests, and symmetric with `write` |
| Should category/volume be parameters? Research §8.3 floated `write_se(code, category, volume, out)` | **No.** R3 fixes the category at 6, and the repo's anti-pattern list calls out over-abstracting early. Named constants instead |
| `XsbError::BadCode`'s message says "song code", which reads oddly for an SE bank name | Keep it. R8 says reuse the existing error type, and rewording it would change the song path's user-visible message |
| Golden-file tests are discouraged for binary formats in `rust-cli-standards.md` | A1–A8's criterion 6 explicitly asks for one, and the point of *this* golden is that it must never be regenerated. Kept **inline** in the test module so any change shows up in the diff |
