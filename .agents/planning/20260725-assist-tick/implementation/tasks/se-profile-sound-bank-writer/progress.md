## Verification beyond the unit tests

The engine **silently rejects** a malformed sound bank, so the 23 XSB validator rules from
`research/xact-bank-format.md` §5.5 (transcribed from `xactengine2_10.dll`'s `FUN_0040e970`),
plus the magic/tool-version gate (`FUN_004232c0`) and the CRC-16 (`FUN_00424200`), were replayed
against the generated bytes by a throwaway checker (`/tmp/xsb_validate.py`, not committed).

| Bank | Result |
|---|---|
| **stock `se_system.xsb`** (671 B, extracted from the install's `soundbanks.arc`, stored raw) | **PASS** — the control. A checker that rejects a stock bank is wrong |
| generated `asti.xsb` (SE profile, 262 B) | **PASS** |
| generated `test_song.xsb` (song profile, 326 B) | **PASS** |

And the checker was shown to be discriminating — four single-byte corruptions each tripped
exactly the expected rule and nothing else:

| Corruption | Rule tripped |
|---|---|
| CRC field | CRC mismatch |
| `sound_offset` | rule 8 (+ rule 9 walk) |
| `cue_name_table_length` | rule 21 |
| a hash bucket → `0x05` | rule 17 (bucket must be `0xFFFF` or `< cue_count`) |

### Findings worth carrying into tasks 02–03

1. **The generated SE sound entry is shape-identical to stock.** All 13 sounds in
   `se_system.xsb` are `flags=0x00, entry_length=12, wavebank_index=0` — exactly what
   `write_se` emits. The only intended differences are `category` (ours **6** = the gameplay-SE
   bus per `se_normal.xsb`'s 138 sounds, stock system bank uses 5) and `volume` (ours **254**,
   which is precisely what `SYS_COIN` and `X_sys_OK1` use).
2. **`wave_index = 0` has direct stock precedent** — `se_system.xsb`'s sound entry 9 points at
   wave index 0. This de-risks the design's 2026-07-25 amendment (single cue at wave index 0
   instead of the research's two-entry shape) at the *sound-bank* level; if the documented
   fallback is ever needed it will be for a wave-bank validator rule, not this.
3. **`total_cues = max(16, cue_count)` confirmed on stock** — `se_system.xsb` has 13 cues and
   declares 16 buckets, matching rule 15b and the constant this writer keeps.
4. Stock `se_system.xsb` also shows cue→wave mapping is arbitrary (its cue 0 points at wave 9),
   so nothing constrains task 02's naming beyond the byte-exact bank-name match.
5. **The AVSLZ port used to pull the other three stock banks out of `soundbanks.arc` was wrong**
   (only `se_system.xsb` is stored raw; the rest decompressed to garbage). Not needed here, but
   task 03's optional stock-bank comparison targets the **wave** banks, and `se_normal.arc` is
   stored **raw** while `se_system.arc` is **AVSLZ-compressed** — see research §2.1's correction
   note. Prefer `se_normal.arc` for that comparison, or port `avslz.rs` faithfully.

## Deviations

### D1 — Pre-existing clippy failure repaired to unblock acceptance criterion 8

`cargo clippy --all-targets -- -D warnings` was **already failing** before any edit, with two
`clippy::manual_checked_ops` errors at `src/job/mod.rs:391` and `:396`. That lint is new in
Rust 1.96; the code predates it. Toolchain drift in the *song*-bank `build_xwb_bank` duration
computation, unrelated to the XSB writer.

Acceptance criterion 8 requires that gate to pass clean, so it could not be met without
repairing them. Took the most conservative resolution: the minimal idiomatic fix at the two
sites (`len().checked_div(ba).unwrap_or(0) * spb`), behaviour identical for every input
including `ba == 0`, in a separate edit to a separate file so it is trivially separable from
task 01's change. Confirmed my own change contributed **zero** clippy findings before applying it.

### D2 — `documentation_dir` overridden away from `.agents/scratchpad/`

Rationale in `context.md` → *Why the working docs are here and not in `repo_root`*. Driven by
the modpack's `AGENTS.md` rule (the feature's planning directory is the one canonical location)
and by task 01's instruction not to modify anything else in `ddr-chart-tools`.

### D3 — Two existing test assertions updated to literals

`header_constants_match_spec` referenced `SIMPLE_CUE_COUNT` and `SOUND_COUNT`, which were
song-only constants and are now profile-derived. Rather than keep them alive as dead code (which
`-D warnings` would reject) or assert tautologically against `SONG_PROFILE.cues.len()`, the two
assertions now use the literals `2` and `2` with a comment naming what they count. Coverage is
unchanged and strictly independent of the implementation; byte-identity is separately guaranteed
by the golden.
