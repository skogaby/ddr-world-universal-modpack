## Functional requirements (restated)

From the task file, 8 requirements and 7 acceptance criteria:

1. Three `SignatureDefinition` entries in `src/core/signatures.rs`, patterns **exactly** as the
   research note gives them.
2. Address / RIP / stack / branch displacement bytes wildcarded; semantic immediates literal.
3. A `derive_*` method, called from `resolve_derived`, producing: the audio-manager global (RIP
   decode), the inner play function's entry (negative offset, prologue-verified, else
   `find_function_entry`), and the named-bank count (byte at a fixed offset, must read `4`).
4. Cross-check: the first `CALL rel32` in `se_play`'s body must target the derived inner function;
   warn naming both on disagreement, never panic.
5. Log every resolved/derived address as a **module-relative offset**.
6. Graceful degradation: one warning, return, rest of resolution untouched. No panics/`unwrap`.
7. No hardcoded absolute game addresses.
8. Nothing outside `src/core/signatures.rs` changes.

## Ambiguities found, and how they are resolved

1. **"Reports exactly one match" (AC1) is not what `resolve_all` proves.** `scan_patterns_batch` has
   first-match-per-name semantics, so a hypothetical second match would be silent — and S1's
   near-identical neighbour (`se_prepare_inner`, byte-identical for ~0x65 bytes) is exactly the case
   where that would matter. Resolved by having the derive method count matches with the existing
   `get_all_matches` and log the three counts, warning if any is not 1. Cost: three single-needle
   scans of the module at boot, in a function that already does several.
2. **Where to "record" the named-bank count (req 3).** `SignatureStore`'s map is
   `String → *const u8`, and the count is a value. Resolved by publishing the **address of the imm8**
   as a derived entry (`audio_named_bank_count_site`) and logging the value read from it. That keeps
   the `+0x2C` offset knowledge inside `signatures.rs` (req 8 / the no-hardcoded-offsets rule) while
   letting Step 2's `register_bank` re-read it for guard G1 without a new API.
3. **Chain B also offers `se_mute_filter`.** Not required by the task, the design, or Step 2's
   service, so it is not derived — an unused derivation is dead weight with a boot cost.
4. **The prologue length.** The note calls it "the 14-byte prologue" and then prints 15 bytes
   (`48 89 5C 24 08 48 89 74 24 10 57 48 83 EC 40`). The byte list is authoritative; all 15 are
   compared.

## Non-functional expectations

- Panic-free: this runs at init, but `resolve_derived` failing must not take the whole DLL down, so
  every read is bound-checked and every failure is a `log_warn!` + `return`.
- No new crate dependency; scanner primitives only (`decode_rip_relative`, `decode_call_rel32`,
  `scan_first_call_rel32`, `find_function_entry`) — never inline displacement decoding.
- The research note's per-build address tables are for a human comparing the boot log; **no absolute
  address appears in the source**.
