## Format constants (research §8.1, §3.3, §4.4)

```
format bits = 2 | (1 << 2) | (44100 << 5) | (48 << 23)   == 0x18158886
  codec 2 = MS-ADPCM, channels 1, rate 44100, block_align_raw 48
  derived (not stored): dwBlockAlign = (48+22)*1 = 70 bytes; samplesPerBlock = 128
```

| Bank field | Value | Why |
|---|---|---|
| `header_version` | **42** | Hard requirement — `WaveBank::IsHeaderValid` rejects anything else (research §3.2) |
| `flags` | **`0x0009_0000`** | TYPE_BUFFER (bit 0 **clear** — mandatory for `CreateInMemoryWaveBank`, §3.5) + ENTRYNAMES (bit 16) + bit 19. Byte-for-byte the stock in-memory value. `(0x00090000 & 0xFFF0FFFE) == 0` ⇒ passes validator rule 5 |
| `entry_name_element_size` | **64** | Rule 10 — required *unconditionally*, even with no names |
| `alignment` | **4** | Rule 11 minimum, and what both stock in-memory banks use |
| `compact_format` | `0` | Stock; unused on the non-compact path |
| `build_time` | **`0`** | Never validated (§2.2) — and fixing it at 0 is what makes R5 achievable |
| entries | **1** — the sound | Design amendment 2026-07-25 |
| `flags_and_duration` | `total_samples << 4` | Entry-flag nibble **must** be 0 (rule E1) |
| `loop_start` / `loop_length` | `0` / `total_samples` | Rule E7 is the only `Duration` constraint: `Duration >= loop_start + loop_length`. Equality is what stock `SYS_CARD` does |

`total_samples = blocks * 128`, `blocks = adpcm_len / 70`.

### The layout this produces (single entry, 4-character name)

`container::write` computes `seg2_off = seg1_off + seg1_len`, `seg2_len = 0`,
`seg3_off = seg2_off` — which is exactly what validator rule 15 demands, so the existing writer's
segment layout is *mandatory* rather than merely conventional.

| Segment | Offset | Length |
|---|---|---|
| header | `0x00` | 52 |
| 0 BANKDATA | `0x34` | 96 |
| 1 ENTRYMETADATA | `0x94` | 24 |
| 2 SEEKTABLES | `0xAC` | 0 |
| 3 ENTRYNAMES | `0xAC` | 64 |
| 4 ENTRYWAVEDATA | `0xEC` (236) | `blocks * 70` |

`file_len − 236 == seg4.length` ⇒ rule 20. For the assist-tick clap (9,423 samples ⇒ 74 blocks
⇒ 5,180 B) the file is **5,416 bytes** — *not* the 5,576 the research note predicted, because that
figure includes the two-entry shape's silent stub entry and its 128-byte name table.

## Determinism (R5) — and why the deterministic path must not run ffmpeg

The only non-deterministic field the container has is `build_time`, pinned to 0. Everything else
is a pure function of the decoded samples: `lewton` decode and the crate's own ADPCM encoder are
both deterministic, and their versions are pinned by `Cargo.lock`.

This has a consequence for **task 03**, worth recording here because it constrains that task:
re-encoding the source through `ffmpeg -c:a libvorbis` would make the output depend on the host's
libvorbis build, breaking both R5 and task 03's own requirement 9 ("re-running it on a clean
checkout must reproduce the committed bytes exactly"). So the committed asset must be generated by
feeding the committed `.ogg` **straight** to this generator. Research §8.1 already establishes
that no transcode is needed — `clap.ogg` is *already* mono 44.1 kHz. ffmpeg's role in task 03 is
therefore preparation/inspection of a *non-conforming* source, not part of the reproducible path.

## Design decisions

| Decision | Choice | Why |
|---|---|---|
| Where the generator lives | `src/job/se_bank.rs` | `structure.md`'s table gives `job/` "per-job orchestration (parse → model → write)". This is the direct analogue of the existing `job::write_ddr_audio` (decode → encode → build XWB → write XSB) |
| Where the dump lives | `src/xwb/dump.rs` | It renders XWB metadata; `xwb/` owns "XWB container parse + write" |
| How it is exposed (R1: "implementer's choice") | **A second binary**, `ddr-se-bank`, via `src/bin/se_bank.rs` + a `[[bin]]` entry | The alternatives are worse. A **subcommand** on the existing CLI would mean making the required `--from-format`/`--to-format` optional and restructuring `Cli::validate`/`into_jobs` plus 11 tests — a large blast radius on a working CLI for an unrelated feature. A **committed example** produces no installable executable, and task 03's requirement 4 explicitly wants a fallback to "the binary being on `PATH`". `Cargo.toml` already declares its `[[bin]]` explicitly, so adding a second is two lines and no restructuring |
| Accepted input container | **Ogg Vorbis only** | It is the crate's one real audio-decode capability, and the reproducibility argument above means the committed path feeds the `.ogg` directly anyway. Adding a WAV reader would need either a new dependency or format-parsing code in a module that `structure.md` says doesn't own it. A clean additive follow-up if the maintainer ever wants it |
| Error type | New `SeBankError` in `src/job/se_bank.rs`, wrapped into `crate::error::Error` with `#[from]` | Exactly the pattern `error.rs` documents: "Each format module defines its own `thiserror`-derived error; this enum wraps them via `#[from]`" |
| Test input for the "real input" criterion | **Synthesized** in-test with the crate's own `ogg::encode` | No fixture to license or commit, self-contained, and it exercises the real `ogg::decode` path. `tests/fixtures/` does not exist in this repo yet |
| Stock-bank comparison input | Env var `DDR_STOCK_XWB`, skip when unset/unreadable | Stock banks live inside the install's ARC containers, and this crate has no ARC/AVSLZ reader (that lives in the modpack). Extraction is task 03's job; this test consumes an already-extracted file if one is pointed at |

## Ambiguities and resolutions

| Ambiguity | Resolution |
|---|---|
| R2 says "transcode … with ffmpeg" is task 03's step, but R2 also forbids silent resampling. Which side normalizes? | The generator **rejects** non-conforming audio; normalization is the operator's explicit act, outside the reproducible path. Recorded above |
| A6 wants generated-vs-stock field comparison, but only some fields "the design requires to match" | Container version, flag bits, alignment, entry-name element size (task 03 req 5 names exactly these). Intended differences: bank name, entry count, per-entry format and length |
| The dump must expose enough for task 03's shell assertions of the container-validator rules | Rules 2/4/13/14/15/17/20 all need **segment offsets and lengths**, which `XwbBank` discards. So `describe` takes `&[u8]`, not `&XwbBank`, and reads the header's segment table alongside the parsed entries. Adding segment fields to the public `XwbBank` was rejected as invasive |
