## Functional requirements (from the task file, mapped to design)

1. **Nonblocking generation lifecycle** — phases Identity, Armed, Preparing,
   RedirectReady, XactInFlight, Committed, Completed, EarlyFailed, LateFailed
   (design "Generation State" + "Lifecycle State Machine"). Arm is atomic and
   never blocks; a busy arm fails closed to identity with a bounded warning.
2. **Scene-26 eligibility primitives** — entered side (`PlayerWork+0x4`, via
   `stage_records::player_work`), participant mask, stage index (GameWork stage
   counter), course exclusion (`GameWork + course_field_offset != 0`),
   solo/doubles ownership (exactly one entered side), rejection of
   local-versus (two sides), matching/BPL/demo/event (structurally excluded —
   separate scene ranges never enter normal scene 26; design req 12), and
   unknown modes (missing pointers/services → identity; design req 11).
3. **One permanent scene callback** — hot path reads only atomics/raw validated
   state; never waits, does I/O, calls game functions, or re-enters
   scene_manager (its callback iteration holds the `SCENE_MANAGER` lock —
   verified in `src/services/scene_manager.rs:108-126`; the "fire callbacks
   outside the lock" comment there is inaccurate, callbacks run under the lock).
4. **Developer-only diagnostic configuration** — one exact song code, 75%, and a
   pre-generated local XWB identity; missing/invalid config ⇒ identity.
5. **Per-side 8-entry pending rate-save rings** — generation/stage identity,
   duplicate suppression, Free/Pending/Claimed/Consumed states, Quick Restart
   dedup (append idempotent per generation), successful card-in reset ownership
   (per-side positive ddrcode match only).
6. **Full-sanitization readiness** — `score_guard::is_full_sanitization_available()`
   requires: save detour, decoded stage/course records, scene manager,
   registered EAM_EXIT sanitizer callback, league-node removal availability +
   tri-state semantics (absent = safe, removed = safe, removal failure =
   fail-closed suppression).
7. **Unknown side/stage decode fails closed while pending rate state exists** —
   never default to P1, never consume an unmatched pending entry. (Legacy
   default-to-side-0 behavior is preserved when NO pending rate state exists.)
8. **Tentative `MovieSuppressor::SongRate`** at accepted diagnostic arm;
   deterministic clearing only at the definitive lifecycle boundary
   (GAMEPLAY → non-GAMEPLAY exit, title/attract/new-session reset, or
   pre-exposure attempt abandonment).
9. **Q31 stays identity, no generated-path exposure, no score taint** until
   Task 2's transaction commits. (Ring append happens at commit — Task 2 wires
   it; Task 1 ships and tests the API.)
10. **Pure host tests** for every eligibility/state/save/policy transition; all
    local gates; **no deployment**.
11. Canonical progress update with Task 2 as next action.

## Interpretations and decisions recorded (auto mode)

1. **Stage identity source (scene-26 arm AND save-time decode)** = GameWork
   stage counter (0-based, GameWork+0xC on 2026 builds), read through a new
   `stage_records::stage_counter()` accessor whose offset is decoded from the
   `premium_free_stage_inc` signature disp8 with the same `FF 41 0C` byte
   validation premium_free performs (hoist pattern precedent: stage_records
   itself was hoisted from premium_free). Rationale: only proven decode
   available; savedata carries no RE-confirmed per-save stage field.
   Known risk: an ESS save delayed across the WaitSequence stage bump decodes
   stage+1 → claim mismatch → suppress-without-consume (conservative
   direction; a pending entry then blanket-suppresses that side until
   consumed/card-in reset). Blanket backstop: `is_stage_suppressed(side)`
   includes nonzero pending count (design Score Guard section). Upgrade path
   if Task 3 observes mismatch: scan savedata `/result` slots (+0xA70 +
   i*0x22B8) for the single non-virgin record — needs new ess.dll RE for the
   in-entry mcode offset.
2. **Claim semantics**: per-stage save (savekind==2) with decoded (side, stage):
   claim = oldest Pending entry in that side's ring with equal stage_index;
   suppress + mark Consumed. Consumed tombstones with matching (side, stage)
   keep suppressing duplicate sender retries without a new consumption. A
   non-matching save while the side has any Pending entry is suppressed
   WITHOUT consuming (fail-closed; over-suppression accepted). Unknown side
   while ANY pending entry exists on either side ⇒ suppress, no consume, no
   P1 default. Unknown stage while the side has pending ⇒ suppress, no
   consume.
3. **League-strip tri-state**: `strip_league_node` returns Absent / Removed /
   RemovalFailed. Absent and Removed forward. RemovalFailed logs an error and
   returns 0 from the trampoline (sender-failure signal) so the built,
   still-league-bearing request is not forwarded — the only post-build
   fail-closed lever. Realistically unreachable (node was just located; remove
   is a null-guarded unlink), and it is exercised only via the pure policy
   function in host tests.
4. **Readiness latches live in `score_guard`** (harness-pure; no cross-module
   reads of windows-only services): `mark_stage_records_ready`,
   `mark_scene_manager_ready`, `mark_sanitiser_registered`,
   `mark_league_strip_available`. `LEAGUE_STRIP_AVAILABLE` migrates from cop
   to score_guard (single source of truth; cop reads the score_guard getter).
   lib.rs latches stage-records/scene-manager after the respective inits; cop
   latches sanitiser/league at its registration/resolution points.
5. **Per-side card-in rate reset**: the load receiver cannot resolve side at
   receiver time (`PlayerWork+0x18` populates after the load — existing
   `PendingLoad` mechanism proves this). On successful load (result != 0),
   capture the load's ddrcode; on SONG_SELECT entry resolve ddrcode→side
   (`side_from_ddrcode`) and only then clear that side's ring + rate-session
   state. Failed/unidentified loads clear nothing. The existing broad
   `reset_session()` call is left untouched for the legacy autoplay model.
6. **Lifecycle/eligibility module** = new `src/services/song_rate/lifecycle.rs`
   (pure: atomic state machine, eligibility classifier on plain inputs,
   transition engine applying effects to injected `&MoviePolicy` +
   `&RatePublication`), plus a `#[cfg(windows)]` runtime glue module
   (`src/services/song_rate/runtime.rs`) owning the permanent scene callback,
   GameWork/PlayerWork reads, and diagnostic-config wiring. No
   `SongPlaybackSpeedMod` yet (player UI is Step 6); the service owns Step 4
   wiring.
7. **Diagnostic config**: `song_playback_speed` section in `mod-config.json`
   with `diagnostic: { song_code, requested_percent, xwb_path }`, honored only
   when LayeredFS developer mode is on (same gate as the design's
   `DDR_SONG_RATE_FAULT`). Only `requested_percent == 75` accepted in Step 4.
   Validation is a pure function in song_rate (host-tested); serde shape in
   `config.rs`. `cache_limit_gib` intentionally NOT added here (no runtime
   cache use until Task 2/Step 5 needs it).
8. **Armed-attempt corridor**: pre-exposure phases (Armed/Preparing/
   RedirectReady) abandon to Identity (movie cleared) when a transition leaves
   the {26, 27, 28} corridor without reaching GAMEPLAY; GAMEPLAY→GAMEPLAY
   retains everything (Quick Restart); GAMEPLAY→non-GAMEPLAY completes (Q31
   identity FIRST, then movie clear, score state retained); title/attract/
   new-session reset forces identity and clears non-score generation state.
9. **Legacy behavior preserved**: unknown playside with no pending rate state
   keeps the current default-to-0 + warn path (option persistence semantics
   unchanged); savekind FIRST/unknown never touch the rings.

## Ambiguities / observations flagged

- `scene_manager.rs` fires callbacks while holding its lock; the in-code
  comment claims otherwise. Design already accounts for this. Not fixed here.
- `load_receiver_trampoline` clears BOTH sides' session taint on ANY profile
  load (`score_guard::reset_session()`); a hypothetical mid-session second-
  player card-in would erase the first side's autoplay session taint. Latent
  pre-existing issue in the legacy model, out of Task 1 scope; rate state uses
  the positive-match path per design. Recorded for the maintainer.
- The validator hard-requires the sibling `ddr-chart-tools` checkout; the
  maintainer has requested an end-of-feature addendum task to make harnesses
  self-contained (recorded in canonical progress.md). Task 1 extends the
