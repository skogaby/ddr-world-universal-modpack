## Key facts

- Script structure: bash wrapper synthesizes a cargo harness in $TMP mounting real
  sources by #[path]; `main()` writes `target/song-rate-validation/report.json`;
  bash then runs a python schema check (lines ~1935+) — the TDD-red lever (require
  `on_demand` before implementing it).
- Harness runs on the HOST (macOS) — `song_rate::runtime` is #[cfg(windows)] and
  excluded; `conversion`/`lifecycle`/`worker`/`xact_runtime` are pure and mounted.
- Fixture pattern for driving the open redirect host-side:
  `src/services/song_rate/conversion_tests.rs::Fixture` (temp store +
  `DiagnosticCoordinator::new`, `LifecycleState::on_scene26(Arm{percent,mask 0b01,stage 0})`,
  `prepare_open_redirect(&env, "data/sound/win/dance/<code>.xwb", source_path)`,
  seam via `enter_frame(file_id)` + `prepare_streaming_redirect(..., |_| Some(rc))`).
- The harness's existing `build_source(false)` synthesizes a strict-profile bank
  with entries `synt`/`synt_s` — the dance path must be `data/sound/win/dance/synt.xwb`
  (GenerationRequest enforces internal-name == path stem).
- `completed_builds` counts FAILED builds too — use it only as an ACTIVITY delta
  (cold ⇒ +1, warm ⇒ +0), never as a success counter (task-01 gotcha).
- Warm-hit latency limits precedent (cache section): native-windows 100 ms else 250 ms;
  cold limit `latency_limit_ms(platform)` (15 s / 25 s).
- Report must contain NO absolute paths — record cache-key hex + file NAME only.
- New host-test FILES would need the script's file-existence list (~96-105) + harness
  mods — this task adds NO new test files (the demo lives in the harness main.rs),
  so no list changes needed.
