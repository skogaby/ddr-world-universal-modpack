## Functional requirements (from the task file)

1. `Binding` runtime state `{file_id, generation, rate, layout, source: Box<[u8]>,
   ring, pending: [PendingSlot; 4], state: AtomicU8 (Active|SilenceFill|Retired),
   readers: AtomicU32}`; construction takes an already-planned layout + private source
   copy (task-03's preflight supplies both).
2. `Ring`: fixed 16 MiB, atomics-cursored, cursors are ABSOLUTE VIRTUAL FILE OFFSETS
   (one linear producer cursor over entry0 + gap + entry1); `produced`
   Release-published / Acquire-read; window `[produced − capacity, produced)`
   serveable; reads below → regeneration target.
3. `PendingSlot`: `{state Free|Arming|Armed|Complete, buffer ptr, accumulator ptr,
   offset, len}` all atomics, SPSC per slot; completion memcpys + accumulates +
   marks Complete; cancellation completes with EOF-clamp semantics (0-byte permitted).
4. `generator.rs`: one `std::thread` per bound generation (`song-rate-generator`),
   generation-token checked every hop; BlockCachePcm → StretchState → whole-block
   accumulate → encode_block into the ring in virtual-offset order (gap zeros
   between entries); loop-start checkpoint; regeneration targets (restore +
   produce-and-discard to block-aligned target, or restart from zero); completes
   pending slots as ranges appear; `catch_unwind` → SilenceFill; superseded
   generations stop at the next opportunity.
5. Fault hook: injectable kill-after-N-packets knob → producer dies mid-stream
   through the same catch_unwind → SilenceFill path (task-03's `mid-song-failure`).
6. Per-generation metrics: frames produced, wall time, max deferral latency,
   deferral count — exposed for task-03's drain.
7. Pure serve dispatch: `(offset, len, dest, accumulator)` → Served(n) / Pending /
   Refused; PreData/Gap/Eof copy/zero/clamp + accumulate; EntryData in window →
   copy + accumulate; not-yet-produced / behind-window → arm slot (behind-window sets
   regen target first) → Pending; SilenceFill → silent ADPCM blocks immediately;
   allocation-free, log-free, panic-free (detour context in task-04).
8. Host tests in sibling `*_tests.rs` (validator harness auto-mounts); keep the added
   cargo-test cost well under the ~30 s total budget (Step-3 suites ≈ 8 s).

## Acceptance criteria (from the task file)

1. Ring-drained bytes == whole-buffer oracle (both physical entry orders, rates
   {50,175} min); reassembled file reparses and decodes.
2. Deferral exactly-once with stock accounting (accumulator carries served count
   once; poll-before-complete incomplete; second consume finds slot Free).
3. Behind-window reads regenerate deterministically (loop-restart read below window;
   re-served bytes identical).
4. Silence-fill keeps the stream valid (producer killed mid-stream; further reads
   complete instantly with valid silent blocks; state reads SilenceFill; stream still
   parses/decodes).
5. Reclamation waits for quiescence (Retired ∧ readers==0; retire-cancelled slots
   complete with clamp semantics).
6. All five gates green; readiness/row behavior unchanged (identity-only tree —
   `integration_available()` stays false; tripwires untouched).

## Ambiguities / assumptions (auto mode — recorded per the sop)

- **Field shapes are free, behavior binding** (recorded at breakdown approval). The
  design sketch's `Ring.base` is omitted: with a fixed power-of-two capacity the ring
  index is `offset % capacity`, so `base` is derivable (`produced − capacity`); the
  cursors kept are `produced` + `consumed` (+ a `rewinds` seqlock counter, see below).
- **Torn-read protection**: forward production and regeneration both overwrite ring
  bytes; a reader that raced either could serve torn bytes. The serve dispatch uses a
  seqlock-style validation: read rewind-counter + produced, copy, re-read both; a
  changed counter or a low-edge (`produced − capacity`) that passed the copied range
  invalidates the copy → the read falls back to the pending/deferral path. Cheap,
  lock-free, allocation-free.
- **Slot arming race**: two readers could race for one Free slot → a `Arming`
  intermediate state claimed by CAS before fields are written, then `Armed`
  (Release). States: Free=0, Arming=1, Armed=2, Complete=3.
- **Full-request deferral**: a read whose EntryData portion is not fully available
  defers the WHOLE request (nothing accumulated at arm time; the producer serves the
  complete request at completion) — preserves exactly-once accumulation without
  partial-completion bookkeeping. Matches stock: one ReadFile either completes
  synchronously in full or defers in full.
- **No free pending slot** (engine keeps 1 outstanding/stream; 4 slots = generous):
  structurally unreachable with the stock engine; the dispatch returns Refused and
  the caller (task-04) treats it as a hard fault leg. Documented at the site.
- **Pacing**: producer produces while `produced < max(consumed, data_start) +
  PACE_AHEAD` (PACE_AHEAD = capacity/2) or an armed slot needs bytes; keeps look-ahead
  bounded AND retains capacity/2 of look-behind for the engine's header-overlap
  re-reads. Internal constant (req 38: no operator knobs).
- **Silent blocks pre-encoded at construction** (per entry format), so SilenceFill
  serving is allocation-free in detour context.
- **Test-size ring**: `Binding` gets a crate-private constructor taking an explicit
  ring capacity so host tests can force behind-window regeneration with small
  fixtures; production path uses the 16 MiB constant.
- **Metrics timestamps**: `Instant` at binding construction; slots record armed-at as
  nanos-since-construction in an AtomicU64 (allocation-free in detour context).
- **Supersession**: `Binding::request_stop()` (used by retire; also the generation
  token's stop edge) — the producer checks it every hop. Task-03 wires the actual
  retire/reclaim calls.
