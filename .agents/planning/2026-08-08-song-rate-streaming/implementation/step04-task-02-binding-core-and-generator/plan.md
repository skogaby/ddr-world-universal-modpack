## Test scenarios

Host tests live in `src/services/song_rate/binding_tests.rs` (slot/epoch protocol) and
the new `src/services/song_rate/generator_tests.rs` (end-to-end feed/serve matrix; owns
its copies of the Step-3 fixture builder + whole-buffer oracle — the `core/xact`
`#[cfg(test)]` module is not importable from services). All run through the validator
harness's cargo-test phase AND `cargo check --tests` on the Windows target.

1. **Slot protocol (AC-2)** — arm a pending slot for a not-yet-produced range against
   a live binding; poll before completion → Incomplete and accumulator untouched; run
   the producer core until completion; consume → Complete(n) with the accumulator
   carrying exactly the served count once and then zeroed; a second consume → the slot
   is Free (NotPending). Written against the absent implementation: fails to compile /
   fails until `Binding` + serve/poll exist.
2. **Cancellation + quiescence (AC-5)** — arm a slot, retire the binding with a reader
   inside the epoch guard: reclamation eligibility refuses until the reader exits;
   the retire-cancelled slot completes with clamp semantics (0-byte completion
   permitted); post-retire serves → Refused.
3. **Ring byte-equality through the serve dispatch (AC-1)** — both physical entry
   orders × rates {50, 175} (full-entry-loop replay fixture): producer core +
   synchronous pump (Pending ⇒ step the producer, re-poll) replays the RE-pinned read
   pattern (0x1000 header read spanning regions, per-entry sequential
   block-align-rounded 64 KiB packets, defensive EOF read); reassembled virtual file
   byte-identical to the whole-buffer oracle, reparses, both entries decode.
4. **Behind-window regeneration (AC-3)** — small test ring capacity; after streaming
   past the window, a loop-restart read at entry offset 0 defers, sets the regen
   target, the producer regenerates (checkpoint restore + discard-to-block-boundary
   or restart from zero) and completes; re-served bytes identical to the first
   serving of the same range.
5. **Silence-fill (AC-4)** — fault hook kills the producer after N packets mid-stream
   (through the real catch_unwind wrapper on a real thread); state reads SilenceFill;
   armed slots complete; all further data reads complete instantly with valid silent
   ADPCM blocks; the reassembled stream (pre-data + served silence) still parses and
   its entries decode.
6. **Thread lifecycle** — `spawn` runs a full small fixture to Done on the real
   `song-rate-generator` thread; metrics snapshot shows frames-produced == plan total
   and nonzero wall; `request_stop` mid-stream exits promptly (generation token).
7. **Gates (AC-6)** — the five standing gates green; Windows check 0 warnings; the two
   Step-1 identity tripwires untouched and passing (readiness stays structurally
   false).

## Implementation approach

Build order per the task file:

1. **Data structures in `binding.rs`**: `BindingState` (Active/SilenceFill/Retired),
   `Ring` (16 MiB production constant; crate-visible capacity override for tests;
   cursors `produced`/`consumed` as absolute virtual file offsets; `rewinds` seqlock
   counter; `UnsafeCell` buffer + `unsafe impl Sync` justified by the seqlock
   protocol), `PendingSlot` (Free/Arming/Armed/Complete + buffer/accumulator ptrs +
   offset/len + armed-at nanos), `Binding` (design shape + regen target + pre-encoded
   silent blocks + per-entry formats parsed from the source copy + metrics + stop
   flag), epoch guard, retire/cancel, `metrics_snapshot`. Focused protocol tests.
2. **`generator.rs`**: `GeneratorCore::new(&Binding)` (parse source, build per-entry
   feed state) + `step()` (bounded work per call: honor stop token → take regen
   target → complete armed slots → pace → produce next chunk (entry blocks / gap
   zeros / done)); the Step-3 `EncodedFeed` shape ported (BlockCachePcm →
   StretchState → whole-block accumulate → encode_block; `try_capture` loop-start
   checkpoint; restore + produce-and-discard regeneration); `spawn(Arc<Binding>)`
   thread wrapper (`catch_unwind` → SilenceFill flip + cancel-armed-with-silence);
   fault hook (kill-after-N-blocks); metrics recording. Byte-equality tests.
3. **Serve dispatch + poll/consume in `binding.rs`** (pure, allocation/log/panic-free;
   task-04's detours call them verbatim): `serve(offset, len, dest, accumulator)` —
   epoch guard; SilenceFill → instant full serve with silent blocks; Active →
   availability pass over `layout.resolve` spans, then copy pass + seqlock
   re-validation, accumulate once, advance `consumed`; unavailable → (behind-window ⇒
   regen target first) arm slot → Pending; Retired ⇒ Refused. `poll(accumulator)` —
   Armed ⇒ Incomplete; Complete ⇒ report + zero + free; no match ⇒ NotPending.
   Synchronous-pump replay tests.
4. **Failure legs + metrics**: silence-fill mid-stream via the fault hook,
   behind-window determinism, cancellation; deferral count/latency + frames/wall
   metrics exposure.
5. Validator file-presence list gains `generator.rs generator_tests.rs`; run all five
   gates; close the record.

Key design points settled in context.md (auto-mode assumptions): seqlock torn-read
protection, Arming CAS state, full-request deferral, pacing constant capacity/2,
pre-encoded silence, test-capacity constructor, nanos-since-construction timestamps.

## Risks

- **Concurrency correctness**: mitigated by the seqlock validation + SPSC slot
  protocol + epoch guard, each with a focused host test; the synchronous
  `GeneratorCore` keeps the protocol matrix deterministic (real-thread tests are the
  smaller set).
- **Test runtime**: reuse Step-3 fixture sizes (proven ≈7.5 s phase); the new suites
  add two replay cells + focused protocol tests — well under the 30 s budget.
- **Windows-target warnings**: pure modules avoid cfg-gated imports entirely where
  possible; checked by gate 3 before closing.
