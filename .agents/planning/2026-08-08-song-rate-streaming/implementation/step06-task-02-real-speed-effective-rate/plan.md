## Shape

### `src/services/song_rate/real_speed.rs` (new)

Pure (host-mounted):

```text
pub fn rate_adjusted_multiplier(target_real_speed: i32, core_bpm: f64,
                                snapshot: &RateSnapshot) -> Option<i32>
```

- `None` at identity/uncommitted (`!is_non_identity_commit`) — no write, both
  fix-toggle states keep today's behavior bit-identically by construction.
- `None` for a non-finite or out-of-domain `core_bpm` (≤0 or >10 000) —
  fail-soft.
- Otherwise: `effective_bpm = core_bpm × (source_frames/output_frames)`
  (the audible tempo multiplier), `m = trunc((target·100) as f64 /
  effective_bpm)` then clamp [25, 800] — byte-faithful to the native
  `(int)((double)(target*100) / divisor)` + the DAT_18035a740/744 clamp;
  the Max-BPM cap sentinel does not apply to the Core path (same semantics
  the shipped R24 patch encodes).
- The fix toggle is STRUCTURALLY absent from the math — that is req 33's
  "independent of the toggle".

Windows glue (same-file `#[cfg(windows)]`, clock_patch.rs precedent):

- `init(signatures)`: resolve `player_option_table` (already derived for
  assist_tick); missing ⇒ recompute unavailable, one WARN.
- `activate()`/`deactivate()`: register/unregister a judge_hook pre-subscriber
  (Priority::Normal) + a scene callback (GAMEPLAY entry resets the per-side
  once-latches).
- Subscriber, per side, ONCE per song at that side's first judge dispatch
  (strictly after any loader-thread commit; actor constructed — the exact
  timing guarantee assist_tick's anchor uses): read the snapshot (one seqlock
  read); identity ⇒ consume the latch, done. Non-identity commit ⇒ guarded
  Option-chain walk (`*(table+side·8)` → holder → ctx → Option = ctx+0xE0):
  speed TYPE @+0x8 must be 0 (Real Speed mode; fixed-multiplier mode is
  untouched per the KEEPER text), target @+0x14, core BPM @+0x88 (f64).
  On `Some(m)`: write actor+0x29C (int m), actor+0x290 = actor+0x294
  (f32 m/100) — the per-frame renderer copy picks them up next frame — and
  Option+0x10 (int m) for display consistency. One INFO per applied side;
  one latched WARN per session on an unreadable chain.

## Test scenarios (`real_speed_tests.rs`, RED first)

1. **Non-identity derivation vectors (AC-1)** — rates 25/50/75/125/175 via
   `target_for_percent(9_876_543, 128, P)` (non-clean source), core 148.5,
   targets 100/400/600; literal pins computed independently (IEEE f64):
   25 %: 269/800/800 · 50 %: 134/538/800 · 75 %: 89/359/538 ·
   125 %: 53/215/323 · 175 %: 38/153/230. Covers the 800-clamp interaction
   (slow rates double the multiplier) and plain values.
2. **Clamp bounds** — tiny target at 175 % ⇒ 25; huge target ⇒ 800.
3. **Identity/uncommitted ⇒ None (AC-2)** — IDENTITY, committed-100,
   uncommitted-75: no derivation, hence each toggle state's stock behavior
   is preserved bit-identically (nothing writes).
4. **Fail-soft** — core_bpm 0 / negative / NaN / 20 000 ⇒ None; degenerate
   zero ratio ⇒ None (is_non_identity_commit still true but the divisor
   guard catches the 0 × core product).
5. **Toggle independence (AC-1's "both states")** — the function takes no
   toggle input; a test documents/asserts the same output is produced for
   the same (target, core, snapshot) regardless of any external state.
