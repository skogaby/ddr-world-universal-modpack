## Key facts

- `clock_patch::snapshot()` is `#[cfg(windows)]`; the pure functions take
  `&RateSnapshot` as a parameter so the host mounting never touches it.
- `RateSnapshot::IDENTITY` = uncommitted 100 %. `is_non_identity_commit()` =
  `committed && requested_percent != 100`.
- `content_to_wall_ms(c) = round_half_away(c · output_frames / source_frames)`
  (i64 → Result<i64>); identity ratio converts exactly 1:1.
- `music_count` under a committed rate is CONTENT-domain (the Q31 stub scales
  the wall-driven raw count by source/output). `m0` and `mc` are therefore
  content; the track's audio plays in WALL ms.
- `JUDGMENT_TIMING_SIGN` (= +1, ear-validated) stays mod-owned: the mod passes
  the sign-applied term to the pure function (bit-identity preserved — same
  product value).
- `shift_bytes_for_ms` consumes the skip (wall ms) — unchanged; its
  CAPACITY_BLOCKS clamp scales with the constant automatically.
- The snapshot resets to identity at gameplay exit → the AwaitAnchor-latched
  copy in `SongState` is what Commit/Rewind consume (never re-read at commit
  time).
- 1_200_000 ms capacity: CAPACITY_RAW_SAMPLES 52.92 M → mix buffer ~105.8 MB
  (i16), sample segment ~28.9 MB (413 438 blocks × 70 B) — matches the design's
  "~28.8 MB, lazily allocated" (D15 accepted).
