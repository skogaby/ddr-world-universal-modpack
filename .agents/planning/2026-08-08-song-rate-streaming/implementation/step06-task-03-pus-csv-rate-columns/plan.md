## Shape

1. **`RateSnapshot::csv_rate_cells()` (clock_patch.rs, host-mounted):**
   `-> (i32, String)` — `(requested_percent, "source/output")` for a
   committed non-identity snapshot; `(100, "1/1")` otherwise (uniform
   identity schema). The `is_non_identity_commit` precedent: the pure cell
   composition lives where the harness mounts it; the non-mounted mod
   consumes it.
2. **`data_feed.rs`:** `SongIdentity` gains
   `rate: clock_patch::RateSnapshot`; `snapshot_song_identity` (the
   existing per-song latch, first judgment = post-commit) fills it with
   `clock_patch::snapshot()`.
3. **`csv_export.rs`:** header becomes
   `Expected,Actual,Delta (Ms Error),Song Rate Requested (%),Song Rate Effective\r\n`;
   each row appends the two cells from `identity.rate.csv_rate_cells()`.
   First-three-cells bytes unchanged everywhere (AC-2).

## Test scenarios (clock_patch_tests.rs, RED first)

- Identity, committed-100, uncommitted-75 ⇒ `(100, "1/1")`.
- Committed 50 % (via `target_for_percent(9_876_543, 128, 50)`) ⇒
  `(50, "9876543/19753088")` — the exact reduced committed ratio, literal
  pin.
- Committed 125 % (reduced ratio) ⇒ `(125, "3292181/2633728")` — pins that
  the emitted fraction is the GCD-reduced pair the publication carries.

## Risks / notes

- Downstream consumers of the CSV (user spreadsheets) see two appended
  columns — additive, uniform schema; recorded as the intended req-34
  behavior.
- No changes to reset paths (the rate rides inside `SongIdentity`, which
  `reset()` already clears).

## Out of scope
