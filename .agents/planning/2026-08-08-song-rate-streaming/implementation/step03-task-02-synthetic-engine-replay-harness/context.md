## Key facts (from the sources and RE notes)

- Engine read pattern (RE-pinned): ONE 0x1000 read at offset 0 (spans the
  2048-byte pre-data AND the first 2048 bytes of entry-0 data — those data
  bytes are parser-ignored but get RE-READ by the first data packet: the
  stream cursor starts at 0); data packets "≤ 64 KiB, block-align-rounded"
  (packetSize 0x20 sectors; rounded DOWN to a whole block-align multiple:
  65,536 → 65,520 for 140-byte blocks), sequential, one outstanding; loop
  start is the only backward jump; EOF clamp `min(len, size − offset)`;
  short completions normal at EOF.
- `transform_bank` (validator main.rs) composition confirmed by reading it:
  parse → per-entry `plan_entry` → `decode_interleaved` →
  `stretch_interleaved` (reference) → `encode_interleaved` →
  `write_song_bank_streaming`.
- Step-2 equalities this task composes (all proven): `StretchState` ≡
  reference stretcher byte-for-byte through any chunking; `BlockCachePcm` ≡
  `decode_interleaved`; `encode_block` per block ≡ `encode_interleaved`.
  Therefore feed bytes == oracle payload bytes EXACTLY.
- Checkpoint semantics (Step-2 task-02): checkpoints exist only BEFORE the
  terminal region, resume hop-aligned (hop 120 at 8 kHz), 5 words, restore
  validates shape and rebuilds the provisional tail; restore + produce
  reproduces the identical suffix.
- Full-entry loops (production shape, and the fixture's): LoopContext
  {0, S, 0, O} → stretched loop start = output frame 0 → the loop-restart
  jump targets block 0 and the qualifying checkpoint is the zero
  checkpoint (discard 0).
- tests.rs fixture `build_bank` has ZERO-byte ADPCM data and 256/384-frame
  entries — too short to stretch (SourceTooShort: min 300 frames at 8 kHz)
  and content-free; the replay fixture must carry real encoded audio.

## Interpretation & assumptions (auto mode)

- **New audio fixture builder** `build_audio_bank(preview_first, payloads,
  durations, loops)` in tests.rs: same strict-profile byte scaffold as
  `build_bank_with_data_lengths` but with real encoded ADPCM payloads, one
  8 kHz stereo format for both entries, explicit durations/loops. Sizing
  for multi-packet coverage at the demo rates within the runtime budget:
  main entry 32,768 frames (256 blocks; 2 packets at 50%, 3 at 25%),
  preview entry 2,048 frames. Full-entry loops on both entries.
- **Data packet requests are stream-bounded** (`min(rounded_packet,
  data_len − cursor)`) — the engine bounds reads to the wave's data region
  (RE table: "≤ 64 KiB"); the file-level EOF clamp is still asserted
  (`offset + served ≤ virtual_size`; entry 1's final packet ends exactly at
  `virtual_size`) plus one defensive read past the end → Eof/0 served.
  Data reads never span into the gap (the engine never reads it); gap
  bytes stay zero in the reassembly buffer, matching the serializer's
  zero fill (gap SERVING via resolve is task-01-covered).
- **The header-read overlap is re-served**: the feed retains produced
  encoded bytes during a pass, so the first data packet's re-read of entry-0
  bytes [0, 2048) serves the identical retained bytes (mirrors the
  production ring window, which always covers the look-ahead region). The
  LOOP-RESTART leg never touches retained bytes — it regenerates through a
  FRESH feed built by `StretchState::restore` + discard-to-block-boundary
  (R5's "never by retaining the whole first-pass output" honored where it
  binds).
- **"Both entries decode to the reference's stretched PCM"** (AC1) read as:
  the reassembled bank re-parses and each entry's data DECODES equal to the
  decoded oracle entry (ADPCM is lossy — decode(encode(x)) ≠ x; the
  decodable-equality against the oracle's encode of the reference stretch
  is the meaningful equality, and it exercises parse+decode of the
  reassembled file end to end).
- **Discard mechanics need a non-trivial exercise**: on full-entry-loop
  fixtures the restart collapses to zero-checkpoint + zero-discard (the
  production shape — asserted as such). ONE additional interior-loop
  restart cell at 75% (interior loops succeed at 75%, Step-2 matrix;
  the 25/50 prohibition doesn't apply) proves the nonzero
  hop-aligned-checkpoint → block-aligned-target discard bridge.
- Matrix: T3 pump matrix {25, 50, 100, 175} × both entry orders on the
  full-entry fixture; T2 feed pin {50, 175} one order; T4 restarts
  {50 full-entry, 75 interior}. Trim first the 25% cells if the phase
  exceeds the budget.
