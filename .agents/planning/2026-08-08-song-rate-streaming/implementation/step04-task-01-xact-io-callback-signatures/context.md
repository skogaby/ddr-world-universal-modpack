## Requirements (from the task file)

1. One new `SignatureDefinition` for the audio-manager ctor callback-registration region
   (`0xFA` imm + three LEA/MOV pairs; LEA disp32s + frame disp8s wildcarded).
2. A `derive_*` function (conventions of `derive_song_rate_runtime_sites`): re-validate
   single match, RIP-decode LEAs 2+3, publish `song_rate_readfile_callback` +
   `song_rate_overlapped_callback`; remove everything published on any validation
   failure with one WARN.
3. File-table global derived from the existing `song_rate_wavebank_unregister` match
   (RIP-decode the `MOV RAX,[rip+d32]` at match+15, disp32 at match+18; the pattern's
   literal bytes guarantee the access shape).
4. Handle→file_id resolution inputs published. DECISION (recorded, per Background
   Option A): publish the stock lookup helper address (`song_rate_handle_lookup`),
   derived from the first `E8 rel32` CALL at readfile_entry+0x21, after validating the
   33-byte literal entry prefix. Rationale: exactly replicates the stock locked
   sorted-vector walk (the helper takes the AVS mutex itself), allocation-free, avoids
   re-deriving manager global + vector offset + mutex gate. Documented cost: an unbound
   read pays the lookup twice (detour classify + trampolined original) — a cost class
   the stock path already pays per read (RE note §7).
5. None of the new names join the required-signature set (fail-open: absence ⇒
   `binding::integration_available()` stays false ⇒ stock boot).
6. Ghidra cross-verification on ALL FOUR builds — done this session (see Evidence).
7. `docs/xact_streaming_research.md` §6 gains the cross-version table + closes the
   "owed before implementation" note.
8. Host tests where pure — repo has NO existing signature-derivation host tests and the
   validator harness does not mount `signatures.rs`; posture matched: boot-time
   validation only (decision recorded in progress.md).
