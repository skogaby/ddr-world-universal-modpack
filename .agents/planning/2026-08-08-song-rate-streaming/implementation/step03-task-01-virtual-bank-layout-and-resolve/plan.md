### 2. `src/core/xact/virtual_bank.rs` — layout + resolve (R1, R2, R4, R5)

- Additive `PlanError` variants (+ Display arms):
  `EntryRate { index: usize, source: RateError }` (entry identity for rate
  refusals surfaced by `plan_virtual_bank`; `plan_entry` itself keeps
  returning `Rate` — stub-identical) and `PreData(String)` (emission leg,
  structurally unreachable after a successful plan; carries XwbError's
  Display because XwbError is not PartialEq).
- `pub struct VirtualBankLayout { entries: [EntryPlan; 2], main_entry_index:
  usize, entry_offsets: [u64; 2], pre_data: Vec<u8>, virtual_size: u64 }`.
- `pub fn plan_virtual_bank(source: &xwb::SongBank<'_>, percent: u32)`:
  plan each entry via `plan_entry` (mapping `PlanError::Rate` →
  `EntryRate { index, .. }`, other errors already carry identity); build
  `[StreamedEntry; 2]` from the plans; call `xwb::stream_pre_data`;
  `entry_offsets[i] = wave_data_offset + data_offsets[i]`;
  `main_entry_index` = index of the entry whose `name() == bank.name()`;
  `virtual_size = total_length`.
- `pub enum Region { PreData { offset: usize }, EntryData { entry: usize,
  offset: u64 }, Gap, Eof }` + `pub struct ResolvedSpan { region, len: u32 }`
  + `impl VirtualBankLayout { pub fn resolve(&self, offset: u64, len: u32)
  -> ResolvedSpan }`: clamp `len` to `min(len, virtual_size − offset)`
  (offset ≥ virtual_size → `Eof`/0); pick the containing region in physical
  order — pre-data `[0, pre_data.len())`, entry-0 data, gap (between entry-0
  end and entry-1 offset, zero fill), entry-1 data — and cap the span at the
  region's remaining contiguous bytes. Spanning reads iterate.

### 3. Tests (`src/core/xact/tests.rs`, R6) — written FIRST, must fail on the stub

All on the existing `build_bank` fixture (both physical entry orders;
full-entry loops; strict profile) with deterministic synthetic payload bytes
(`fn payload(len, seed)`), percents from {75, 125} (+ 100 for identity
sanity in the reconstruction loop).

- T1 `virtual_bank_pre_data_matches_streaming_serializer` (AC1): for each
  entry order × percent: parse → `plan_virtual_bank` → build the SAME
  `[StreamedEntry; 2]` → oracle = `write_song_bank_streaming` with payload
  writers → assert `pre_data.len() == 2048`, `pre_data ==
  oracle[..2048]`, `virtual_size == oracle.len() ==
  serialized_song_bank_len`; complete `pre_data` + payloads/gaps to exactly
  `virtual_size` and `parse_song_bank` it, asserting the reparsed entries
  carry the plan's duration/loop/data_len and `main_entry_index` names the
  bank-code entry.
- T2 `virtual_bank_resolve_reconstructs_serializer_layout` (AC2): serve
  `[0, virtual_size)` through `resolve` with chunkings {0x1000-first then
  0x10000 packets (the engine shape), 1 byte, 2047, 2048, 4096+1 (spans),
  whole-file} — reassemble (pre_data bytes / payload bytes / zeros) and
  byte-compare with the oracle; assert every span's region/len invariants
  (len > 0 except Eof; len ≤ request).
- T3 `virtual_bank_resolve_clamps_at_eof` (AC3): at `virtual_size` → Eof/0;
  past → Eof/0; straddling (last byte + 64 KiB request) → clamped to the
  remaining bytes; `len == 0` request → 0-length span.
- T4 `virtual_bank_plan_refusals_carry_entry_identity` (AC3): duration
  bumped past the 28-bit ceiling on entry 1 at 25% → `EntryRate { index: 1,
  source: DurationOutOfRange { .. } }`; a degenerate loop on entry 0 →
  `InvalidMappedLoop { index: 0 }`. (Existing stub refusal tests continue to
  pin `plan_entry`'s own identities — R5.)

Fixture note: `build_bank`'s metadata is mutated in-place for the refusal
legs (put_u32 on the entry meta), mirroring the existing negative tests.
