## Requirements (task file, normalized)

R1. `plan_virtual_bank(source: &xwb::SongBank<'_>, percent: u32) ->
    Result<VirtualBankLayout, PlanError>`: plans BOTH entries via the
    existing `plan_entry`; per-entry refusals (28-bit ceiling, unmappable
    loops) propagate with their entry identity; physical entry order
    preserved; `main_entry_index` = the entry named exactly like the bank.
R2. `VirtualBankLayout` carries the two `EntryPlan`s, per-entry VIRTUAL data
    offsets (entry 0 at 2048; entry 1 at 2048 + round_up(entry0.data_len,
    2048)), the synthesized pre-data block (exactly the first 2048 bytes of
    the virtual file), `main_entry_index`, `virtual_size` (= 2048 + entry-1
    offset-within-segment + entry-1 data_len; segment 4 ends exactly there).
R3. Pre-data synthesis reuses xwb.rs's canonical streaming emission — factor
    the private `write_stream_header`/`validate_stream_write_layout` path so
    serializer and `plan_virtual_bank` share ONE code path; the refactor
    leaves `write_song_bank_streaming`/`serialize_song_bank` byte-identical
    (their suites pass unmodified).
R4. `resolve(offset, len)`: returns the region containing `offset` —
    pre-data (block offset) / entry data (entry index + offset within the
    generated stream) / gap (zero fill) / EOF — plus the contiguous byte
    count servable from that region, after clamping to
    `min(len, virtual_size − offset)`. At/past `virtual_size` → EOF, zero
    bytes. Spanning reads are served by repeated calls (the engine's
    0x1000-at-0 header read spans pre-data + entry-0 data). Field shapes
    free per the sketch-elision rule; behavior binding.
R5. 28-bit and loop-mapping refusals remain exactly the Step-1 stub's
    (`rate::target_for_percent` + `map_loop`); no new numeric policy.
R6. Tests in `src/core/xact/tests.rs`, running through the validator
    harness's cargo-test phase.

## Key code facts (from reading the sources in full)

- `xwb.rs`: `write_song_bank_streaming` = `validate_stream_write_layout`
  (private, → `WriteLayout` with `data_offsets: [0, round_up(e0.data_len,
  2048)]`, `segment_four_offset` = round_up(324, 2048) = 2048,
  `total_length` = 2048 + data_offsets[1] + e1.data_len) then
  `write_stream_header` (private — writes EXACTLY bytes
  `[0, segment_four_offset)`: 52-byte header, BANKDATA 96, 2×24 entry
  metadata with `duration << 4`, 2×64 names, zero pad), then per-entry
  payload writes with zero gap fill. `serialized_song_bank_len` (pub)
  already returns `total_length`. So the canonical pre-data emitter EXISTS —
  the factoring is a thin pub composition (`validate_stream_write_layout` +
  `write_stream_header` into a Vec) with the two private functions and the
  serializer bodies untouched → AC4 trivially holds.
- `virtual_bank.rs` (Step-1 stub): `EntryPlan { streamed: StreamedEntry,
  rate, source_frames, loop_context }`; `plan_entry(index, &SongEntry,
  percent)`; `PlanError { Rate(RateError), InvalidMappedLoop { index },
  ArithmeticOverflow }` derives `Debug, PartialEq, Eq`.
- After a successful `plan_entry`, `validate_stream_write_layout` cannot
  fail structurally: duration ≤ 2^28−1 (= xwb MAX_DURATION),
  data_len = blocks × block_align with duration = blocks ×
  samples_per_block (`validate_generated_layout` exact), mapped loops
  clamped to ≤ duration, and 2×(2^21 blocks × 140 B) ≈ 587 MB < u32::MAX so
  `to_u32` cannot overflow. Only `AllocationFailed` remains theoretically
  reachable — the new PlanError variant for the emission leg is
  belt-and-braces, not a live path.
- `parse_song_bank` requires `segments[4].offset + length == bytes.len()`
  (EOF framing), so AC1's reparse leg needs the completed file to be exactly
  `virtual_size` bytes.
- tests.rs fixture `build_bank(preview_first, tail_remainder)`: strict
  2-entry bank `tst1`/`tst1_s`, stereo 48000/48001, 2 and 3 blocks
  (BLOCK_ALIGN 140, 128 samples/block), FULL-ENTRY loops (loop_start 0,
  loop_length = duration). Both entry orders. Perfect for layout tests — no
  DSP involved (payloads are arbitrary bytes for layout equality).
- `rate::MAX_XWB_DURATION = (1 << 28) − 1`;
  `RateError::DurationOutOfRange { output_frames: u128 }` (PartialEq).

## Interpretation & assumptions (auto mode)

- **xwb factoring shape**: add ONE pub function to xwb.rs, e.g.
  `stream_pre_data(bank, entries) -> Result<StreamPreData, XwbError>` where
  `StreamPreData { bytes: Vec<u8>, data_offsets: [usize; 2],
  wave_data_offset: usize, total_length: usize }` — composed from the
  existing private `validate_stream_write_layout` + `write_stream_header`.
  Both the serializer and `plan_virtual_bank` therefore run the SAME
  emitter (`write_stream_header`); nothing existing changes. (Task's
  "factor ... rather than duplicating": satisfied — no duplication, one
  code path.)
- **Entry identity on rate refusals**: `InvalidMappedLoop` already carries
  `index`; `Rate(RateError)` does not. `plan_virtual_bank` wraps a failing
  entry's rate error as a NEW additive variant
  `PlanError::EntryRate { index: usize, source: RateError }` while
  `plan_entry`/`plan_entry_values` keep returning `PlanError::Rate`
  (stub-identical, R5). RateError is PartialEq so the derive survives.
- **Emission-leg error**: new additive variant `PlanError::PreData(String)`
  (XwbError is not PartialEq — carrying its Display keeps the derive;
  the leg is structurally unreachable after a successful plan, see above).
- **Resolve shape** (sketch-elided, behavior binding):
  `Region { PreData { offset: usize }, EntryData { entry: usize, offset: u64 },
  Gap, Eof }` + `ResolvedSpan { region: Region, len: u32 }`;
  `fn resolve(&self, offset: u64, len: u32) -> ResolvedSpan`. `len` clamped
  to `min(len, virtual_size − offset)` then to the containing region's
  remaining contiguous bytes. `offset ≥ virtual_size` → `Eof`, len 0.
  u32 span length: the engine's reads are DWORD-sized; a span never exceeds
  the request.
- **Pre-data length**: taken from the factored layout
  (`wave_data_offset`), asserted == 2048 in tests rather than hardcoded in
  crate logic.
- `VirtualBankLayout { entries: [EntryPlan; 2], main_entry_index: usize,
  entry_offsets: [u64; 2] /* virtual file offsets */, pre_data: Vec<u8>,
  virtual_size: u64 }`. `virtual_size` comes from the factored
  `total_length` (== `serialized_song_bank_len` by construction).
- Both entries planned at the SAME percent (design: "Both entries are
  stretched at the same percent").
