# Orientation: Preserve Song Pitch sub-option

Findings from the Step-2 blind-spot pass (two exploration passes + reading
`scripts/gen_option_labels.py`). All paths repository-relative.

## What the idea actually requires

Two independent tracks:

1. **UI track** — a boolean child row under the `song_speed` scalar row,
   visible only when `song_speed != 100` for that side.
2. **DSP track** — the option has to *do* something: today the rate engine is
   WSOLA time-stretch, which is pitch-preserving **by design**. "Preserve pitch
   OFF" means a **plain resampler** (vinyl-style: pitch follows rate). No
   resampler exists in the codebase — one must be written.

The UI track is nearly free; the DSP track is the real work.

## UI track findings (custom_options framework)

- `RegisterSpec::bool_toggle(id)` (`src/services/custom_options/api.rs:243-265`)
  is the ready-made row shape: stock `seop_op_off`/`seop_op_on` value ribbons
  (no ribbon PNGs needed), `PersistMode::Full` default, builder setters for
  `.default_value()`, `.on_change()`, `.show_when()`.
- **Conditional visibility gap:** the framework's predicate is
  `ShowWhen::{Always, Equals { parent_id, value }}` (api.rs:157-164).
  "`song_speed != 100`" is **not expressible** — a `NotEquals` variant must be
  added. Exactly **4 touch points**: the enum (api.rs:158-164), parent
  validation (registry.rs:150-157), the evaluator
  `is_show_when_satisfied` (rows.rs:281-297), and the child-detection
  `matches!` in `update_children_visibility` (rows.rs:2113-2130).
- **Live show/hide already works:** after every user value press the framework
  calls `update_children_visibility(parent_id, side, value)` →
  `options_scroll::reapply_mask_for_side(side)` — the child appears/disappears
  same-frame as the user scrolls `song_speed` through 100. Evaluation is
  per-side against the parent's live registry value; hidden rows collapse the
  list (subsequent rows shift up), exactly like `weight` under
  `is_disp_weight` today (`src/mods/webui_options/profile_fields.rs:121-138`).
- **Textures** (all in
  `data_mods/custom_options/select_music_option_lang_eng_v3_ifs/tex/`):
  - `seop_item_preserve_pitch.png` — 176×16 row label ("PRESERVE SONG PITCH")
  - `seop_image_preserve_pitch.png` (single fallback) and/or
    `seop_image_preserve_pitch_{off,on}.png` — 368×172 preview panel(s).
    Lookup is `seop_image_<id>_<key>` falling back to `seop_image_<id>`.
  - Generated by `scripts/gen_option_labels.py` (add LABELS + PREVIEWS rows).
    Injection is automatic at `register_option` via the donor-clone atlas
    pipeline (donors: `seop_item_appearance` label slot,
    `seop_image_scroll_speed` preview slot).
- **Registration placement:** parent must exist before child; register
  `preserve_pitch` immediately after `song_speed` in
  `src/mods/song_playback_speed.rs::enable()` (also covers default `row_order`
  adjacency). Handle the `Duplicate` arm (re-enable path) and mirror the
  mod's `set_option_available` enable/disable calls for the child.
- **Persistence for a Full bool:** everything derived from the id — wire field
  `mod_preserve_pitch` (s32), JSON offline cache key
  `custom_options.{p1,p2}.preserve_pitch`, automatic scene-25 seeding via the
  framework's load path, optional `load_transform` clamp to {0,1}. Backend
  (bemani-buddy) needs a matching column for network round-trip (precedent:
  `mod_song_speed` → `opt_mod_song_speed`, stored verbatim).

## DSP track findings (song_rate engine)

- **The plan is the contract, not the rate.** `plan_virtual_bank`
  (`src/core/xact/virtual_bank.rs:183`) quantizes output length to whole
  ADPCM blocks (128 frames): `round(len/rate)` does NOT match. Any DSP mode
  must emit exactly `plan.streamed.duration` frames at the **effective** ratio
  `source_frames/output_frames` (a Q32 phase accumulator, mirroring
  `q32_phase_step` in stretch.rs). Done that way the entire downstream —
  virtual bank, ring serving, clock Q31, tick domain, Real Speed, score guard,
  movie policy — is byte-level indifferent to the pitch mode.
- **The seam is `Feed`** (`src/services/song_rate/generator.rs:69-106`): it
  owns the `StretchState`; the mode switch is an enum
  (`Wsola(StretchState) | Resample(ResampleState)`) behind the same
  `produce`/checkpoint surface. Everything else in the producer thread
  (pacing, pending slots, silence-fill, ADPCM block encode drain) is
  byte-agnostic. Resample checkpoints are trivial (any position directly
  computable — rewind becomes a seek, no produce-and-discard).
- **Flag carriage:** mirrors percent — per-side desired atomic in `runtime.rs`
  → read at the scene-26 arm from the single entered side
  (`classify_scene26`, lifecycle.rs:163-204) → `LifecycleState` atomic →
  `prepare_binding` parameter → `Binding` field the generator reads. Quick
  Restart re-binds through the lifecycle's latched values, so the flag rides
  restarts automatically. It does **not** need to live in `RateSnapshot` —
  every rate consumer keys off `effective_rate` only (optional: CSV
  diagnostics).
- **No resampler exists** (verified: only chart-timing integer interpolation
  and UI lerps). Must be written: fixed-point Q32 phase + integer rounding for
  determinism (reuse `round_half_up_u128`/`divide_half_away_i128` from
  rate.rs); linear interpolation is defensible quality-wise (comparable
  artifact floor to WSOLA's linear-crossfade OLA); loop-context two-domain
  mapping (global phase outside the loop, loop-relative proportional map
  inside) must be reproduced for seam alignment. Cost: 2–4 orders of magnitude
  cheaper than WSOLA (no SAD search) — loading gets *faster* with preserve
  OFF.
- **Historical alternative (rejected):** the original feature research
  (docs/song_playback_speed.md §4) proposed engine-native resampling via the
  XSB sound-entry pitch field (cents). Never live-proven, cent-quantized
  (breaks the exact-integer `RateRatio` clock/tick machinery), bypasses the
  proven virtual-bank architecture. Treat as historical.
- **Unaffected:** preview passthrough (the `<code>_s` entry stays verbatim
  stock regardless), the 100 % identity zero-footprint path (supports the
  conditional-visibility design — at 100 % the option is semantically inert),
  score containment (keys on "rate-played" only).
- **Validation:** replicate the established pattern —
  (a) whole-buffer *reference resampler* oracle (never modified),
  (b) streaming/resumable production form proven byte-identical across the
  chunk-size/checkpoint/engine-replay matrix (host tests in
  `src/core/xact/tests.rs`, `src/services/song_rate/generator_tests.rs`),
  (c) a new `scripts/validate_song_playback_speed.sh` leg with the pitch
  expectation **inverted**: output frequency must track `f_source · S/O`
  (existing `estimate_frequency` machinery works as-is).

## Unknowns / risks surfaced

1. **Stereo phase coherence of a per-channel linear resampler** — resampling
   interleaved stereo with a shared phase accumulator is trivially coherent;
   no risk if designed that way.
2. **Loop seam under resampling** — needs the same two-domain mapping WSOLA
   uses; arithmetic only, but must be in the design explicitly.
3. **Backend column** for `mod_preserve_pitch` — out of this repo's scope;
   JSON cache covers offline persistence either way.
4. **Preview panel semantics** — user specified one preview text; framework
   supports per-value (`_off`/`_on`) or single fallback panel. House style is
   per-state paragraphs.
