## Deviations & open questions

- **Backend testability deviation (Step 1):** the two save-applier lines are routed
  through `parse_workout_fields → WorkoutFieldUpdates` (two `Option`s) instead of raw
  inline, purely so the present/absent + `!=0` contract is DB-free unit-testable (DDR
  handlers have zero existing tests; `handle_save_profile` is DB+tokio-coupled;
  `stub_db()` panics). Net behavior identical to the plan.
- **Did NOT run `cargo fmt` on `bemani-buddy`** — repo isn't rustfmt-clean (compact
  one-liner style throughout `playdata.rs`/`context.rs`); running fmt would bury the
  change in a 1000-line reformat. New code matches neighbor style; clippy clean.
- **DLL: register fires `on_change` at registration** (framework primes both sides
  with defaults). At boot no card is in → null-guarded → no memory write. Only if the
  mod is enabled at runtime while carded-in would defaults briefly write, corrected at
  next SONG_SELECT seed — identical to the cosmetics' behavior. Acceptable.
- **Cannot live-validate the DLL here** (no cabinet/live game). Only compile + build
  verified. All runtime behavior is the user's on-cabinet task (see Deploy & test log).
- **Open (non-blocking):** weight-unit calibration. If scaled, only the range
  constants in `profile_fields.rs` change.

## Key facts for a cold resume

- Offsets (hardcoded, verified 20260324 & 20260616): weight = PlayerWork+0x24 (s32 kg,
  0=unset→60); is_disp_weight = +0x28 (u8 0/1). Don't touch today_cal (+0x30). Chain:
  `player_work_table[side]` → `*wrapper` = PlayerWork.
- Save is automatic: `SaveOnly` → `snapshot_for_save()` (filters `persist != None`) →
  persistence emits `<mod_{id}>` s32 → wire `mod_weight`/`mod_is_disp_weight`. No
  save_transform, no custom save code.
- Register parent (`is_disp_weight`) BEFORE child (`weight`) or child rejected
  `UnknownParent`. `register()` is latched (idempotent across re-enable).
- Seed uses `set_value_silent` (no on_change → no write-back loop), extends the
  existing scene-25 callback.
- DLL build: `cargo check --target x86_64-pc-windows-msvc`; `./build.sh`. No unit
  tests — validation is live deploy + `log_info!`/`log_warn!`→OutputDebugStringA.
- Ignore `retour-0.4.0-alpha.4` LSP errors (pre-existing dependency-analysis quirk).
