## Interpretation & assumptions (auto mode)
- "Seeded at the shift-mapped source position" = fresh stretch of the source TAIL onto
  the output TAIL: sub-problem `StretchState::new(source_frames − src0, output_frames − S0, …)`
  over an offset source view, where `src0 = round_half_up(S0 · source_frames / output_frames)`
  (the codebase's established half-up mapping, same as `q32_phase_step` family).
- Short-tail handling (AC-1 "including the final block"): the seeded start `S0` backs off
  from `S` just far enough to satisfy the stretcher's minimum source/output requirements,
  and the first `S − S0` frames are discarded (bounded by the minimums ⇒ still O(1)).
  Rationale: the sub-problem must be a valid stretch; the backoff is deterministic pure
  math shared by reference and streaming forms.
- Loop context: `None` for seeded runs (per task §Technical Requirements 1).
- Seeded runs capture NO checkpoints (`capture_target = None` — the loop-restart anchor
  belongs to the canonical `{0,0}` stream). Within-epoch regen = fresh seeded state +
  bounded produce-and-discard from the seek point (deterministic; same-cost class as the
  shipped loop-restart regen).
- `shift == 0` keeps `Feed::new` / canonical `positioned_at` exactly (Quick Restart pin).
- Resample mode: mapping changes keep using the O(1) positional seek — unchanged.
