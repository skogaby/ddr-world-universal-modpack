## Requirements (from the task)

1. Publication cell `{code_digest: u64, audio_len_ms: u32, generation: u32}`,
   seqlock torn-read guard, published from the create detour for EVERY
   slot-5 dance-bank create (armed or not); parse failure ⇒ previous
   publication stays. Detour-legal (no logging; allocation limited to the
   path/parse work the bind closure already performs pre-original).
2. Effective-clamp helper: row seconds capped at `audio_len_ms/1000` when a
   publication exists (pure, host-tested, applied at USE time).
3. Gameplay-entry bound resolution per entered side: `MARGIN` = the existing
   1000 ms class (`MARKER_END_MARGIN_MS`), `MIN_SECTION = 5_000` named
   const; `a_ms = min(skip·1000, end − MARGIN)`,
   `b_ms = clamp(end − omit·1000, a + MIN_SECTION, end)`; block-quantized
   via `quantize_marker`; stored as row-derived `{a_ms, b_ms}`; one INFO
   when nonzero.
4. Triple-5 RESTORES row-derived values (zero rows ⇒ Step-2 clear-to-none).
   `active_section_start()` returns the live a_ms.
5. Session-active latch: rows > 0 at gameplay entry OR gesture/seek
   mid-song; consumed by task-03's driver + Step 5's taint.
6. Host tests: clamp truncation, resolution formula cases, torn-read guard.

## Key exploration facts

- **Create detour**: `song_rate::wavebank_hook::create_hook` (cfg windows)
  fires for every bank create; `file_table_path(id)` +
  `dance_bank_song_code(&path)` identify dance banks (= the slot-5 banks,
  research §8.2 — the preview player loads the SAME XWB through the same
  create). At detour entry the FileManager row is resident
  (`file_table_source`). The bind closure already allocates (path String)
  pre-original in this detour — precedent for the publication's path/parse
  work. The detour has an early degraded path (SLOTS/publication absent) —
  publication must fire on BOTH paths ⇒ top of create_hook.
- **Parse**: `xwb::parse_song_bank(bytes)` (pure, borrowing). Main entry
  index = `usize::from(bank.entries[1].name() == bank.name())`
  (virtual_bank::plan_virtual_bank:190 precedent). Audio ms =
  `duration · 1000 / format.sample_rate()` (duration is frames).
  `song_code_digest(code)` = md5-low-64|1 (binding.rs).
- **Module placement**: new `src/services/song_rate/selected_song.rs`
  (cfg-agnostic — song_rate/mod.rs is harness-mounted whole, so the cell +
  parse composition get host tests for free via a sibling
  `selected_song_tests.rs`). NOTE `song_rate::runtime` is cfg(windows) —
  selected_song must not depend on it.
- **Fixture**: `generator_tests::build_bank_bytes` / `replay_fixture`
  (pub(super)) — `replay_fixture` main entry = 32 768 frames @ 8 kHz =
  exactly 4096 ms.
- **Resolution timing**: at the scene-change instant to GAMEPLAY the
  DPS/actors do NOT exist yet (`chart_end_raw(side)` walks the live DPS →
  gameplay actors → CMA child). Resolution is therefore PENDING-latched at
  entry and completed by `try_resolve_row_bounds()` — retried per frame by
  task-03's driver (the design's driver hosts exactly this; the step demo
  runs after task-03). Entered side = the first side where
  `chart_end_raw(side)` resolves (armed sessions are never versus — the
  classifier fails them closed — so exactly one side resolves;
  doubles/solo carry the entered side's id on the actor).
- **Bounds domain**: content raw-ms; `quantize_marker` (bounds.rs) already
  does the wall→grid→content composition with a no-binding fallback.
- **At resolution, the audio clamp is subsumed by the chart clamp**
  (audio ≥ chart ≥ chart−MARGIN) but is composed anyway per AC 2; the
  audio clamp's real standalone consumer is task-03's select-time pre-shift
  arming (no chart end exists at scene 25/26).

## Sentinels (design §5)

`a_ms == 0` ⇒ none; `b_ms == 0` ⇒ none in storage (the design's
"b == chart_end = none" is normalized to 0 at resolution so every consumer
keeps Step-2's `> 0` checks). Row-derived latches separate from the live
markers: `ROW_A_MS`/`ROW_B_MS` (restore source), `A_MS`/`B_MS` stay the
live bounds gestures overwrite.
