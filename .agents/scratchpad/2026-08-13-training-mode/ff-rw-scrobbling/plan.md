## Test scenarios (written first — all in `section_math.rs`, harness-run)

### `scrub_target(current, delta, b_live, chart_end, margin) -> Option<i32>`

Constants mirror the existing test module: `CHART_END = 120_000`,
`MARGIN = 1_000`.

1. **Normal FF** (AC 1): `scrub_target(30_000, 5_000, None, CHART_END, MARGIN)`
   → `Some(35_000)`.
2. **Normal RW** (AC 2): `scrub_target(30_000, -5_000, None, CHART_END, MARGIN)`
   → `Some(25_000)`.
3. **Clamp at end, no b_live** (AC 3): `scrub_target(118_500, 5_000, None,
   CHART_END, MARGIN)` → `Some(119_000)` (= chart_end − margin).
4. **Clamp at end, b_live smaller** (AC 3): `scrub_target(85_000, 5_000,
   Some(88_000), CHART_END, MARGIN)` → `Some(87_000)` (= b − margin: the
   margin applies after the min, per the spelled formula).
5. **b_live above chart_end** (defensive): `scrub_target(118_500, 5_000,
   Some(130_000), CHART_END, MARGIN)` → `Some(119_000)`.
6. **Clamp at zero** (AC 4): `scrub_target(3_000, -5_000, None, CHART_END,
   MARGIN)` → `Some(0)`; also from a negative pre-song count:
   `scrub_target(-2_000, -5_000, …)` → `Some(0)`.
7. **FF from the pre-song approach**: `scrub_target(-2_000, 5_000, None,
   CHART_END, MARGIN)` → `Some(3_000)`.
8. **Degenerate refusals**: `chart_end = 0` → `None`; `chart_end = MARGIN`
   → `None` (bound ≤ 0); `b_live = Some(500)` with margin 1000 → `None`;
   `b_live = Some(0)` → `None` (defensive — `section_end()` never yields
   ≤ 0, but stay total).
9. **No-op delta stays put**: `scrub_target(30_000, 0, …)` → `Some(30_000)`
   (shape guard: the clamp is pure, no hidden bias).

### `normalize_scrub_increment_ms(raw: Option<i32>) -> i32`

## Implementation approach

### 1. `section_math.rs` (pure, TDD)

- `pub const SCRUB_INCREMENT_DEFAULT_MS: i32 = 5_000;`
  `SCRUB_INCREMENT_MIN_MS = 250; SCRUB_INCREMENT_MAX_MS = 60_000;`
- `pub fn scrub_target(...) -> Option<i32>`: refuse `chart_end ≤ 0`; bound
  = `min(b_live?, chart_end).saturating_sub(margin)`; refuse `bound ≤ 0`;
  `Some(current.saturating_add(delta).clamp(0, bound))`.
- `pub fn normalize_scrub_increment_ms(raw: Option<i32>) -> i32`.

### 2. `config.rs`

- `TrainingModeConfig { ff_increment_ms: Option<i32>, rw_increment_ms:
  Option<i32> }` (derive Deserialize/Clone/Debug/Default, `#[serde(default)]`
  per key — the QuickRestartConfig shape).
- `training_mode: Option<TrainingModeConfig>` in `ConfigFile` + both
  fallback literals in `init()`.

### 3. Service accessors (one-liners)

- `song_reset::reset_in_flight() -> bool` (public, reads `RESET_IN_FLIGHT`).
- `driver::loop_reset_in_flight() -> bool` (`pub(super)`, reads `LOOP_COOLING`).

### 4. `bounds.rs` — the scrub layer

- Statics: `FF_INCREMENT_MS` / `RW_INCREMENT_MS` (AtomicI32, default 5000),
  `SCRUB_COOLING` (AtomicBool), `SCRUB_WARNED` (AtomicBool).
- `pub(super) fn load_scrub_increments()`: read `config::get().training_mode`,
  normalize via section_math, one INFO if any key was out of range, store.
- `on_input_event`: before the triple-gesture slot match, arm NUM_7/NUM_9 →
  scene gate → side → `scrub(side, ±increment)`.
- `fn scrub(side, delta_ms)`: cooling gate (lazy clear via
  `reset_in_flight()`; yield to `driver::loop_reset_in_flight()`; debug-log
  drop) → live count (silent drop) → live binding + chart end + pure clamp
  (WARN-once drops) → `quantize_marker`, `.max(0)` → `t_q > 0` needs
  `seek_available()` (WARN-once) → `request_reset(t_q, TRAINING_LEAD_MS as
  i32, Zero, None)`. `Started` ⇒ `SCRUB_COOLING = true`, `SESSION_ACTIVE =
  true`, `set_training_taint(side)`, INFO. Refused ⇒ WARN-once drop.
- `warn_scrub_once` mirror of `warn_end_apply_once`; clear `SCRUB_COOLING` +
  `SCRUB_WARNED` in `clear_session_state`.

### 5. `mod.rs`

- `enable()`: call `bounds::load_scrub_increments()` beside the gesture
  registration; extend the enable log + module doc (Step 7 note, 7/9).

### 6. Gates

Harness `cargo test` (301 + new) → `cargo check --target
x86_64-pc-windows-msvc` → `cargo fmt` → `./build.sh` → maintainer demo
(plan Step 7 demo paragraph).

## Risks / notes

- No new signatures, no new detours, no new engine writes — every dispatch
  rides shipped transactions. The riskiest line is the gesture-arm
  restructure in `on_input_event` (keep triple-4/5/6 byte-for-byte).
- The loop-vs-scrub concurrency edge (press within the prepare window of the
  loop bound) is accepted: generation last-wins, loop-to-A outcome
  (context.md interpretation 8).
- Frame-thread discipline: `scrub()` is straight-line atomics + guarded
  reads, no locks held across `request_reset` (it schedules render-thread
  work internally; the call itself is the same shape the loop driver makes
  from a render-thread closure — here from the input callback, matching
  `set_marker`'s use of the same gated service calls).
