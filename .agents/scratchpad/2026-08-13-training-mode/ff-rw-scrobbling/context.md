## Interpretations & assumptions (auto mode — recorded for audit)

1. **Rewind past the start (`t_q ≤ 0`)**: dispatch
   `request_reset(0, TRAINING_LEAD_MS, Zero, None)` — the plain delayed
   restart, exactly the loop driver's whole-song-restart precedent
   (`active_section_start().unwrap_or(0)` → t=0). Anchor semantics are
   identical to a hypothetical seek-to-0 (`now + delay − wall(0) = now +
   delay` at content 0), satisfying the task's "acceptable if the timing
   anchor behavior matches". AC 4 says "playback resumes from the song
   START" — the target is 0, not A (scrubbing below A is free navigation).
2. **Completion signal for the scrub latch**: add a one-line public
   accessor `song_reset::reset_in_flight()` over the existing
   `RESET_IN_FLIGHT` atomic (set at Started, cleared at completion AND all
   recovery paths AND scene changes — strictly more robust than any
   count-observation heuristic, and the loop-cooling analogue).
   `SCRUB_COOLING` (the contract's own AtomicBool) is set on `Started` and
   lazily cleared at the next press once `reset_in_flight()` reads false;
   also cleared by `clear_session_state`.
3. **Score containment incl. the t=0 edge**: AC 7 demands suppression for
   ANY scrub. The Step-5 subscriber covers `t > 0` automatically; a
   rewind-to-start (t=0) only re-taints while `SESSION_ACTIVE`. The scrub
   therefore sets `SESSION_ACTIVE` + `score_guard::set_training_taint(side)`
   on `Started` — the exact `set_marker` gesture pattern (existing taint
   machinery only; nothing reimplemented).
4. **Versus safety**: the scrub requires a live binding
   (`song_rate::runtime::active_content_grid()`), which the scene-26
   classifier never arms for versus/course — so a scrub can never disturb
   the other player (fail-open WARN-once instead). This also gates the
   t=0 restart path uniformly (no binding ⇒ no scrub at all).
5. **WARN vs debug split**: cooling/in-flight refusals and transient
   no-live-count → `log_debug!` (silent drop); structural failures (no
   binding, chart end unreadable, degenerate bound, seek unavailable,
   refused transaction) → one WARN per song (`SCRUB_WARNED`, cleared with
   session state).
6. **Margin applies after the min** (`min(b_live?, chart_end) − margin`),
   exactly as the task/plan spell it — the seek transaction's own gate
   refuses at `min_end − 1000`, and under a LOOP OFF truncated end
   `chart_end_raw` already reads B, so the formula stays aligned with the
   transaction on every path. (The loop_fire_bound "margin guards stock
   only" reshape does NOT transfer here: seeking exactly TO B would land on
   an instant end/loop-fire — the margin guards the transaction's own gate.)
7. **Quantize-after-clamp**: `quantize_marker` moves ≤ ~one ADPCM block
   (~3 ms content); the 1000 ms margin absorbs it (no re-clamp needed).
8. **Loop driver is NOT taught to yield to the scrub** (out of contract
   scope): a loop firing during a scrub's ~150–300 ms prepare window is
   possible only when the press lands within the window of the fire bound;
   song_reset's generation mechanism makes it safe (last-wins), and the
   outcome (loop to A) is semantically acceptable there.
9. **Config normalize host tests** live in `section_math` (pure
   `normalize_scrub_increment_ms`: `None` → 5000 = "absent block");
   config.rs itself is not harness-mountable — its serde-default wiring is
   structural and validated by `cargo check` + the cabinet demo.
