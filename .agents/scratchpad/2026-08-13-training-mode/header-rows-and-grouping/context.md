## Key code facts (explored)

- `ordering.rs`: `compute_order(registered, configured) -> (Vec<usize>, unknown)`
  is pure; `display_order_for` owns the OnceCell + identity fast-path +
  warn-once. NOT yet harness-mounted. Uses once_cell + `crate::log_warn`
  (harness has both; log_warn is a crate-root `#[macro_export]` stub).
- `builder_hook.rs`: per-open snapshot `Vec<(OptionHandle, String, RowKindTag)>`
  (availability-filtered, carries TRUE registry indices), then
  `display_order_for(&ids)` permutation, then injection loop routes by
  `RowKindTag` (Enum/Scalar) and binds enum labels at injection.
- `registry.rs`: `FrameworkState::try_register` validates Duplicate then
  UnknownParent; `RegisteredOption.preview_image_names()` drives preview atlas
  injection (default arm returns base name — headers must return empty);
  `ribbon_texture_names_for` is enum-only already. `snapshot_for_save`/
  `json_persisted`/`reset_session_values` all key off `PersistMode` — a header
  with `PersistMode::None` is naturally inert on every persistence path.
- `rows.rs`: donor-clone factory. Enum path: `game_malloc(0x330)` → zero →
  ArrowColor donor ctor → synth primary vtable (COL at [-1], 8 slots; slot 4 =
  advance, slot 6 = noop, slot 7 = render) → clone `+0xC0` IOptionElement
  vtable (preview) → `write_page_tag(Page6)` → push RowSlot{kind}. Render
  (`render_enum`): position pin (row+0x88/+0x90 f64 + ancestor chain at +0x60)
  via `bm2d_api::set_position`, label bind to `option_usr` child
  (mc_set_param 0x1007=1, 0x101e=1, mc_load_bitmap), value chip to
  `choice_usr/choice_usr`, marker + tri-arrows under `choice_usr/...`.
- `+0x28` = the MI selectability-interface vtable pointer (donor writes
  0x180377300-era table; slot 0 `bool isSelectable(this=row+0x28)` hardcoded
  ret 1; slot 1 `onFocusChanged(this, bool)`). All three cursor paths test
  slot-0 && `+0xB8`; layout engine ignores slot-0. (research §1–2)
- `+0xA0/+0xA8` = f64 per-row layout extents (options menu is vertical ⇒
  y-advance reads `+0xA8`); per-row input the ctor fetched from the
  "option_item" metrics. Halving affects only this row's slot. (research §5,
  options_scroll_research row-field table)
- `mod.rs` facade: `register_option` also fires `asset_gen::register_label_for(id)`
  (atlas injection for `seop_item_<id>`) + preview/ribbon registration (both
  empty for headers) + initial on_change dispatch for both sides (noop for

- `filter_hook`/`options_scroll` consume `row_handles_for_tab` →

## Assumptions / interpretations (auto mode)

- "Callbacks refused" = `spec.on_change` differs from the api-module default
  noop (`default_on_change_noop`, exposed pub(crate) for the comparison), or
  save/load transforms present. "Values" is structural (UiKind::Header has no
  values) plus `default_value != 0` refused (headers hold no state).
- "Persistence refused" = anything but `PersistMode::None`.
- Header render hides the `choice_usr` subtree each frame (single
  0x1007=0 + 0x101e=1 on the named child) so the donor clip's value box art
  disappears; label binds to `option_usr` as on other rows. Marker/arrows are
  simply never driven.
- The `+0xC0` IOptionElement preview-vtable clone is SKIPPED for headers
  (never focusable ⇒ getter unreachable; donor native slot returns "" safely).
- Shared `+0x28` table carries the donor's COL pointer at [-1] (same RTTI
  discipline as every other synthesized vtable here); both slots are mod stubs
  (research §7 — never reuse native fn addresses). Built lazily at first
  header allocation from the donor-ctor-written table.
- Header label asset: 352x16 (2× label width), black, horizontally centered —
  renders wider than the label column into the (hidden) value area from the
  same anchor. Tunable after the cabinet look (approved open item).
- `+0xA8` halving guards on finite/positive donor value; skip+WARN otherwise.
