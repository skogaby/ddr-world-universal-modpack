## Session-vs-None resolution (the task's explicit Explore question)

`PersistMode::None` is NOT the needed behavior — its doc claimed a card-swipe
reset that **no code implements** (zero users, no reset mechanism anywhere in
the codebase; the in-memory cache lives across card swaps). `Session` =
None's exclusions + a real card-in reset. Not redundant; no maintainer halt
required. `None`'s false doc corrected in the same pass.
