## Explored facts

- `bounds.rs` latch sites: loop latch at `try_resolve_row_bounds` (side in
  scope, before the digest gate); row-engagement latch after
  `resolve_bounds` when `a_ms > 0 || b_ms > 0`; `set_marker('A'/'B')` sets
  `SESSION_ACTIVE` per arm (triple-5 clear does NOT taint — the song already
  played altered content, taint set when markers were set; clearing never
  untaints by design).
- `training_mode/mod.rs`: enable() registers input + scene callbacks with
  `Option<usize>` handles; `assist_tick.rs` already models the song_reset
  subscriber handle (`reset_cb_id` + `song_reset::remove_callback`).
- `song_reset::on_song_reset(impl Fn(i32))` → usize id; fired on the frame
  thread after every completed in-place reset (seek transaction, t=0 resets,
  adjust_run_to) with the content time.
- `stage_records::side_entered(side) -> Option<bool>` (PlayerWork+0x4).
- `assist_tick.rs` scene callback latches `LATCHED_ENABLED` for both sides at
  GAMEPLAY entry; disable() zeroes the latches.
- Restart-from-A re-taint rationale: `quick_restart_or_fail::trigger_restart`
  (line ~500) calls `reset_song_taint()` at the trigger, BEFORE the seek to A
  lands — the subscriber re-taints on completion (t>0).

## Assumptions / decisions (auto mode record)

- **assist_tick disable() also level-writes the taint false for both sides**:
  the producer's callback disappears on disable, so without this a taint from
  the last clapped song would go stale (suppress an honest later song).
  Level semantics extend naturally: producer gone ⇒ level false. Minor
  conservative addition, recorded as such.
- The subscriber taints on ANY t>0 reset without inspecting the cause: every
  t>0 reset in the codebase is training-originated (restart-from-A, the
  silent-start adjust, loop iterations to A>0), and the task names this
  uniform coverage as intended ("any future seek path").
- Sides where `side_entered` returns `Some(false)` for both (or None):
  fall back to tainting both (conservative, per the task text).
