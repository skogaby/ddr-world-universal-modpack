## Implementation approach

`src/services/score_guard_tests.rs`. No other file changes; no callers added
(task-02 wires the producers).

1. **Statics** (beside `AUTOPLAY_TAINT` / `QUICK_FAIL_TAINT`):
   - `TRAINING_TAINT: [AtomicBool; SIDES]` — per-song, one-way; doc names the
     producers (bound engagement at entry / marker gesture / seek fired —
     wired in task-02) and the clearing paths.
   - `ASSIST_TICK_TAINT: [AtomicBool; SIDES]` — level-written mirror of
     assist_tick's per-song enable latch (the autoplay model); doc records
     WHY `reset_song_taint` must not touch it (cross-mod scene-callback
     ordering).
2. **Setters** (in the "Taint writers" section, matching house style):
   - `pub fn set_training_taint(side: usize)` — bounds-guard, `store(true,
     Release)`.
   - `pub fn set_assist_tick_taint(side: usize, on: bool)` — bounds-guard,
     `store(on, Release)`.
3. **Predicate**: `is_stage_suppressed` gains
   `|| TRAINING_TAINT[side] || ASSIST_TICK_TAINT[side]` after the existing
   terms; doc sentence updated.
4. **Resets**: `reset_song_taint()` also clears both sides of TRAINING (doc
   updated: honest-replay contract + the task-02 re-taint note);
   `reset_session()` clears both sides of TRAINING and ASSIST_TICK.
5. Module-level doc (`## Taint model`) gains a short paragraph on the two new
   sources.

## Test scenarios (all in score_guard_tests.rs, written FIRST)

All new tests take a shared `static Mutex<()>` test lock (the new statics are
process-global and these tests mutate both sides; the existing rate-ledger
global test touches disjoint state). Each test starts from and restores a
clean-taint state while holding the lock.

1. `training_taint_suppresses_only_its_side` (AC1): clean baseline both sides
   read not-suppressed → `set_training_taint(P1)` → P1 suppressed, P2 clean →
   restore via `reset_session` + verify clean.
2. `assist_tick_taint_is_level_driven` (AC2): `set_assist_tick_taint(P1,true)`
   → suppressed; `(P1,false)` → clean. Also P2 unaffected while P1 true.
3. `reset_song_taint_clears_training_but_not_assist_tick` (AC3 first half):
   both new taints set on P1 → `reset_song_taint()` → training cleared
   (P1 not-suppressed once assist-tick also cleared… concretely: after
   reset_song_taint, P1 still suppressed via assist-tick; clear assist-tick
   by level-write false → P1 clean ⇒ training really was cleared).
   Additionally set training on P2 → reset clears both sides.
4. `reset_session_clears_both_new_sources` (AC3 second half): both taints set
   on both sides → `reset_session()` → all clean.
5. `out_of_range_sides_are_no_ops` (AC-adjacent, req 1/2/3): `set_training_
   taint(2)`, `set_assist_tick_taint(9,true)` don't panic and don't affect
   sides 0/1; `is_stage_suppressed(7)` stays false.
6. `new_sources_compose_with_existing_ones` (req 3): with training set on P1
   AND quick-fail set, both sides suppressed (quick-fail is global); after
   `reset_song_taint()`, P1 and P2 clean (both were per-song). With
   assist-tick P2 + autoplay P2, P2 suppressed; clearing one leaves it
   suppressed until the other clears too.

Failure-first check: tests reference `set_training_taint` /
`set_assist_tick_taint`, which don't exist ⇒ the suite fails to COMPILE
before implementation (the TDD "fails for the expected reason" for missing
