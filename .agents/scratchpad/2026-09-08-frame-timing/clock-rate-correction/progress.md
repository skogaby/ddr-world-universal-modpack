## Deviations from design.md (all fail-open, none change the model)

- **§10's `mc_tick0` formula dropped a term.** Requiring the clap for note `t` to coincide with the song's content `t` gives `skip* = (E_tick0 − S + J) − wall(m0) − C` (the authored `−S` is replaced by the clock's own `−C`); with `S == C` and no pass jitter this is exactly the stock `wall(mc_c − m0)`. Pinned by `onset::tick_skip_star_ms` + its host test; derivation in `tick_align.rs`'s module docs.
- **Assist-tick alignment uses ONE post-onset re-lay instead of K=3 pre-encoded candidates.** §10 proposed pre-encoding candidates for n̂±1 and swapping the matching one; implemented: the commit ships as today (no block-shift change), and after `aux_onset()` arrives the claps are re-laid at SAMPLE positions for the EXACT observed `F0_tick` (not just the pass index) on a background thread (~0.3 s since the extent-limited synthesis), then swapped ahead of `consumed_bytes + 8 KiB`. Same swap mechanism, covers every `n` (no "outside the candidate set" case), removes the ±1.45 ms block quantisation too; the cost is ~0.3 s more of `n̂`-aligned ticks at song start (still inside READY). Refuses corrections > 60 ms. The tick voice is recognised by `generation ≥ commit-time floor && same epoch && F0_tick ≥ F0_song` — NOT by an exact generation read at commit (the identity lands asynchronously; see deploy log 17:15).
- **Arm timing.** The design said "sanity gate at arm"; implemented as a per-frame gate that ALSO drops back to Gating on divergence while ACTIVE (`Reason::Diverged`). That is what makes seeks/adjusts safe: the game re-anchors before `song_reset` publishes the new origin, and the frame in between passes through instead of being corrected against a stale origin. `origin_generation` adoption while ACTIVE handles the same-frame case (`adjust_run_to`).
- **Voice identity for the song** = cue's `+0x240` bank == the manager's slot-5 bank (via new lock-free `game_audio::sound_bank_in_slot`) AND a play scene, rather than the diag's prepare-time correlation map — simpler and independent of the diag being on.
- **`raw` mode** swaps only the line's phase/slope for the newest sample's nominal-rate extrapolation; the fit STILL runs underneath and supplies `mean_lead`/`mean_margin`/`pass_frames`/readiness (C needs them in both modes — a first cut with a pure `Line::raw` could never arm because `pass_frames` was 0).
- **Hot-path reads:** the DS backend object is probed once (0xE0 bytes) when first seen and the source node once (0x600 bytes) at identity time; the per-pass cursor and produce paths then use plain unaligned reads (`read_probed`) — no VirtualQuery on the render thread.
- `audio_sync_diag::xact::init_factory` now runs when EITHER the diag or the mod is enabled in config; the CSV recording stays diag-gated.

## Key Facts (cold resume)

- Engine renders in fixed **10 ms / 441-frame passes** on a TIME_CRITICAL thread paced by
  `sleep(lead_ms − 30)`; every pass writes one block. `W`/`Wc`/`P` accumulators live in the
  DS backend at `+0xC0/+0xC8/+0xD0`; the only DAC-position read is `0x435A50` (once per pass).
- Voice `Start` is a POSTED command applied at the next pass → **stock onset jitter is uniform
  0..10 ms per play** relative to the game's anchor. Sample 0 lands at the first frame of the
  block written by the first `0x43CAC0` produce for that node (`node+0x5F8` 0 → >0);
  `F0 = DS+0xC0/blockalign` read there is exact.
- Game tick = libavs RDTSC with QPC-calibrated frequency; CrossOver log `freq=999984252/s`
  ⇒ +15.75 ppm, matching the measured +16 ppm. On Win7 the remaining drift is the sound
  device crystal vs the tick — only the DS cursor exposes it.
- CrossOver DS play cursor is a **512-frame (11.6 ms) staircase**; write cursor = play + 10 ms.
  Win7 granularity unmeasured (expected 10 ms class) — the first tester run's `fit_resid_sd`
  answers it.
- Clock-stub call-out ABI (all four builds): at the patch site `rax` = J (vcall result), `rbx` =
  `T − S − A`, `rdi` = GamePlayActor; rbx is DEAD after the displaced `lea r14d,[rax+rbx]`,
  r12/r14 are written by the displaced instructions ⇒ r12 is the rsp save. The stub is 212 bytes
  of prologue + the identity body; allocation grew to 320.
- Visual pipeline (game): main thread DRAINS the GPU executor at frame start before submitting the
  previous frame, then polls input (T). D3D9 vsync `Present` on the executor thread paces
  everything ⇒ T is sampled at vblank+≤1 ms every frame; judgement is independent of T's phase.
  The tester's "visual and aural move together" is the shared anchor error — the clock fix covers both.
- Input ages need NO transformation for an audio-authority clock (rate mismatch × ≤250 ms age = µs).
- Existing uncommitted diagnostics/frame-pump work, operator config (`mod-config.json`) and the
  unrelated `docs/in_shop_battle_local_versus_research.md` are preserved. No commits made.
