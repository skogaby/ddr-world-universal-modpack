## Implementation shape

`src/mods/multiplayer_bot/mod.rs`:
- `pub const OPT_ID`, `OPT_LEVEL_ID`, `DEFAULT_LEVEL: i32 = 5`.
- `static OPTION_ON: [AtomicBool; 2]`, `static LEVEL: [AtomicI32; 2]`.
- `pub fn option_on(side) -> bool`, `pub fn level(side) -> u8` (clamp via `eligibility::clamp_level`).
- `fn on_option_change(side: u8, v: i32)` (store + INFO), `fn on_level_change(side: u8, v: i32)` (store clamped).
- `fn register_rows()` — the assist_tick shape: parent → (`Ok` INFO | `Duplicate` reseed+show | `Err` WARN+return) → `register_level_row()` → (`row_injection_available` gate | `Ok` INFO | `Duplicate` reseed+show | `Err` WARN).
- `enable`: `register_rows()` after the `CAPABLE` gate, before the scene callback.
- `disable`: `set_option_available(both, false)` first.
- Module docs updated.

`scripts/option_strings.py`: two `LABELS` entries after `autoplay`; three `PreviewSpec`s after the
`assist_tick_volume` preview.

`mod-config.json`: two entries after `autoplay`.

## Risks
- `on_change` fires from a non-render thread at registration — the bodies are atomic stores + one
  INFO (the log macro is thread-safe); no game memory touched.
- `Duplicate` path: `get_value` returns `Option<i32>`; `unwrap_or(0)` / `unwrap_or(DEFAULT_LEVEL)`.
