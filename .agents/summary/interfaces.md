## Mod Trait and Registry (`src/mods/mod_trait.rs`)

```rust
pub trait Mod: Send {
    fn id(&self) -> &str;                     // config key in mod-config.json "mods"
    fn name(&self) -> &str;
    fn description(&self) -> &str;
    fn required_signatures(&self) -> &[&str]; // any unresolved => registry skips the mod
    fn init(&mut self, ctx: &ModContext) -> bool;
    fn enable(&mut self);
    fn disable(&mut self);
    fn is_active(&self) -> bool { true }      // "CAN work", never "effect landed this boot"
    fn early_apply(&mut self, _ctx: &EarlyContext) -> bool { true } // pre-derivation patches
}
```

- **`ModRegistry::register`** skips the mod when a required signature is missing or `init` returns false.
- **`enable` / `disable`** track two separate flags:
  - `requested`: operator intent
  - `enabled`: the effective state, equal to `is_active()` after `enable()`
- **`enable_with_config`** enables everything except `LATE_BINDING_MODS` first (`folder-expansion`, `webui-options`), then those.
- **`mod_enabled_in_config(config, id)`** is the one default rule: absent means ON unless the id is in `DEFAULT_OFF_MODS`. Boot-time checks outside the registry use it too.
- **Menu toggles** are saved through `config::save_mod_states`, which persists `requested`.
- **Boot-only mods** (custom-resolution, fps-unlock, gameplay-timing-fixes) must report `is_active() == true` whenever their sites resolved. This also covers "turned ON from the menu for next launch". Without it, the menu writes the toggle back as off.

## Signature Registry (`src/core/signatures.rs`)

- **Declaring:** add a `SignatureDefinition { name, pattern, description }` to `SIGNATURES`. The description doubles as RE documentation.
- **Resolving:**
  - `resolve_all()` runs one batch scan.
  - `resolve_derived()` then runs the `derive_*` / `find_*` family in dependency order. Each derivation validates its anchor and publishes nothing on failure.
  - Feature groups that must be complete to be safe are **all-or-nothing** derivations.
- **Consuming:**
  - `get_address(name)` is graceful.
  - `require_address(name)` panics, so use it only for names in `required_signatures()`.
  - Typed accessors cover layouts that differ between builds (`gameplay_actor_layout()`, `shutter_actor_layout()`, `scene3d_sites()`, …).
  - Non-address derived values use `publish_value` / `published_value`. They appear in the boot log as `name (derived) = 0x…`.
- **Cross-build check:** run `scripts/validate_signatures.sh <dir>`, then `scripts/sig_harness/shape_diff.py` for anything read at `match+N`. See `workflows.md`.

## LayeredFS Extension Points (`src/services/avs_layeredfs/`)

All are safe to call before `avs_layeredfs::init` (the StepMania loader registers at step 0'); none adds a detour.

- **`mod_paths::register_resolver(fn(&str) -> Option<String>)`** — a virtual-asset resolver: normalised game path → host path to serve. Consulted by `find_first_modfile` AFTER the operator's mod folders, in registration order, on every intercepted open/lstat/convert_path — so it must be cheap for non-matching paths (prefix test). Every DLL-side reader that already goes through `find_first_modfile` (`chart_length`, fast-bootup identity, split discovery) sees the materialised files for free.
- **`arc_handler::register_member_transform(arc, member, fn(&[u8]) -> Option<Vec<u8>>)`** — rewrites one member of a repacked arc AFTER overlays (an operator's full-file `musicdb.xml` overlay keeps working underneath). An arc with a transform is repacked even without a mod folder.
- **`arc_handler::register_pre_repack_hook(arc, fn)`** — runs inside the game's open of that arc, before the repack (the XML-arena patch rides `startup.arc` this way).
- **`arc_handler::register_arc_fingerprint(arc, fn() -> Option<String>)`** — extra cache-key material; the arc cache key is the original arc's AVS size+mtime + overlay stamps + transform member names + fingerprints (the StepMania validated-and-injectable index digest, so a changed pack set or a re-run of the prep tool re-repacks). `startup_arc_seen()` reports whether this boot's open went through LayeredFS.
- **Progressive reads** — `stepmania::progressive::register` publishes a `ProgressiveFile { watermark, tail_ready, done }` findable by its `.part` and final paths; `file_hooks` records `fd → handle` at open and holds a read past the watermark (≤ 5 s, then passes through). `lseek`/`close`/`fstat` stay unhooked; the per-fd cursor follows what each read returned (the FileManager's single I/O worker streams sequentially).

## Cross-Mod Predicates Features Must Respect

| API | Rule |
|---|---|
| `multiplayer_bot::is_bot_side(side)` | During a bot song both sides read as entered. Any cabinet-wide policy that folds both players' option values must exclude the bot side. |
| `ddr_selection::legacy_package(base)` + `armed_skin()` | A feature that edits a HUD template (s-marvelous) must pick the song's package — World's or legacy skin N's (the legacy exports share World's names and are byte-identical across some skins) — and stand down where it has nothing for that skin. |
| `s_marvelous::on_ddr_selection_enabled()` / `legacy_combo_smarv(skin, side)` | DDR SELECTION's `enable` triggers S-Marvelous' legacy-skin staging; its A3 combo write asks for the all-S-Marvelous sheet (skins 4–5). |
| `ddr_selection::leaked_forced_options(side)` | The save trampoline strips forced 1st-5th options from the save tree. |
| `per_song_judgement_offsets` at `Priority::Early` | It writes `Option+0x24` before assist-tick reads it at `Normal` on the same dispatch. |
| `per_song_judgement_offsets::override_hook::set_song_delta_provider` | A cabinet-wide per-song judgement delta (today StepMania auto-sync, `stepmania::sync_apply`, read from the prep tool's `sync.bin`) is applied THROUGH this one write — `compose.rs`: `(player's entry, else stock) + delta`, ±100 — never by rewriting a song file; the provider runs on the game thread at a side's first judge, so it must not block (today: a map lookup + freeze), and must return the same value for both sides and every replay in the session (freeze rule). |
| `stepmania::is_injected(mcode)` / `is_injected_basename(&str)` / `injected_song(mcode)` | Anything that treats an injected StepMania song differently (fast-bootup quarantine + radar exclusion, `hide`, the taint) keys on these. An injected song must never reach a score save: route new score paths through `score_guard`. |
| `stepmania::is_armed()` | True once `early_init` ran with the mod enabled and a songs root; `scroll_remap` installs only when it is armed and `stepmania_packs.scroll_gimmicks` is on. |
| `s_marvelous::is_enabled()` / `state::is_armed` | Readers of the S-Marv split (PUS widget, bot filler) gate on it. |
| `song_reset::on_song_reset` | Subscribe to it when state must follow in-place restarts and seeks (movie sync, calibration, training). |
| `versus_mirror::register` / `mirror_edit` | Rows backed by one cabinet-global mechanism mirror P1 → P2 while both players are entered. |

## Option-Row Framework (`src/services/custom_options/api.rs`)

`register_option(RegisterSpec) -> Result<OptionHandle, RegisterError>`

- **`UiKind`:** `Enum { allowed_values: Vec<EnumValue> }` (texture-labelled), `Scalar { min, max, step_fine, step_coarse, format }`, `Header`.
- **`ScalarFormat`:** `Integer`, `FixedPoint`, `OffsetInteger`, `SignedUnit`, `Unit`, `MinutesSeconds`, `PrefixedIndex`, `Labeled`, `Dynamic(fn(&str, i32) -> Option<String>)`.
- **`PersistMode`:**
  - `Full`: network wire field `mod_<id>` plus JSON cache
  - `SaveOnly`: network save only
  - `Local`: JSON cache only, never on the wire
  - `None`
  - `Session`: reset at card-in
- **`LoadSource`:** `Network` or `JsonPrime`.
- **`ShowWhen`:** `Always`, `Equals { parent_id, value }`, `NotEquals { parent_id, value }`. The parent must be registered first.
- **`MenuPlacement { in_game, overlay }`:** the operator can override it per id through `custom_options.option_menu_settings`.
- **Builders:** `.on_change`, `.show_when`, `.persist_mode`, `.persist_transform` / `.save_transform`, `.menus`, `.in_game_only()`, `.overlay_only()`, `.display_name`, `.description`.
- **Runtime:** `get_value`, `set_value` (fires `on_change`), `set_value_silent`, `set_scalar_bounds`, `set_option_available`, `row_injection_available`, `on_menu_open` / `on_menu_close` / `on_preview_request`, `flush_label_atlas`.
- **Label textures:** row labels and value chips come from generated textures (`scripts/option_strings.py` → `scripts/gen_option_labels.py`). A new row needs its textures shipped under `data_mods/custom_options/`, otherwise its label renders blank.

**Overlay-menu cabinet-wide rows** (`src/mods/mod_menu/rows.rs`):

- `register_scalar_row(ScalarRowSpec)`
- `register_enum_row(EnumRowSpec)`
- `set_row_show_when(child, parent, value)`
- `remove_rows_for(ids)`

Re-registering a key replaces it in place.
