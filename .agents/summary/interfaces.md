## The Mod Trait (`src/mods/mod_trait.rs`)

```rust
trait Mod: Send {
    fn id(&self) -> &str;                    // config key, e.g. "fast-bootup"
    fn name(&self) -> &str;                  // mod-menu display name
    fn description(&self) -> &str;
    fn required_signatures(&self) -> &[&str]; // unresolved => registry skips the mod
    fn init(&mut self, ctx: &ModContext) -> bool;
    fn enable(&mut self);
    fn disable(&mut self);
    fn is_active(&self) -> bool;             // default true; self-disabled mods return false
    fn early_apply(&mut self, ctx: &EarlyContext) -> bool; // default no-op; pre-derivation patches
}
```

`ModRegistry`: `register` (checks required signatures, calls `init`), `enable`/`disable` (per-mod `HookManager` auto-removes hooks on disable), `enable_with_config` (default-on; `LATE_BINDING_MODS` = folder-expansion + webui-options enable last), `get_entries` → mod-menu.

## Service Singleton Pattern

Every service exposes `init(...) -> bool` (called once from `src/lib.rs` in a fixed order) and `is_available() -> bool`; consumers check availability and degrade gracefully. Services returning game data use `Option<T>` throughout.

## Signature Registry (`src/core/signatures.rs`)

- Declare: an entry in the `SIGNATURES` table (`name`, wildcard AOB `pattern`, `description`; the doc comment carries annotated disassembly + per-build match evidence).
- Resolve: `resolve_all()` (batch scan at init phase 2), `resolve_derived()` (phase 3 — derivation methods that publish additional names; fail-closed).
- Consume: `get_address(name)` (graceful) / `require_address(name)` (panicking — only for names listed in a mod's `required_signatures()`), `get_all_matches(name)`.
- Verify across builds: `scripts/aob_check.py` (a clean signature matches exactly once in every supported build).

## Shared Dispatcher Contract

`register_pre(Priority, fn)` / `register_post(Priority, fn) -> Option<CallbackHandle>` / `unregister(handle)`. Callbacks are plain `fn` pointers, dispatched in ascending priority, each wrapped in `catch_unwind`. Priorities matter: e.g. per-song-judgement-offsets registers at `Priority::Early` because assist-tick reads the same field at `Normal` on the same dispatch.

## Option-Row Framework (`src/services/custom_options/api.rs`)

`register_option(RegisterSpec) -> Result<OptionHandle, _>` with:

- `UiKind`: `Bool`, `Enum { allowed_values }` (texture-labelled), `Scalar { min, max, step_fine, step_coarse }`, `Header` (display-only)
- `ScalarFormat`: `Integer`, `FixedPoint`, `OffsetInteger { display_offset }`, `SignedUnit { unit }`, `Unit { unit }`, duration `M:SS`
- `PersistMode`: `Full` (network + JSON cache), `SaveOnly` (network save only — the WebUI cosmetics), `None`, `Session` (reset at card-in)
- `ShowWhen`: `Always`, `Equals { parent_id, value }`, `NotEquals { parent_id, value }` (conditional child rows)
- `MenuPlacement { in_game, overlay }` — overridable per-id by the operator's `custom_options.option_menu_settings`
- Callbacks: `on_change` (player edits), plus `set_value_silent` for observer-only reseeding; `load_transform` for clamp/snap on load
- Wire persistence: a `PersistMode::Full`/`SaveOnly` option id `x` becomes network field `mod_x`; string-typed fields register via `custom_options_persistence::register_string_field`

Overlay-menu contributed rows (cabinet-wide settings) use the separate frozen API in `src/mods/mod_menu/rows.rs`: `register_scalar_row` / `register_enum_row` / `remove_rows_for`.

## Persistence & Score Policy Contracts

- Save/load: `custom_options_persistence` appends `<mod_*>` s32/string children on the ess.dll save path and parses them on load; gated by `custom_options.persist_network` / `persist_json`.
- Taint: mods feed `score_guard` (`set_autoplay_taint`, `set_quick_fail`, `set_training_taint`, `set_assist_tick_taint`, rate ledger); persistence enforces — tainted per-stage saves suppressed, logout saves sanitised (records virginised + league stripped) or fully suppressed if sanitisation is unavailable (fail-closed).
