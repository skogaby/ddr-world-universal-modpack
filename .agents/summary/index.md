# Documentation Index

> Machine-generated by the codebase-summary workflow. Everything in `.agents/summary/` is regenerated on each run, so do not hand-edit it. Durable human rules belong in `AGENTS.md` → Custom Instructions. Per-feature mechanisms belong in each module's `//!` doc, and RE investigations belong in `docs/`.

## How to Use This Documentation

Load this file first. It routes a question to the detailed file that answers it. For one specific feature, go from `components.md` (entry file + RE note) to that module's own docs.

**Quick routing:**

| Question | File |
|---|---|
| What is this project, what is the tech stack, what does the repo look like? | `codebase_info.md` |
| How do the layers relate? Init order, threads, hook discipline, resilience? | `architecture.md` |
| Where does module or feature X live? What mods exist, and which harness / RE note goes with each? | `components.md` |
| Who owns which hook? What is the subscriber API? Which cross-mod predicates apply? Option-row API, Mod trait, signature registry? | `interfaces.md` |
| Allocators, game layouts, config sections (who writes what), persistence wire model, file formats? | `data_models.md` |
| Build, host tests, signature sweep, adding a mod/row/shader, runtime flows, the updater pipeline? | `workflows.md` |
| Crates, toolchain, other crates, external tools? | `dependencies.md` |
| Known code issues, stale strings, doc gaps? | `review_notes.md` |

## Consolidated Files (repository root)

- **`AGENTS.md`** (`CLAUDE.md` is a symlink to it) is the always-loaded agent guide. It covers the project summary, directory map, entry points, repo-specific tools, patterns that deviate from defaults, the cross-cutting gotchas, and the preserved Custom Instructions (workflow/git rules, quality rules, PDD convention). It deliberately contains no per-feature mechanism detail.
- **`README.md`** is user-facing: installation, features, configuration, Wine, and a short "For Developers" section.

## Refreshing

Re-run the codebase-summary workflow after structural changes: new mods or services, moved hooks, new config sections, or tooling changes.

- **Safe to regenerate:** everything in `.agents/summary/`, and every AGENTS.md section above Custom Instructions.
- **Hand-maintained, never regenerated:** AGENTS.md → Custom Instructions, `.agents/learnings/`, `.agents/steering/`, `docs/`, and module `//!` docs.
