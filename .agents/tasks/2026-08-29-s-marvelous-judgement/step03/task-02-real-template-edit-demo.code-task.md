# Task: real-template edit validation and render preview

## Description
Extend the validation script's dev legs with an EDIT leg: run the Step 3
primitives against the real `dance_judge` template (clone `in_marvelous` →
`in_smarvelous` with a fresh shape), verify the edited output re-parses with
the expected structure AND still passes bemaniutils' parser, and render the
cloned segment with `afputils render` so a human can eyeball it. This is the
plan step's demo.

## Background
Synthetic tests prove the primitives' bookkeeping; the real template proves
them against Konami's actual timeline shapes (mask helpers, aep children,
shared segments). The render preview is the cheapest possible look at "does
the cloned segment play" before any cabinet deploy. Rendering a NEW shape
would need a new geo + texture (Step 4's work) — so for the render leg, the
clone uses an IDENTITY remap (clone still references the marvelous art):
the render should look exactly like the stock marvelous flash, played from
the new label. The remapped-shape variant is still validated structurally
(parse + bemaniutils cross-parse), just not rendered.

## Technical Requirements
1. Extend `ap2check` with an `edit-demo <afp> <bsi> <out_afp>` subcommand:
   descramble → parse → `add_shape` + `clone_labeled_segment("in_marvelous",
   "in_smarvelous", remap)` (remapped variant) → serialize → verify
   re-parse + label present → ALSO produce an identity-remap variant →
   write the identity variant's descrambled bytes to `<out_afp>` (temp dir)

2. New Leg C in `scripts/validate_s_marvelous.sh` (same env gating as A/B):
   - Run `edit-demo` on `dance_judge` from the extracted package.
   - Cross-parse the edited file with `afputils parseafp` (needs an empty/
     no-op BSI — the edited file is descrambled; generate a 2-byte zero BSI,

     the CLI supports for a labeled sub-range; a full-template render that
     includes the cloned frames is acceptable fallback). Copy the preview to
     a path printed at the end for the maintainer to open — use a stable
     location OUTSIDE the repo (e.g. the system temp dir) and print it.
