# Task: core/ap2 serializer and round-trip identity

## Description
Add serialization to `core/ap2`: `Ap2Doc::serialize()` recomputing every
offset, length, count, and alignment — validated by byte-identity round-trip
(`serialize(parse(x)) == x`) on synthetic fixtures built by the writer
itself.

## Background
No open AP2 writer exists anywhere (bemaniutils round-trips AP2 as an opaque
blob) — this is the genuinely new piece of the whole feature. The property
everything downstream stands on: any file the parser accepts must re-emit
byte-identically when unmodified. Konami bytes must NOT enter the repo, so
committed fixtures are synthetic (built via the writer + a fixture builder);
real-template validation is task-03's dev-only harness leg.

Serialization rules (from the design and the repo's AP2 knowledge):
- String table: rebuild with u16 offsets, 4-byte aligned total size
  (misalignment is a live game FATAL — docs/afp_system.md §9), ≤ 64 KiB.
  Preserve existing string order where unmodified (byte-identity); new
  strings append.
- Tag headers: `(tag_id << 22) | size`, payloads padded to 4-byte alignment.
- Frames: packed u32 (20-bit start index, 12-bit count) — validate widths.
- Name-reference (label) arrays re-emitted per section; section header
  counts/offsets recomputed; nested DefineSprite sections recursively
  re-serialized; root header total-length + string-table offset/size +
  tag-section pointer fixed up.
- Serialization returns `Option<Vec<u8>>` — `None` (never panic) when a
  limit is violated (string table overflow, frame index > 20 bits, tag
  size > 22 bits).

## Technical Requirements
1. `Ap2Doc::serialize(&self) -> Option<Vec<u8>>` in `core/ap2` (same
   std-only constraint as task-01).
2. A reusable fixture builder (promoted from task-01's test helpers if
   present): programmatic construction of valid `Ap2Doc`s — N sprites,
   labels, opaque tags, PlaceObjects with each modeled flag — used by tests
   AND later by task-03/dev tooling.
3. Round-trip identity tests: for a matrix of builder-generated fixtures,
   `serialize()` → `parse()` → `serialize()` is byte-stable, AND for
   fixtures first emitted as bytes, `serialize(parse(bytes)) == bytes`.
4. Limit-violation tests: oversized string table / frame index / tag size ⇒
   `None`, no panic.
5. PlaceObject encode/decode round-trip across the modeled flags
   (source_tag_id, movie_name, translate, scale/rotate fixed-point) with
   sign-edge values (negative tx/ty, extreme scales).
6. All tests run via `./scripts/validate_s_marvelous.sh`.

## Acceptance Criteria

1. **Byte-identity round trip**
   - Given any builder fixture emitted to bytes
   - When parsed and re-serialized without modification
   - Then output equals input byte-for-byte

2. **Mutation stability**
   - Given a parsed fixture whose model is mutated (string appended, opaque
     tag appended) and serialized
   - When the output is parsed again
   - Then the model round-trips (parse(serialize(m)) structurally == m) and
     all offsets/alignments validate

3. **Limits fail closed**
   - Given a doc exceeding a packed-field or table limit
   - When serialized
   - Then `None` is returned without panic

4. **Harness green**
   - Given the module on disk
   - When `./scripts/validate_s_marvelous.sh` runs
   - Then all ap2 tests pass
