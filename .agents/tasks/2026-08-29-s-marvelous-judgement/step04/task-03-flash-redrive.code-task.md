# Task: flash re-drive wiring and cabinet readiness

## Description
The runtime half of the gameplay flash: expose the captured `dance_judge`
clip from `overlay_element_styling` (shared idempotent install + a
`judge_clip(side)` accessor), re-drive it to `in_smarvelous` from the
S-Marvelous classification path, gate on patch success, and hand the
maintainer a deployable build (the Step 4 cabinet demo).

## Background
Design §4.4. The stock 0x1028 broadcast already played the clip at
`in_marvelous` (synchronously inside judge_submit's original); the mod
re-drives the SAME clip one event later in the same frame:
`afp_mc_op(*(wrapper+0x110), 0xF09, "in_smarvelous")` — goto-label-by-string
via the libafp export, no play/visibility calls needed (stock set them).
Calibration-hide and judgement styling need no code (same clip). The clip
wrapper comes from `overlay_element_styling::capture`'s registry
(`dance_judge` is already classified + side-bound); the capture detours must
install even when that mod is config-disabled — the `data_feed::install`
idempotent-shared precedent.

## Technical Requirements
1. `overlay_element_styling`: (a) refactor the capture install into an
   idempotent `ensure_capture_installed(signatures) -> bool` callable from
   other mods' inits (the mod's own init keeps calling it; one detour set,
   installed once); (b) `pub fn judge_clip(side: usize) -> Option<*mut u8>`
   returning the side-bound `dance_judge` wrapper (game-thread-only —
   document; returns None when unbound). Do NOT regress the styling mod's
   own behavior (its enable/disable semantics unchanged).
2. `src/mods/s_marvelous/flash.rs`: `on_smarvelous(side)` called from the
   classification path (the data_feed tap block or a thin hook in state —
   keep the disarmed path untouched): gated on `afp_patches::patch_applied()`
   and a per-song latch; resolves the clip via `judge_clip(side)`; issues
   the 0xF09 goto with `"in_smarvelous"`. Panic-free, no locks, no logging
   per event (one-shot WARN on first unexpected failure class).
3. Verify `bm2d_api::mc_op` supports string-arg ops (0xF09); if the shipped
   wrapper is numeric-only, add `mc_op_str` beside it (same export, string
   3rd arg) rather than widening the existing signature.
4. `s_marvelous` init requests `ensure_capture_installed`; enable order:
   assets → patch registration → flash arming (design §4.10).
5. Fail-open matrix honored: patch not applied ⇒ no re-drive (stock word);
   clip unbound ⇒ skip silently (WARN once per session).
6. Gates: `cargo check` msvc, `./scripts/validate_s_marvelous.sh`,
   `cargo fmt`, `./build.sh` — then STOP for the maintainer's cabinet
   deploy (do not commit).
