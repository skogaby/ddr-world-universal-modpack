# Task: Self-update by rename-swap

## Description
Add `selfupdate.rs` and the `SelfUpdate` plan action: when the staged release
carries `ddr_world_hook_updater.exe` whose hash differs from the running
executable, rename the running exe to `.exe.old`, move the staged one into
place, record it in the manifest; delete stale `.old` files at start-up; undo on
same-run rollback.

## Technical Requirements
1. `selfupdate.rs`: `cleanup_stale(exe_dir)` (remove `ddr_world_hook_updater.exe.old`, best-effort); `swap_in(new_exe, running_exe) -> io::Result<SwapReceipt>` (rename running → `.old`, rename new → running); `undo(&SwapReceipt)` (remove new, rename `.old` back).
2. `plan.rs`: `Action::SelfUpdate { rel }` emitted when the stage contains `UPDATER_EXE` and `stage_hashes[exe] != probe(exe)` hash (probe supplies the running exe's hash via the normal disk probe); the exe's hash is recorded in `new_manifest_files`. Order: after `WriteMerged`, before `WriteManifest`.
3. `apply.rs`: execute `SelfUpdate` via `swap_in`; failure → WARN + skip (R24), NOT an error; rollback → `undo`. `Done::SelfSwapped(receipt)`.
4. `main`: `cleanup_stale` right after the game folder resolves. The running exe path = `current_exe()`; when `--game-dir` points elsewhere than the exe's folder, SelfUpdate still targets `root/ddr_world_hook_updater.exe` (the copy in the game folder), i.e. `swap_in(stage exe, root/exe)` — if `root/exe` does not exist, plain move (first install of the updater into a folder).
5. Tests: `swap_in`/`undo` on dummy files; `cleanup_stale`; plan emits `SelfUpdate` only on hash difference; e2e — release zip with a different updater exe → after run `root/ddr_world_hook_updater.exe` has the new bytes, `.exe.old` holds the old bytes (the test binary is NOT the file being swapped, so no lock semantics on the host), next run removes `.old`; `--from-zip` of a zip whose exe matches → no `SelfUpdate`.

## Acceptance Criteria
1. **Swap** — Given a release with a newer updater exe — When installed — Then the game folder's exe is the new one, the old one is `.exe.old`, and the manifest records the new hash.
2. **Stale cleanup** — Given an `.exe.old` — When the updater starts — Then it is removed.
3. **Unchanged** — Given a release whose updater exe matches — When installed — Then no swap happens.
