# Task: Journal crash recovery and empty-directory cleanup

## Description
Implement `apply::recover_if_interrupted` (design §6.4): at start-up, if
`journal.json` exists the previous run died mid-apply — restore every backed-up
file, delete files a `Write{existed:false}` created, delete the journal, log
what was recovered, then proceed with a normal run. Also remove directories
under `data_mods/` left empty by prunes (best-effort, after a successful apply).

## Technical Requirements
1. `pub fn recover_if_interrupted(game: &GameDir) -> Recovery` where `Recovery::{Clean, Recovered{restored, removed, errors: Vec<String>}}`; for each journaled action: `Write{rel, existed:true}` / `WriteMerged{existed:true}` / `Prune{rel}` → if `backup/rel` exists: remove `root/rel` if present, rename backup → root; `Write{existed:false}` / `WriteMerged{existed:false}` → remove `root/rel` if present; `KeepModified`/`WriteManifest`/`SelfUpdate` → nothing. Unreadable journal → delete it, WARN, `Clean`.
2. Called from `main` right after the log is attached (before any network call). Errors are logged (WARN each) but never block the run.
3. Empty-dir cleanup: after `execute` succeeds, for each pruned `rel` walk its `RelPath::parent()` chain while the directory is under `data_mods/`, is empty and is not `data_mods/` itself → `remove_dir`. Stop at the first non-empty ancestor. Remove the `#[allow(dead_code)]` on `RelPath::parent` and `Journal::read`.
4. Tests: unit — recovery table over a synthetic journal + backup layout in temp dirs (restored, created-removed, missing backup → error listed, journal deleted); e2e — run with `DDR_UPDATER_FAULT=apply-after:2` but with the rollback SUPPRESSED (new dev fault `crash-after:N`: return early WITHOUT rollback, leaving the journal) → folder is dirty + journal present; next run recovers (folder byte-identical to the pre-crash snapshot) and then completes the install. Empty-dir cleanup e2e: a pruned file's now-empty parent dir is gone; a dir that still holds a user file stays.

## Dependencies
- Step 4 complete.

## Acceptance Criteria
1. **Recovery** — Given a journal + backups from an interrupted run — When the updater starts — Then the folder is restored to its pre-run state, the journal is deleted, and the run then proceeds normally.
2. **Cleanup** — Given a prune that empties a directory under `data_mods/` — When the apply succeeds — Then that directory is removed; non-empty and `data_mods/` itself are kept.
