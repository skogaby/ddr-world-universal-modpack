# Task: Wire the merges into the install pipeline

## Description
Replace `main.rs::merge_inputs`'s copy-if-absent placeholder with the real
merges: read the user files, merge against the staged release copies, emit
merged bytes only when they differ from the user's current bytes, apply R15 for
unparseable user files, and log the §4.13 merge lines. Extend the e2e harness.

## Background

rows placed"; "Merging judgement_offsets.csv ... N offsets filled, M songs

## Technical Requirements
1. `merge_inputs(game, stage_root) -> MergedFiles`: for each merged file — user absent → release bytes; user present + parseable → merge; merged bytes == current bytes → `None`; user unparseable → copy the file to `backup/<name>.unparseable` (create dir), WARN, `None`; release copy missing/unparseable → WARN, `None`.
2. Log lines: `Merging mod-config.json ... N keys added (first 3 dotted paths, …), M menu rows placed` / `... no changes`; `Merging judgement_offsets.csv ... N offsets filled, M songs added` / `... no changes`.
3. e2e (`tests/apply_e2e.rs`): customised user config (reordered menu, removed row, changed scalar) + release config with an extra top-level key, an extra nested key, an extra menu row under an existing header and a new header+row → all user values/order intact, additions placed per §4.7, report lines present; user CSV with set offsets + blank cells → blank filled, set kept, missing rows appended; unparseable user config → untouched, copied to `backup/`, WARN, run still exit 0 and other files updated; identical config/CSV → not rewritten (mtime unchanged).
4. Backup of the two merged files before overwrite is already handled by `WriteMerged{existed:true}`.

## Acceptance Criteria
1. **Merged in place** — Given customised user files — When a release with additions is installed — Then user values/order survive and additions land as specified, exit 0.
2. **No churn** — Given identical files — When installed — Then the merged files are not rewritten.
3. **R15** — Given an unparseable user config — When installed — Then it is untouched, a copy sits in `backup/`, a WARN is logged, and the rest of the update completes.
