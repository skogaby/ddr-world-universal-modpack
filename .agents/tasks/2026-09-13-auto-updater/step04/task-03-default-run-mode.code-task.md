# Task: Default run mode — fetch, decide, download, install

## Description
Replace the "nothing to do yet" placeholder: a bare run fetches the latest
release, decides via the manifest, downloads + verifies, and hands the archive
to the existing `install()` pipeline. `--check` reports without changes
(exit 0/3), `--include-prerelease` and `--repo` are honoured, every network/API
failure prints one "skipped (...)" line and exits 0.

## Technical Requirements
1. `run_default(cli, game)`: `Checking github.com/<repo> ...` → `fetch_latest` (Err → `skipped (<NetError>) — starting the game with the installed version`, `Skipped`) → `select_asset` (None → skipped) → tag/digest → `needs_update` → `up to date (<tag>)` / `--check` → `update available: <tag>` exit 3 → `Downloading <name> (<MB> MB) ...` with progress → verify → `install(...)` (already extracts/merges/applies) with `release_name = release.name`.
2. Digest: `parse_digest` result → hex for the manifest; absent → WARN + size-only.
3. `placeholder_line` and its tests removed; `Outcome::NothingToDo` now means "up to date"; the console transcript matches §4.13.
4. e2e: `--repo this/does-not-exist` → skipped, exit 0, nothing written (network-dependent test; skip gracefully when offline by checking the message class); `--check` against the real repo with a manifest that names the live tag/digest → "up to date" exit 0 (construct the manifest from a `--check` run's output? simpler: unit-test the decision path with fixtures and keep the live check manual).
5. Manual validation on the real install: `--check` (expect exit 3: installed tag is `local:…`), then a real run → downloads `v1.2`'s asset, verifies, installs, manifest tag `v1.2`; second run → up to date.
