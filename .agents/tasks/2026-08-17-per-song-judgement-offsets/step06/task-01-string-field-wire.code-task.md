# Task: String-field persistence extension and mod_judge_offsets wire (client)

## Description

(emit + load + card-in notification), and wire the mod as its first consumer:
`mod_judge_offsets` emitted on every save, applied on profile load, session

## Technical Requirements
1. Registry in `custom_options_persistence.rs`:
   `register_string_field(wire_name: &'static str, save: fn(u8) -> Option<String>, load: fn(u8, &str))`
   and `register_card_in_callback(cb: fn(u8))`.
2. Emit (save trampoline, post-`original.call`, same `PERSIST_NETWORK` gate
   as `emit_network_children`): for each field with `Some(value)`, create a
   kbin **str** child under `/data/option` via a second typed transmute of
   ordinal 163: `fn(ctx, parent, 11, name: *const i8, value: *const i8)` —
   the value slot carries a POINTER to the NUL-terminated string
   (ess `ghost` emission convention, Ghidra-verified). CString both name and
   value; skip + warn-once on interior NUL.
3. Read (load receiver): per registered field, ordinal 176 as
   `(ctx, option_node, name, 11, buf, capacity)` with a 64 KiB heap buffer;
   negative return = absent (skip). Buffer → NUL-terminated string. Side is
   unresolvable at receive time: push into a `PENDING_STRING_LOADS` keyed by
   ddrcode (`*(job+0x18)+0x48`), mirroring `PENDING_RATE_RESETS`.
4. Drain at the existing SONG_SELECT-entry callback, ordered: card-in
   callbacks fire FIRST (mod resets the side to CSV baseline), then string
   loads apply (server replaces the session map). Reuse `side_from_ddrcode`.
   Card-in callback timing: fire exactly where `PersistMode::Session`
   card-in resets happen (`apply_pending_card_in_resets`), per side.
5. Mod wiring (`per_song_judgement_offsets`): at `enable()` register
   - save: `store.is_armed()` gate → `Some(encode_side(side))` (empty map ⇒
     `Some("")` — the server-clear signal); un-armed ⇒ `None` (omit field);
   - load: `apply_server_string(side, value)` + aggregated WARN from
     `DecodeStats` when dirty + one INFO with entry count;
   - card-in: `reset_to_baseline(side)`.
6. Failure legs: emit ordinal null-return ⇒ warn-once, skip field this save;
   registry consulted only when the detour pair installed (same condition as
   the s32 channel). No new ordinals; no locks across `original.call`.
7. Harness green; `cargo check` clean; release build clean. Cabinet check:
   emitted `<mod_judge_offsets>` visible in save traffic; server (pre-Step-7)
   safely ignores it.

## Acceptance Criteria
1. **Emit** — Given an armed store with entries for the entered side — When
   any save fires — Then the request carries `<mod_judge_offsets>` (str)
   with the sorted `code|offset|...` encoding (verify via server log /
   packet dump); un-armed or mod-disabled ⇒ field absent.
2. **Load + merge order** — Given a profile with a stored string — When the
   player cards in — Then at song-select entry the side resets to baseline
   FIRST, then the server map replaces it (rows re-seed accordingly).
3. **No regression** — s32 mod_* fields, Session-mode resets, score_guard
   paths unchanged.
