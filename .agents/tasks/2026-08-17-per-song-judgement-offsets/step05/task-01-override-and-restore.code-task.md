# Task: Gameplay override, restore layers, tree-fix safety net

## Description
The feature's core: apply the stored per-song offset to `Option+0x24` during
gameplay and guarantee the override never reaches a save. New `override.rs`
in the mod plus a small tree-fix helper in `custom_options_persistence`.

## Technical Requirements
1. `override.rs` state (design shape): `PENDING: [AtomicI32; 2]`
   (i32::MIN = none), `ACTIVE: [AtomicBool; 2]`, `STOCK_CACHE: [AtomicI32; 2]`,
   `LOCKED_CODE: Mutex<Option<String>>`. `player_option_table` address stashed
   at init (via ui::init pattern or its own init fn).
2. Scene callback (registered at enable, gated on `is_active()`):
   - `next == SONG_TO_STAGE_INTERSTITIAL (26)`: latch `ui::current_code()`
     into LOCKED_CODE.
   - `next == GAMEPLAY (28)`: per side — `stage_records::side_entered(side)`,
     course/event skip (same accessors quick_restart's predicate uses —
     check `src/services/stage_records.rs` for `course`/`event` reads; if
     the exact predicate helpers aren't public, read the same fields it
     does), then `store.arm_decision(...)` → set PENDING.
   - `prev == GAMEPLAY (28)`: for each ACTIVE side, write STOCK_CACHE back
     to Option+0x24, clear ACTIVE (+ INFO log with values).
   - `next == SONG_SELECT (25)`: sweep — if any ACTIVE survived, restore +
     WARN (should be unreachable).
3. Judge-dispatch write: `judge_hook::register_pre` (see
   `src/services/song_rate/real_speed.rs` for the exact idiom — side at
   `actor+0x84`): consume PENDING for the side → read stock from
   `*(*(table + side*8)) + 0xE0 + 0x24`; refuse + WARN once if outside
   ±100; else cache, write override, set ACTIVE.
4. Tree-fix helper in `custom_options_persistence.rs`:
   `pub fn replace_option_s32(kbin_ctx, tree_or_option_node, name, value) -> bool`
   implementing find(162) → remove(164, non-fatal if unresolved) →
   add(163, type 6). Mirror `strip_league_node`'s navigation to
   /data/option. Called post-`original.call` in `save_sender_trampoline`
   via a new hook point: a registered check
   (`per_song_judgement_offsets::override::fixup_leaked_override(side)` →
   Option<i32 stock>) — keep coupling one-directional (persistence calls a
   fn pointer registered by the mod, matching the service's style) or a
   direct crate call if simpler and consistent with existing code (score_guard
   is called directly — direct call is acceptable).
5. Restore writes must be unconditional-safe: only write when ACTIVE was
   set (STOCK_CACHE valid), through the same guarded pointer walk; if the
   walk fails at restore time, WARN loudly (leak risk) — the trampoline
   fix is the remaining layer.
6. All callbacks panic-contained per project rules; no locks across game
   calls.
7. Harness green, `cargo check` clean, release build clean.

## Acceptance Criteria (cabinet, deploy #3)
1. A +50 override audibly/measurably shifts judgement vs the row OFF.
2. Profile purity: after per-stage save and card-out, server
   `opt_timing_music` = stock value; stock JUDGEMENT OFFSET row unchanged.
   Across natural exit, quick-restart, quick-fail, in-place restart.
3. Course mode: no override.
4. No WARNs on the happy path.
