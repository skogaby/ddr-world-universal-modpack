# Task: Option rows, wheel-poll seeding, edit capture

## Description
Register the two option rows, poll the song-wheel selection per frame at
song select, seed the rows from the store as the selection moves, and capture
user edits back into the store + CSV. This completes the visible editing loop
(plan Step 4).

## Technical Requirements
1. New `ui.rs` in the mod (keep `mod.rs` lean): row registration + the
   per-frame poll + on_change handlers. Called from `enable()` after
   `bootstrap::start()`.
2. Rows (design D3/D4/D19, PersistMode::None both):
   - `RegisterSpec::bool_toggle("adjust_song_offset").on_change(...)`
   - `RegisterSpec::scalar("current_song_offset", -100, 100, 1, ScalarFormat::Integer)
     .step_coarse(10).default_value(0)
     .show_when(ShowWhen::Equals { parent_id: "adjust_song_offset", value: 1 })
     .on_change(...)`
   - Parent first (UnknownParent validation). Registration failures WARN and
     leave the mod inert (design D20 — if the parent registers but the child
     cannot, treat as inert too: deregistering isn't supported, so gate all
     behavior on a rows-ready flag).
3. Wheel poll: `input_manager::on_frame` callback registered at enable;
   scene-25 gate via `scene_manager::current_scene()`; the
   `selectmusic_model` global (from `ctx.signatures` at init, stored in a
   static) holds a POINTER to the model; highlighted-song weak_ptr at
   `*(model)+0x1B0` (ctrl block +0x1B8, liveness = strong count != 0);
   selection change = raw pointer compare; song code via the guarded inner
   vtable getter — mirror `music_wheel_song_length.rs`'s
   `read_song_code`/poll shape exactly (null guards, module bounds checks,
   panic containment).
4. Seeding: on selection change (and retry frames until the code reads), for
   each side: `store.row_seed(side, &code)` → `set_value_silent` both rows.
   Publish the code into a shared `CURRENT_CODE` (Mutex<Option<String>>)
   consumed by the on_change handlers. Clear it when leaving scene 25 or on
   dead selection.
5. on_change handlers (plain fn pointers): ignore until rows-ready + a
   current code exists (registration-prime guard). Parent 1 → `set_entry`
   with the child row's current value (`custom_options::get_value`); parent
   0 → `clear_entry`; child change → `set_entry` only when the parent is 1.
   Every store mutation also `bootstrap::queue_csv_upsert(code, side,
   value_or_None)`.
6. All hook-path code panic-free; store lock never held across
   custom_options calls (read values first, then lock).
7. Harness stays green; `cargo check` clean; release build clean.

## Acceptance Criteria (cabinet, deploy #2)
1. Rows render with localized labels; child hides/shows with the parent
   same-frame; **negative values render** ("-7", "-100").
2. Wheel navigation re-seeds both rows (pre-seeded songs show ON + value;
   unset songs show OFF).
3. Edits persist: change a value, scroll away and back (re-seeded), reboot
   (CSV carries it), and the CSV cell matches.
4. Versus: sides independent.
5. No WARNs on the happy path.
