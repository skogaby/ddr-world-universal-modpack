# Task: Source rows, per-source model rows, mirror observer, preview wiring

## Description
Rewrite `src/mods/background_dancers/options.rs` around `options_logic`: register the DANCER SOURCE /
STAGE SOURCE rows and one model row per source with `ShowWhen::Equals`, texture aliases, per-row
labels and load clamps, request readers for the pick path, `row_choice_key` for the preview, and the
versus mirror through a value-changed observer. Wire `preview/mod.rs` to the new readers.

## Background
Today's `options.rs` registers two flat rows with per-side atomics and `on_change` fns. The design
replaces the atomics with `custom_options::get_value` reads, moves the stage mirror to an observer
(the `on_change` fn cannot know its row id), and keeps a `Duplicate` re-enable path.

## Technical Requirements
1. `static ROWS: OnceLock<Vec<RowInfo>>` and `static CATALOG: OnceLock<Catalog>`, built once at the first
   `register`; ids leaked once (`Box::leak`) into a parallel `Vec<&'static str>`.
2. Registration per §4.5: `generate_chrome(base)` per kind; source row (`step_coarse(1)`, `Local`,
   `persist_transform(identity, clamp_load)`, `in_game_only`, `display_name` / `description`,
   `preview_texture_like(base)`) when `has_custom`; model rows (`step_coarse(5)`, aliases for label +
   preview, `ShowWhen::Equals { source_row, i + 1 }` or `Always` without a source row). `Duplicate` ⇒
   `set_option_available(id, true)`; other errors ⇒ WARN + `ROWS_LIVE` false.
3. `versus_mirror::register(&stage_ids)`; one value-changed observer (subscribed once) that calls
   `versus_mirror::mirror_edit(id, side, value)` for registered stage rows while `rows_live()`.
4. `label(id, value)` and `clamp_load(id, value)` as `fn` pointers over `options_logic`.
5. Readers: `kind_for_option`, `rows_live`, `set_available` (all rows + stage ids), `Request`
   (re-export), `dancer_request(side)`, `stage_request(side)`, `row_choice_key(id, side)`; keep
   `OPT_DANCER` / `OPT_STAGE`.
6. `preview/mod.rs::on_preview_request`: `kind_for_option(id)` + `row_choice_key(id, side)`.
7. Rows INFO lists the registered rows and counts. The display-string lint in
   `validate_custom_options.sh` requires `.display_name(` / `.description(` near every
   `register_option(` call — satisfy it.
8. No panics on any path; every `get_value` miss degrades to RANDOM/`Any`.

## Acceptance Criteria

1. **Rows registered**
   - Given a catalog with custom dancer sources and stock-only stages
   - When the mod enables on the cabinet
   - Then the log shows DANCER SOURCE + one model row per dancer source, and BACKGROUND STAGE alone

2. **Visibility and labels** (cabinet)
   - Given the options modal
   - When the dancer source steps RANDOM → STOCK → CUSTOM → …
   - Then the visible model row swaps on the same frame, RANDOM hides it, and labels read correctly

3. **Mirror** (cabinet, versus)
   - Given both sides entered at song select
   - When P1 edits the stage source or a stage model row
   - Then P2's rows follow (and vice versa); dancer rows stay independent

4. **Preview** (cabinet)
   - Given a model row focused ⇒ its value previews; a source row focused ⇒ the effective pick or the badge

5. **Gate**
   - `cargo check --target x86_64-pc-windows-msvc` clean; `validate_custom_options.sh` lint passes
