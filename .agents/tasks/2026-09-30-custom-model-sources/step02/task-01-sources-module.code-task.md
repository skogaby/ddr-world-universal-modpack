# Task: `sources.rs` — pure source identity and directory roles

## Description
Create the dependency-free module `src/mods/background_dancers/sources.rs` holding everything about
custom-content SOURCES that needs no filesystem: the implicit source, slugging, source resolution,
the planned-entry type the catalog groups, directory-role classification from names, and the
option-row id rules. Mount it in the host harness.

## Background
The design adds a source level to `data_mods/custom_models/{dancers,stages}`. A source is identified
by the slug of its folder name and labelled through the existing folder-label rule; legacy
placements land in the implicit source `CUSTOM`. Later tasks (the planner, the scanner, the catalog,
the option rows) all consume these primitives, so they live in one pure file the
`scripts/validate_background_dancers.sh` harness can test.

## Technical Requirements
1. `IMPLICIT_SOURCE = "Custom"`, `RESERVED_SLUGS = &["source"]`, `MAX_SLUG_BYTES = 32`.
2. `SourceRef { slug, label }`; `CustomEntry { key, label, source: SourceRef }`.
3. `slug(name) -> Option<String>`: ASCII-lowercase, every run of `[^a-z0-9]` → one `_`, trim `_`,
   cap at `MAX_SLUG_BYTES` (then re-trim), `None` when empty.
4. `resolve_source(folder: Option<&str>) -> Result<SourceRef, String>`: `None` ⇒ the implicit
   source; `Some(f)` ⇒ slug + `label_from_folder(f)` fitted to 15 bytes; reserved slug or empty
   slug/label ⇒ `Err(reason)` (human-readable, used verbatim in a WARN).
5. `DirRole { Model, Source, Friendly, Ignored }`; `dir_role(is_model_folder, has_friendly_child,
   has_model_content)` — `Model` wins, then `Source`, then `Friendly`, else `Ignored`.
6. `has_model_content(files, dirs) -> bool`: any dir classifies as a body/part/stage/gold-stage model
   folder, or any file as a body/part/stage arc (`classify_arc_name`).
7. `source_row_id(base) -> String` (`{base}_source`); `model_row_id(base, slug: Option<&str>)`
   (`base` for `None` = STOCK, else `{base}_{slug}`).
8. `mod.rs` declares `pub mod sources;`; the harness lists it in `MODULE_NAMES` / `MODULE_PATHS`.
   The file uses only `std` and `super::custom_content` (mutual sibling imports are fine).

## Acceptance Criteria

1. **Slugs**
   - Given `"DDR STRIKE"`, `"J.C."`, `"UMX2"`, `"  Custom  "`, `"___"`, and a 40-letter name
   - When `slug` runs
   - Then it returns `ddr_strike`, `j_c`, `umx2`, `custom`, `None`, and a 32-byte-or-shorter slug with no trailing `_`

2. **Source resolution**
   - Given `None`, `Some("Custom")`, `Some("CUSTOM ")`, `Some("Source")`, `Some("♥♥")`
   - When `resolve_source` runs
   - Then the first three yield `SourceRef { slug: "custom", label: "CUSTOM" }`, and the last two are `Err` with a reason naming the folder

3. **Directory roles**
   - Given every combination of the three booleans
   - When `dir_role` runs
   - Then `Model` when `is_model_folder`, else `Source` when `has_friendly_child`, else `Friendly` when `has_model_content`, else `Ignored`

4. **Model content**
   - Given listings with a `pl_x/` dir, a `mapset_y/` dir, a `pl_x.arc`, a `pl_x_head00.arc`, a `mapset_y_g/` dir, only `readme.txt`, nothing
   - When `has_model_content` runs
   - Then the first five are `true` and the last two `false`

5. **Row ids and harness**
   - Given `model_row_id("background_dancer", None)` and `Some("ddr_strike")`, `source_row_id("background_stage")`
   - When evaluated
   - Then `background_dancer`, `background_dancer_ddr_strike`, `background_stage_source`; and `./scripts/validate_background_dancers.sh` passes with the module mounted
