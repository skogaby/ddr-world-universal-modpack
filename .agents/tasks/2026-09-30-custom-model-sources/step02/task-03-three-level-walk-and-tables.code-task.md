# Task: Three-level walk, tables, and the flat-catalog adapter

## Description
Teach the impure scanner (`src/mods/background_dancers/custom_scan.rs`) to recognise source folders
one level above the friendly folders, thread the sourced entries into `lifecycle::Tables`, log the
per-source breakdown, and keep today's flat option rows working through a temporary adapter in
`mod.rs` until Step 3 lands the grouped catalog.

## Background
`walk_kind_root` walks exactly two levels (`<kind>/<model>`, `<kind>/<Friendly>/<model>`); a source
level is invisible. `lifecycle::init_tables` stores `custom_labels: Vec<(key, label)>` and
`mod.rs::enable` feeds them to `catalog::build_catalog_with_custom(&stages, &dancers, &custom)`.

## Technical Requirements
1. `walk_kind_root(root)`: root files + model folders ⇒ `PackDir { folder: None, source: None }`.
   For each non-model dir `d`: list it; for each non-model subdir `f`, list once more and compute
   `has_model_content`; `dir_role(false, any friendly child, has_model_content(d))`:
   `Source` ⇒ `PackDir { folder: None, source: Some(d) }` for `d`'s own files/model folders plus one
   `PackDir { folder: Some(f), source: Some(d) }` per friendly `f`; `Friendly` ⇒
   `PackDir { folder: Some(d), source: None }`; `Ignored` ⇒ nothing. `read_pack_dir` takes `source`.
2. The "custom content -- N dancer(s) + M stage(s)" INFO gains a per-source breakdown
   (`… in K source(s): DDR STRIKE 45, CUSTOM 5`), derived from `plan.entries`.
3. `lifecycle::Tables.custom: Vec<CustomEntry>` (replaces `custom_labels`);
   `custom_entries_snapshot()` (replaces `custom_labels_snapshot()`); the "tables ready" INFO counts
   distinct sources.
4. `mod.rs::enable`: TEMPORARY adapter — `entries.iter().map(|e| (e.key.clone(), e.label.clone()))`
   into today's `build_catalog_with_custom` so the flat rows are unchanged (a `// Step 3 replaces`
   comment).
5. Engine-facing code: `cargo check --target x86_64-pc-windows-msvc` + `./build.sh` clean; no panics on
   the enable path.

## Acceptance Criteria

1. **Source folder discovered**
   - Given `data_mods/custom_models/dancers/Test Source/Some Dancer/pl_<key>/…`
   - When the game boots with `custom_content` on
   - Then the boot log reads `custom content -- … in 2 source(s): CUSTOM 115, TEST SOURCE 1`, the
     dancer appears in today's flat BACKGROUND DANCER row, and the untouched 115 folders log no new WARN

2. **Legacy layout unchanged**
   - Given only today's two-level folders
   - When the game boots
   - Then every dancer/stage is discovered as before (same mounts, same labels) under `CUSTOM`

3. **Junk subdirectory ignored**
   - Given `dancers/Kasane Teto/textures_src/` (no models inside)
   - When the scanner runs
   - Then `Kasane Teto` stays a friendly folder (no source promotion)

4. **Readiness gate**
   - Given the change
   - When `cargo check --target x86_64-pc-windows-msvc`, `./build.sh`, and both harnesses run
   - Then all are clean/green
