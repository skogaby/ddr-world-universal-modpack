# Task: Per-element choices and source pools

## Description
Generalise the pick resolution in `src/mods/background_dancers/selection.rs` so every element (the
stage, each dancer) is either an explicit key or a random draw from an explicit pool, add the
within-source pool builders, add the `source` provenance tag, and adapt `lifecycle::option_pick` to
the new signature with no behaviour change.

## Background
`resolve_choice(rng, stages, dancers, stage_key: Option<&str>, dancer_keys: &[Option<&str>])` draws a
`None` stage from the slice it is given and a `None` dancer from the whole dancer table. Within-source
RANDOM needs per-element pools; the stage pool must honour the screen rule with a fallback to the
whole source.

## Technical Requirements
1. `StageChoice<'a> { Key(&'a str), Random(&'a [StageCandidate]) }`,
   `DancerChoice<'a> { Key(&'a str), Random(&'a [DancerCandidate]) }`.
2. `resolve_choice(rng, stages, dancers, stage: StageChoice, dancer_choices: &[DancerChoice])`:
   `Key` looked up in the full tables (stage: uniform over that key's rows; dancer: that candidate);
   `Random(pool)`: `pick_stage(pool)` / one uniform draw over `pool`; unknown key or empty pool ⇒
   `None`; empty `dancer_choices` ⇒ `None`. With `Random(global)` everywhere the draw sequence equals
   `pick_stage` then `pick_dancers` under the same seed.
3. `source_stage_pool(stages, keys, keep) -> StagePool`: the rows whose key is in `keys`, run through
   `random_stage_pool` (so `All` / `Filtered` / `NoneLeft` are relative to the source; `rows()` of
   `NoneLeft` must yield the source's rows, not the whole table — return the subset alongside or make
   the variant carry it).
4. `source_dancer_pool(dancers, keys) -> Vec<DancerCandidate>` in table order.
5. `PickSource::Source` with `tag() == "source"`; `pick.rs` summary renders it.
6. `lifecycle.rs::option_pick`: today's `Option<String>` choices map to `Key` / `Random(random_stages)`
   / `Random(&t.dancers)`; no other change.

## Acceptance Criteria

1. **Seed-identical random path**
   - Given the stock tables and a seed
   - When `resolve_choice` runs with `Random(all stages)` and `[Random(all dancers); n]`
   - Then the result equals `pick_stage` followed by `pick_dancers(n)` under the same seed

2. **Pools are respected**
   - Given a two-stage pool and a two-dancer pool
   - When resolved many times with different seeds
   - Then every stage and dancer drawn is from its pool; a `Key` outside the tables ⇒ `None`; an empty pool ⇒ `None`

3. **Source stage pool**
   - Given stages `a` (screens), `b` (no screens), `c` (screens) and keys `[a, b]`
   - When `source_stage_pool` runs with `keep = has screens`
   - Then the pool is `Filtered { rows: [a] }`; with `keep = no screens` ⇒ `[b]`; with keys `[c]` and `keep = no screens` ⇒ `NoneLeft` whose rows are `[c]` (not the table); with `keep = |_| true` ⇒ `All` over `[a, b]`

4. **Dancer pool**
   - Given dancers in table order and keys `[third, first]`
   - When `source_dancer_pool` runs
   - Then the pool is `[first, third]` (table order) and an unknown key is ignored

5. **Provenance**
   - Given a `Pick` with `PickSource::Source` on a dancer
   - When `summary()` renders
   - Then the element carries `{source}`

6. **Gate**
   - Given the change
   - When the harness and `cargo check --target x86_64-pc-windows-msvc` run
   - Then both are clean
