# Task: Real Speed × Effective Rate

## Description

At a committed non-identity song rate, Real Speed's normalized speed
multiplier must derive from `Core BPM × effective_rate` REGARDLESS of the
Real Speed Fix toggle; at 100 % the toggle keeps its stock-vs-fix meaning
exactly as today. Design req 33 (a KEEPER from the approved 2026-08-05
design, unchanged by the streaming redesign — this task lands its
implementation).

## Background

Real Speed normalizes arrow speed against the song's BPM so a chosen
"real speed" reads the same across songs. A rate-committed song's audible
tempo is `Core BPM × effective_rate` — deriving from the stock BPM would
make the same real-speed setting feel different at 50 % vs 100 %. The
committed effective rate is read from
`services::song_rate::clock_patch::snapshot()` (seqlock, lock-free;
`committed` + `effective_rate: RateRatio`); non-identity commits land
before gameplay's first frame (loader thread at latest — the same
guarantee the assist-tick gate relies on). The integration point is
`src/mods/real_speed_fix.rs` (design §Dependent features names it); the
multiplier derivation site and its toggle branch are located there —
find the BPM term's consumer and thread the rate factor through with
exact arithmetic (the `RateRatio` fields are integers; prefer
integer/deliberate-rounding math over float drift where the existing code
allows).
