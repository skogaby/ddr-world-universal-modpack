# Task: PUS CSV Rate Columns

## Description

Power User Statistics' CSV export gains requested-rate and effective-rate
columns; ms-error values stay content-domain (labeled as chart
milliseconds, unchanged). Design req 34 (a KEEPER from the approved
2026-08-05 design — this task lands its implementation).

## Background

PUS exports per-player step data to CSV at song end
(`src/mods/power_user_statistics/csv_export.rs`; the per-song identity
snapshot flows through `data_feed.rs`). A rate-committed song's error data
is only interpretable with the rate on record. Two new columns:
the REQUESTED percent (the option value that armed, e.g. 50) and the
EFFECTIVE rate (the committed exact ratio — emit as a fraction or
sufficiently precise decimal; pick what the existing CSV conventions
favor and record the choice). Identity/uncommitted songs emit the
identity values (100 / 1.0) so the schema stays uniform. Source of truth:
`services::song_rate::clock_patch::snapshot()` (`committed`,
`requested_percent`, `effective_rate`), latched at the same per-song
boundary the exporter already uses for song identity — never read at
write time from a stale generation (the snapshot resets to identity at
gameplay exit; latch alongside the existing song-identity snapshot).
