# Task: Enhanced config schema, module split and pure model

## Description
Split `src/mods/series_expansion.rs` into a module directory, make the `series_expansion` config
accept `custom_series_enhanced` safely, add the pure `enhanced/model.rs` that validates the block
into an `EnhancedPlan`, a host harness for it, and the `init` mode selection that logs the parsed
plan and (until the engine lands) falls back to legacy.

## Background
Enhanced mode is keyed on `series_expansion.custom_series_enhanced` (an object with `num_columns`
and `filters[]`). Today `SeriesConfig.custom_series` is required and any type error in the section
fails the whole `mod-config.json` parse, dropping every mod to defaults.

## Technical Requirements
1. `git mv`-equivalent move of `src/mods/series_expansion.rs` to `src/mods/series_expansion/mod.rs`
   with no content change, then add `enhanced/mod.rs` and `enhanced/model.rs`.
2. `SeriesConfig`: `custom_series` `#[serde(default)]`; `custom_series_enhanced:
   Option<serde_json::Value>` `#[serde(default)]`.
3. `enhanced/model.rs` (`crate::`-free): `Group`, `Cell`, `EnhancedPlan`, `TableRow`, `parse`,
   `members`, `table_rows`, `custom_names`, `label_key`, `texture_name`, `label_stems`,
   `source_candidates`, `canvas_width`, `summary`, constants `MAX_CELLS`, `MAX_GRID_ROWS`.
4. `init`: enhanced key is an object ⇒ `parse`, log each warning (WARN) and the plan summary (INFO),
   then fall back per R20 with one INFO (engine not present yet); not an object ⇒ WARN + fallback;
   legacy path otherwise unchanged. The mod registers when legacy `custom_series` is non-empty,
   exactly as today.
5. `scripts/validate_series_expansion.sh` running the model's `#[cfg(test)]` suite on the host,
   plus a fixture: the canonical block from `scripts/gen_series_labels.py --emit-config` parses with
   zero warnings.

## Acceptance Criteria

1. **Pure move**
   - Given the moved module
   - When the crate builds
   - Then behaviour is unchanged and `mods::series_expansion` paths still resolve.
2. **Lenient parse**
   - Given a config with only `custom_series_enhanced` (no `custom_series`) or a malformed cell
   - When `config::init` runs
   - Then `mod-config.json` parses and other sections load.
3. **Validation**
   - Given the §2.1 rules
   - When `parse` sees invalid cells, bad `num_columns`, too many cells, 16 bounds, groups
   - Then it skips / defaults / normalises / caps exactly as specified and returns one warning per issue.
4. **Derived data**
   - Given a plan
   - When `table_rows`, `members`, `custom_names`, `label_key`, `label_stems`, `source_candidates` run
   - Then they match §4.3 / §5.2 (N+1 rows, padding to 10 for N < 9, `end + 1`, inert rows).
5. **Canonical fixture**
   - Given the generator's canonical block
   - When parsed
   - Then 20 cells, 3 columns, GOLD 4 / WHITE 3 / CLASSIC 13, zero warnings.
6. **Fallback**
   - Given the enhanced block on a cabinet
   - When the mod inits
   - Then the plan summary and the fallback INFO are logged and the menu is legacy/stock.
