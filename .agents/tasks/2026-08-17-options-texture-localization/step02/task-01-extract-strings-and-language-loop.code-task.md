# Task: Extract strings and add the language loop

## Description

Restructure `scripts/gen_option_labels.py` around a language loop and a
data-only string module `scripts/option_strings.py` (English content only —
translations land in a later step), without changing any output pixel.

## Background

- `scripts/gen_option_labels.py` currently holds all display strings inline
  (LABELS/HEADER_LABELS/RIBBONS/PREVIEWS lists) and hardcodes `OUT_DIR` to
  the eng tex dir. It renders four families (labels 176x16, headers 352x16,
  ribbons 132x24, preview panels 368x172) with module-level fonts.
- The design's data model adds `art`/`art_pos` fields to preview specs and a
  `TEMPLATES` table — declared now (empty/None), populated in the next step.
- Gate: post-refactor `--lang en` output must be byte-identical to
  pre-refactor output (fresh run vs fresh run, same environment).

## Technical Requirements

1. New `scripts/option_strings.py`: data-only (no Pillow imports). Per-family
   structures keyed by id with per-language text dicts (`{"en": ...}` now);
   `PreviewSpec` gains `art`/`art_pos` (None for all current entries);
   `TEMPLATES` declared empty; an `AVAILABLE_LANGS` list (currently
   `["en"]`) the generator consults.
2. `gen_option_labels.py`: `LANGS` table mapping string-key → ifs code
   (`en→eng`, `ja→jpn`, `ko→kor`); `out_dir(ifs_code)`; per-language
   `FontSet` (en entry only); render functions take fonts as parameters;
   `--lang` CLI flag restricting generation (default: all AVAILABLE_LANGS).
3. Zero layout-constant changes; zero rendering-logic changes.
4. Byte-identical gate: fresh pre-refactor output == fresh post-refactor
   output for every generated file (compare via temp-dir runs; shipped files
   in `data_mods` are NOT the baseline — they may predate environment drift).

## Dependencies

- Step 1 (complete): jpn/kor dirs exist but are NOT written by this step.

## Implementation Approach

1. Snapshot: run the current script with OUT_DIR redirected to a temp dir.
2. Refactor per requirements; run `--lang en` to a second temp dir; byte-compare.
3. Final run writes the eng data_mods dir as before.

## Acceptance Criteria

1. **Byte-identical English regeneration**
   - Given the pre-refactor script's fresh output snapshot
   - When the refactored generator runs with `--lang en`
   - Then every generated file is byte-identical to the snapshot

2. **Data/logic separation**
   - Given `option_strings.py`
   - When imported
   - Then it imports without Pillow and contains no rendering code

3. **Language restriction flag**
   - Given `--lang en`
   - When the generator runs
   - Then only the eng dir is written; jpn/kor dirs are untouched
