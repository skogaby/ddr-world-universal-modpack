# Task: training-mode mod skeleton + Step-1 cabinet demo

## Description
Create the minimal `training-mode` mod: mod id, config gating, the
scene-26 eligibility latch, and the training-arm request — plus a
temporary dev knob (`DDR_TRAINING_TEST_SHIFT_MS`, removed in Step 2) that
applies a bind-time content mapping so the Step-1 demo is observable on
the cabinet.

## Background
This is the thin real consumer that makes Step 1 demonstrable end-to-end:
with the mod enabled, every eligible song (any rate, including 100 %) gets
a binding armed, and audio remains byte-identical at zero mapping. The
mod's full row/gesture/HUD surface arrives in Steps 2–6; this skeleton
establishes the module layout (`src/mods/training_mode/`), registration,
and the arm policy: arm whenever the mod is enabled and the session is
eligible — arming alone is not an alteration and never taints (design
§4.2).

## Technical Requirements
1. `src/mods/training_mode/mod.rs`: Mod trait impl, id `training-mode`,
   default enabled, registered in `src/lib.rs` in a sensible init position
   (after song_rate/song_reset services are up).
2. On enable + scene-26 eligibility (mirror song_rate's ordinary
   solo/doubles predicate): call Task 02's `set_training_arm(true)`;
   cleared on disable and on ineligible sessions.
3. Temporary demo knob: env `DDR_TRAINING_TEST_SHIFT_MS` (read once at
   arm; absent ⇒ no mapping) applies
   `set_content_mapping(B(shift_ms), B(2500))` at bind time via Task 02's
   plumbing. Clearly marked `// TEMPORARY (Step 1 demo — removed in Step 2)`.
   This is a dev knob, not a dry-run mode: the song genuinely plays
   shifted.
4. Mod disabled ⇒ zero footprint (no arm requests; ordinary 100 % plays
   remain literally stock).
5. Logging per repo convention (`log_info!` on enable/arm decisions; one
   WARN on degraded paths only).

## Acceptance Criteria
1. **Zero-footprint when disabled**
   - Given `mods["training-mode"] = false`
   - When any song plays at 100 %
   - Then no arm request is made and no binding exists (logs confirm Identity)
2. **Armed and byte-identical when enabled**
   - Given the mod enabled and an eligible 100 % song (no test knob)
   - When the song plays on the cabinet
   - Then logs show the identity binding armed and the song is audibly/functionally normal (preview normal, gameplay normal, score submits — no taint)
3. **Demo: shifted start**
   - Given `DDR_TRAINING_TEST_SHIFT_MS=60000`
   - When an eligible 100 % song starts
   - Then the first audible content is the song at ~1:00 after a 2.5 s silent lead (the true beginning is never heard), and the clock/notes are NOT yet adjusted (that is Step 2/3 work — audio-only proof is the Step-1 demo)
4. **Ineligible fail-closed**
   - Given a versus or course session with the mod enabled
   - When songs play
   - Then no arm requests fire and behavior is stock
