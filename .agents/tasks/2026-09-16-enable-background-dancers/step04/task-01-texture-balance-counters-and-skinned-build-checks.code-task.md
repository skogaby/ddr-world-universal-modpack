# Task: Texture create/release balance counters and the skinned-build checks

## Description
Make the engine-texture lifetime observable and the skinned branch of `render_item::build` self-checking
before the first skinned model is handed to the engine: count every `texture::create_dynamic` /
`texture::release` (per process, atomics) so a per-song log line proves `created == released` across
songs (no texture-registry growth), and assert the skinned item's shape at build (two non-zero, distinct
handles wired at `+0x78/+0x7C`, mode `0xF`, `ModelParameters {bones, 1, 0, 0}`, bone array = bind copy of
`bones × 0x40` bytes) with the counts reported in the build INFO.

## Background
The skinned pipeline (design §5.2, RE §2.3/§2.4): the bone-texture upload (`FUN_180261780`) locks
`item+0x78+parity*4` once per frame under the frame stamp and writes `invBind[i]·bone[i]` as 3 float4
rows per bone into a `bone_count × 4` `A32B32G32R32F` (0x74) texture created with usage `0x2001`; the
draw binds that texture on stage 3 when the GPU draw record's flags carry `0x100`. Both handles are
released by our node dtor through `render_item::free_raw` → `texture::release` (RE §1.4: the World
release `FUN_18024a170` decrements the registry slot and frees on 0; `-1` = stale). A leak would grow the
registry every song; a double release would free someone else's texture — the counters make either
visible in one line.

## Technical Requirements
1. `texture.rs`: `static CREATED: AtomicU32`, `static RELEASED: AtomicU32`, `static RELEASE_STALE: AtomicU32` (release returned `-1`); `create_dynamic` increments `CREATED` on success; `release` increments `RELEASED` (and `RELEASE_STALE` when the engine returns `-1`); `pub fn balance() -> TextureBalance { created, released, stale }` (a small `Copy` struct with `Display` = `created=N released=M stale=K`).
2. `render_item::build`, skinned branch: after creating both handles assert `a != 0 && b != 0 && a != b`; on violation release both, free the block, `Err(BuildError::BoneTexture)`. `RenderItem::bone_textures()` already exposes them — extend the caller's INFO (spike) with `bone_tex=0x…/0x…`.
3. Host test (`render_item_layout.rs`): none new needed beyond the existing consts; add a `skinned_block_size_covers_bone_textures` test asserting `ITEM_BONE_TEX + 8 <= ITEM_BONES` (the two handles never overlap the next field) and that `trailing_layout` for `{2, 33, 2, 2}` (pl_emi00) gives `bones_off + 33*0x40 <= materials_off`.
4. Rust Quality Rules: atomics only (no locks in `release`, which runs from the node dtor on a job thread).
