# Task: Theme policy, trigger rows and naming

## Description
Teach DDR SELECTION's pure layers about the three themes (skins 6 / 7 / 8 = DDR A / DDR A3 (White) /
DDR A3 (Gold)): the option row's values 7..=9, the theme table, the theme package-naming rule, and
the policy rows for the bases plan Step 1 swaps (the whole-package swaps, the stage frame and the
A3 song-info panel). No engine code in this task.

## Background
Design §4.1, §4.3, §5.1–§5.3. A theme's packages are A3's skin-0 art by explicit `_vN` name
(`<arc_base>0000<suffix>`, `_v0` for game over / danger / pacemaker / option icons,
`dance_message<suffix>`); World's probe reaches them only through its bare rung, so no row may ever
produce a bare `…0000`. A theme row for a base must land only together with its adapter's range
widening (plan rule), so this task adds theme rows for `dance_judge`, `dance_fast_slow`,
`dance_fullcombo`, `dance_game_over`, `dance_danger`, `dance_score_compare`, `dance_stage`,
`dance_song_info` only; gauge / combo / score / option / message stay Stock for 6..=8. AUTO is not
changed in this step (themes are explicit-only until plan Step 3).

## Technical Requirements
1. `trigger.rs`: `ROW_MAX = 9`; labels 7 `DDR A`, 8 `DDR A3 (White)`, 9 `DDR A3 (Gold)` (≤ 15 bytes);
   `clamp_row` to 0..=9; the dev knob accepted for `1..=8`; explicit value v ≥ 2 → skin v − 1;
   `auto_skin` unchanged.
2. `policy.rs`: `SKIN_MAX = 8`, `ERA_MAX = 5`; `Theme { skin, suffix }` table (6 `_v0`, 7 `_v2`,
   8 `_v1`); `is_era`, `is_theme`, `theme`; `tex_number` (eras → skin, themes → 0); `engine_skin`
   (eras → skin, themes → 0); `skin_name` = the row labels (`1stMIX-5thMIX` … `2013-2014`,
   `DDR A`, `DDR A3 (White)`, `DDR A3 (Gold)`).
3. `Entry.skins: u16`; `fixed_arc` replaced by `naming: Naming` (`Suffixed`, `Fixed(&str)`,
   `Theme(ThemeArc)`), `ThemeArc::{Own, V0, Message}`; `Decision::Legacy { arc_base, skin, naming }`;
   one `package_name(arc_base, skin, naming) -> String` (NUL-terminated) for every name.
4. Theme rows (skins 6..=8) for the Step 1 bases with the adapters of design §4.3.
5. `marker_keys::root_name(6..=8)` = `dance_common0000<suffix>`; `song_info_logic::mode_for_skin(6..=8)
   = Panel`.
6. Pure files stay `crate::`-free (harness-mounted); cross-module references use `super::`.

## Acceptance Criteria

1. **Row values**
   - Given a row value 7, 8 or 9
   - When `trigger::resolve` runs for the governing side
   - Then the skin is 6, 7 or 8 with source Explicit, and labels fit the 15-byte budget

2. **Theme package names**
   - Given skin 7 (White) and every adapter available
   - When `policy::decide` runs for `dance_judge`, `dance_game_over`, `dance_stage`, `dance_song_info`
   - Then the package names are `dance_judge0000_v2`, `dance_game_over0000_v0`,
     `dance_stage_frame0000_v2`, `dance_song_info0000_v2` with record skin 7

3. **Not yet adapted bases stay stock**
   - Given any theme skin
   - When `decide` runs for `dance_gauge`, `dance_combo`, `dance_score`, `dance_option`, `dance_message`
   - Then the decision is Stock

4. **Eras unchanged**
   - Given skins 1..=5
   - When `decide` / `package_name` run for every base
   - Then the results equal today's (existing tests pass unchanged apart from the naming type)

5. **Invariants**
   - Given the table
   - When the invariant tests run
   - Then no name ends in a bare `0000`, every theme name carries `_vN`, rows never overlap, skin 0 is
     never legacy
