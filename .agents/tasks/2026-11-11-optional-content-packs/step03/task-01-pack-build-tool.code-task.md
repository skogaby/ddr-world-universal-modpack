# Task: Pack Build Tool

## Description
Add `scripts/build_packs.py`: turn each source folder of the assets checkout into a pack
(shipped form, marker, zip) and write a catalog, plus validation of catalog files and
staging of packs into a game-folder image. Commit a synthetic fixture the updater tests
read.

## Background
Part of the optional content packs feature: the ported dancers and stages become packs a
user opts into, built from the assets repository and installed by the updater.

## Technical Requirements
1. `build`, `stage` and `check` subcommands; assets checkout located by
   `DDR_WORLD_ASSETS` or as a sibling folder.
2. Pack id, content id, marker and zip layout exactly as the design specifies; a pack's
   files equal what `pack_custom_models.run` leaves for that source.
3. One source at a time, so scratch space is one pack.
4. Fixture under `updater/tests/fixtures/packs/`, reproduced by a test.

## Acceptance Criteria

1. **Stable identity**
   - Given the same source folders
   - When they are built twice, with file timestamps changed in between
   - Then the content ids are equal, and a one-byte change gives a different id

2. **Shipped form**
   - Given a synthetic assets tree
   - When a pack is materialised
   - Then its files equal the release packer's output for that source, and the marker lists each with size and hash

3. **Zip layout**
   - Given a built pack
   - When its zip is listed
   - Then entries are in byte-sorted path order with the marker last and fixed timestamps

4. **Catalog validation**
   - Given a catalog with any one malformed field
   - When it is checked
   - Then the problem is reported and the exit code is non-zero

5. **Fixture**
   - Given the committed fixture assets
   - When they are rebuilt
   - Then content ids, markers and zip entries equal the committed output
