# Task: Move the Ported Models to the Assets Repository

## Description
Move every ported dancer and stage source out of the code repository's
`data_mods/custom_models/` into the assets repository checkout, prove the move is
lossless, and point the tools that write or read ported models at the new location. The
`Custom` sources stay where they are.

## Background
The ported models are 3.5 GB and become optional packs built from a separate repository
(`skogaby/ddr-world-universal-modpack-assets`). Later plan steps build packs from that
checkout, so the move comes first. Removing the models from the code repository's
history is a later, maintainer-run step; this task only changes the working trees.

## Technical Requirements
1. Every source folder under `data_mods/custom_models/dancers/` and `…/stages/` except
   `Custom` is placed in the assets checkout as `dancers/<Source>/` and
   `stages/<Source>/`. `.DS_Store` files are not carried over.
2. Before anything is removed from the code checkout, every moved file's git blob id is
   shown equal to the committed one, and the two file sets are shown identical.
3. The assets checkout gains `.gitattributes` (`* -text`) and a `README.md`.
4. The code repository's `.gitignore` ignores every folder under
   `data_mods/custom_models/dancers/` and `…/stages/` except `Custom/`.
5. The Blender port examples resolve the assets checkout as a sibling folder or through
   `DDR_WORLD_ASSETS`, with no absolute fallback, wherever they defaulted to or read from
   a ported source. References to `Custom` models stay in the code repository.
6. The add-on's documentation states where ported sources now live.
7. Nothing is committed or pushed in either repository.

## Dependencies
- The assets repository cloned beside the code checkout.

## Implementation Approach
1. Copy, verify by blob id, then delete the originals from the working tree (they stay
   recoverable from git).
2. Add the ignore rules and check them with a probe folder.
3. Add a Blender-free lookup module to the port examples and use it for the defaults.

## Acceptance Criteria

1. **Lossless move**
   - Given the committed ported sources
   - When they are copied to the assets checkout
   - Then the sorted list of (blob id, path) of the copy equals that of the committed
     files, entry for entry

2. **Code checkout holds only Custom**
   - Given the move is verified
   - When the originals are removed
   - Then `data_mods/custom_models/dancers/` and `…/stages/` each contain only `Custom`,
     and git reports the removed files as deletions and nothing else under that path

3. **Stray sources stay out of git**
   - Given a new folder placed under `data_mods/custom_models/dancers/`
   - When git evaluates it
   - Then it is ignored, while files under `Custom/` are not

4. **Tools find the assets checkout**
   - Given no `DDR_WORLD_ASSETS`
   - When the lookup runs
   - Then it returns the sibling checkout; with the variable set it returns that path

5. **Nothing else broke**
   - Given the moved tree
   - When `scripts/validate_background_dancers.sh` and
     `scripts/build_release_archive.sh` run
   - Then both succeed, and the release zip's `custom_models` holds only the `Custom`
     sources
