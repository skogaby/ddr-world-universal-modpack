# Task: Pack Transactions

## Description
Install, replace and remove one pack transactionally: pack-mode archive extraction, pack
plans, a transaction descriptor for `apply::execute` with per-transaction backups, and
`--packs-install` / `--packs-dir`.

## Background
Part of the optional content packs feature: the ported dancers and stages become packs a
user opts into, built from the assets repository and installed by the updater.

## Technical Requirements
1. A pack archive may write only under its root and its marker, and must match its
   marker and the catalog.
2. The marker is written or pruned last.
3. Backups per transaction; the backup folder is emptied once per run; a committed pack
   transaction keeps only modified files in its backup.
4. A journal without `backup_subdir` recovers from the backup folder itself.

## Acceptance Criteria

1. **Install and remove**
   - Given a pack zip in `--packs-dir`
   - When it is installed and later deselected
   - Then its files appear, then only its recorded unmodified files go

2. **User files**
   - Given files the user added, inside and outside a pack's folder
   - When packs are installed, updated and removed
   - Then those files are byte-identical afterwards

3. **Rollback**
   - Given an injected failure in a pack transaction
   - When it runs
   - Then the folder is as before and the base is untouched; a failed rollback exits 1; a crash is recovered on the next run

4. **Base backup**
   - Given a base update followed by a pack install in one run
   - When both complete
   - Then `backup/base/` still holds the base originals
