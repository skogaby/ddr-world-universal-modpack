# Task: `services/wheel_cards` — card-bound events (promoted detour)

## Description
Move the song-select wheel-card refresh detour out of `s_marvelous/lamp_badge.rs` into a
service that owns it and publishes "card N was bound to song M" events, so both the lamp
badge and the StepMania prefetch scheduler can subscribe (one detour per target).

## Background
`lamp_badge::install` detours `selectmusic_card_refresh` (signature) and, post-original,
reads the card's own song holder at `this+0x148` (stable on every supported build), resolving
the mcode via `selectmusic_highlight::mcode_of_holder`. The wheel is a 3-per-row grid; a
vertical scroll binds one new row = three refreshes. The design (§4.11, D21) uses those
refreshes as the "song became visible" signal for preview/jacket prefetch.

## Technical Requirements
1. `src/services/wheel_cards.rs`: `init(signatures) -> bool` installs the ONE `selectmusic_card_refresh` detour (fail-open), `is_available()`, `on_card_bound(fn(CardBound))` subscriptions (`CardBound { card: *mut u8, holder: *const u8, mcode: i32 }`), fired post-original, panic-contained, only in scene 25, null/readability-checked exactly as `after_refresh` does today. Subscribers must be cheap (frame thread).
2. `lamp_badge` keeps its difficulty-panel and record-panel detours but subscribes to `wheel_cards` for the card (its gating `ACTIVE && TEXTURE_READY` moves into its callback). Behaviour identical.
3. `lib.rs`: init the service with the other song-select services (after `selectmusic_highlight`, before mods). Update `.agents/summary/interfaces.md`'s hook-ownership row for `selectmusic_card_refresh` (one line).

2. **Lamp unchanged** — Given S-MFC lamps, then cards still show them (cabinet, Step 8 demo).
