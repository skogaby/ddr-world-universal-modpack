# Task: Cabinet run — E1 / E3 / E5 observations

## Description
Boot the cabinet with the Step 1 fixtures and record whether the hand-built injected song
appears, previews, plays and reaches results — online and offline — plus the E3 arena
headroom counts and the E5 missing-art behaviour.

## Background
This is the gate for the whole feature. The DLL under test is the current build with no
StepMania code; only the `_spike_sm` overlay mod folder is new. Online = the cabinet's
normal dev-server connection with `musicdata_load` succeeding; offline = server unreachable
from boot. `scripts/game_nav/` can drive the CrossOver cabinet to song select and start a
song; screenshots verify the wheel.

## Technical Requirements
1. Runs: (a) single entry online; (b) single entry offline; (c) `--clones 100`, `500`, `1000` online with the stock 1 MiB arena (`song-limit-expansion` disabled in `mod-config.json` for these boots) — count loaded songs from the log; (d) `--no-art` single entry.
2. For each run record: boot OK / `ME1529` or other service error; song on wheel (folder, VERSION 30 filter, ALL MUSIC); preview audible; play to results; log lines for the SSQ/XSB/XWB/jacket/thumbnail opens; any WARN/ERROR.
3. Record outcomes in `.agents/planning/2026-10-20-stepmania-pack-loader/progress.md` under "Deploy & test log" with the format the AGENTS.md PDD convention prescribes; strip absolute paths from pasted log lines.
4. Restore `mod-config.json` and remove the clone overlay after the runs; leave the single-entry fixture in place for Step 3.

## Dependencies
- Task 01 fixtures.
- Cabinet (CrossOver bottle) and dev server availability — maintainer-provided.

## Implementation Approach
1. Install the fixture; launch via `scripts/game_nav/launch.sh`; tail spice2x `log.txt`.
2. Navigate to song select, find the song (folder/filter), screenshot, start, play (autoplay mod acceptable), reach results.
3. Repeat offline, then the clone counts, then no-art.
4. Write up; decide go/no-go for Step 2.

## Acceptance Criteria

1. **E1 online**
   - Given the single-entry fixture and a reachable server
   - When the cabinet boots and a player enters song select
   - Then the song is listed, previews, plays and shows results with no service error

2. **E1 offline**
   - Given the same fixture with the server unreachable from boot
   - Then the song is still listed and playable

3. **E3 counts**
   - Given 100/500/1000 clones with the stock arena
   - Then the number of loaded songs per run is recorded (and whether any boot failed)

4. **E5**
   - Given no jacket/thumbnail
   - Then what the wheel card and header draw is recorded (blank, default art, or crash)

5. **Record**
   - Then `progress.md` carries all observations and a go/no-go line for Step 2
