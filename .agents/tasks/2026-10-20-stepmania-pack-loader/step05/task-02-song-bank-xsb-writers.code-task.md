# Task: `core/xact/song_bank.rs` + `core/xact/xsb.rs` — stock-shaped song banks

## Description
Add a from-scratch song wave-bank planner/writer (XWB, two entries, main-first, layout
known before any audio is encoded, blocks appendable in file order) and a song-profile
sound-bank writer (XSB with the engine-enforced CRC-16), both pure and byte-checked
against `ddr-chart-tools`.

## Background
`core/xact/xwb.rs` parses stock song banks strictly and re-serialises PARSED banks; it has
no from-scratch builder. `se_bank_synth/{xsb,xwb}.rs` build the SE profile (one entry,
in-memory bank), not the streaming song profile. `ddr-chart-tools` `src/xwb/container.rs` +
`src/job/mod.rs::build_xwb_bank` and `src/xsb/mod.rs::write` are the references: v43/header
42, flags `0x0009_0001`, alignment 2048, wave data at `0x800`, 64-byte entry names, MS-ADPCM
codec 2 with 140-byte / 128-frame blocks, seek tables. The tool writes preview FIRST; stock
banks are mostly main = 0, preview = 1 — the design mandates main-first, so XWB bytes differ
from the tool by entry order only. The XSB (326 B for a 4-char code) has cues `<code>`
(simple, category 4) and `<code>_s` (complex looping, category 3), complex-first, CRC-16
over `[0x12..]` stored at `0x08`; a mismatch is silence.

## Technical Requirements
1. `song_bank.rs`: `SongBankPlan::new(name: &str, rate: u32, frames_main: u64, frames_preview: u64) -> Result<SongBankPlan, PlanError>` computing every offset/size up front: `header_bytes() -> Vec<u8>` (header + segment table + entry metadata + seek tables + names, padded to `0x800`), `entry_data_offset(entry)`, `block_offset(entry, block_index)`, `total_len()`, `blocks(entry)`. `SongBankWriter` appends encoded 140-byte blocks for entry 0 (main) then entry 1 (preview) to any `std::io::Write + Seek`, tracking `written_watermark()`; `write_complete(sink, main_blocks, preview_blocks)` convenience. Entry names `<name>` / `<name>_s` (≤ 63 bytes).
2. `xsb.rs`: `write_song_profile(name: &str) -> Vec<u8>` ported from the tool's `xsb::write`, with the CRC-16; name rule 1–16 lowercase alnum/`_` (return `Err` otherwise).
3. Acceptance: `core::xact::xwb::parse_song_bank` accepts the produced bank strictly (`main_entry_index()==0`, `preview_entry_index()==1`, names, sizes); the per-entry bytes (metadata fields, seek table, ADPCM data) equal the tool's `build_xwb_bank` output for the same PCM; the XSB is byte-identical to the tool's for 4/5/6-char codes.
4. Encoder: in-tree `core/xact/adpcm.rs` (`encode_block`); harness leg round-trips through the tool's decoder.
5. Harness: extend `scripts/validate_stepmania.sh` with these legs (and task-01's suites); the sibling path dep is already there.

## Acceptance Criteria

1. **Strict parse** — Given a plan for 2 min @ 44.1 kHz + 15 s preview filled with encoded silence, then `parse_song_bank` accepts it and `song_rate` would bind it (names/indices per spec).
2. **Tool parity** — Given the same PCM, then our entry 0 bytes == the tool's main entry bytes and our entry 1 == its preview entry (modulo offsets).
3. **XSB golden** — Then `write_song_profile("zab12c")` equals the tool's `xsb::write("zab12c")`.
4. **Progressive contract** — Given a writer that has appended k blocks of entry 0, then `written_watermark()` == `block_offset(0, k)`.
