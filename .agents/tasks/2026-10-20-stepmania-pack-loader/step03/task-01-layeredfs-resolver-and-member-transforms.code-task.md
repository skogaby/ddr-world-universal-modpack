# Task: LayeredFS resolver registry, arc member transforms, cache-key fix

## Description
Give LayeredFS three generic capabilities with no new detours: (1) a resolver registry
consulted by `mod_paths::find_first_modfile` after the mod list; (2) arc member transforms
applied after overlays in `arc_handler::handle_arc`, which also trigger a repack when no
overlay exists; (3) a cache key that actually invalidates when the original arc changes
(AVS `lstat` size + mtime instead of a failed host `metadata`) and accepts extra fingerprint
contributions from transforms.

## Background
Run #1 logged `arc cache up to date for arc/startup.arc` on the boot that first saw a new
overlay — `CacheHasher::add(original_path)` stats an AVS path (`/data/arc/startup.arc`),
which fails on the host, so the original arc never contributes to the key. The repack still
happened because the overlay path itself was new. The StepMania feature appends `<music>`
entries to the `musicdb.xml` member via a transform and needs the repack to rerun whenever
the index changes, even with no overlay files. `handle_arc` returns early when
`scan.files.is_empty()`.

## Technical Requirements
1. `mod_paths`: `pub type Resolver = fn(&str) -> Option<String>`; `register_resolver(Resolver)`; `find_first_modfile` tries registered resolvers (in registration order) after the mod list in both normal and developer mode. Cheap: resolvers are a `Mutex<Vec<..>>` read once per call; no allocation when none is registered.
2. `arc_handler`: `pub type MemberTransform = fn(&[u8]) -> Option<Vec<u8>>`; `register_member_transform(arc_norm_path, member_path, MemberTransform)` and `register_arc_fingerprint(arc_norm_path, fn() -> Option<String>)`. In `handle_arc`: proceed to the repack when overlays OR transforms exist for the arc; after overlays are applied, run each transform on the member's current bytes (original or overlaid); a transform returning `None` leaves the member unchanged and logs once.
3. Cache key: replace `hasher.add(original_path)` with the original's AVS `lstat` (`orig_fs_lstat`, new trampoline accessor in `file_hooks` beside `orig_fs_fstat`) folded as `add_str("<path>:<size>:<mtime>")`; fold every registered fingerprint string for the arc; keep the overlay-file stamps.
4. The `startup.arc` repack output stays under `data_mods/_cache/arc/startup.arc`.

## Implementation Approach

2. Transform/fingerprint registries in `arc_handler`; adjust the early return; apply transforms after the overlay loop.
3. `orig_fs_lstat` accessor; hasher inputs.
4. `cargo check`, `cargo fmt`, `./build.sh`.

## Acceptance Criteria

1. **Resolver consulted**
   - Given a registered resolver mapping `mdb_apx/ssq/zzzz.ssq` → a cache path
   - When `find_first_modfile("mdb_apx/ssq/zzzz.ssq")` runs with no mod folder providing it
   - Then the cache path is returned; a mod folder providing the same path wins instead

2. **Transform without overlay**
   - Given a transform registered for `arc/startup.arc` / `data/gamedata/musicdb.xml` and no `startup_arc` overlay in any mod
   - When the game opens `startup.arc`
   - Then the open is redirected to a repacked cache arc whose `musicdb.xml` is the transformed member

3. **Cache invalidation**
   - Given a cached repack
   - When the original arc's size/mtime or a registered fingerprint changes
   - Then `handle_arc` logs `regenerating cache` and repacks; otherwise `arc cache up to date`
