# Task: fast-bootup quarantine + radar exclusion for injected songs

## Description
In `fast_bootup`'s owned `CheckStepDataActor::onUpdate` loop: (1) pre-flight every injected
item before the game's stock analysis touches it — if a declared slot has no steps in the
on-disk SSQ, quarantine it (record flipped to the complete-empty shape, music-DB corruption
flag set, one WARN) so the `ME1529` reporter is never reached; (2) exclude injected items from
the actor's per-side groove-radar maxima (snapshot/restore around stock items, skip the fold
on replay).

## Background
`fast_bootup::update_hook` processes items per cursor: Replay (apply cached writes, fold
radar via pure `replay::fold_radar`, release, advance) or Stock (re-invoke the original,
which analyses the loaded SSQ, writes the entry, folds the actor's radar accumulators
`+0xA8..` / `+0xBC..`, and — for a declared slot with zero steps+shocks — reports `ME1529`, a
hard boot blocker). Replay never reports; it only writes the `+0x1B0` flag. The record flip
1→6 ("complete, empty") is how replay keeps the stock path from analysing an emptied buffer.
The music-DB entry for an item is reachable the way fast_bootup already does for replay
(`find_music_by_mcode` / the item's entry pointer). Injected songs are identified by
`stepmania::is_injected(mcode)` / `is_injected_basename`; the item's SSQ bytes are the
materialised `_cache/stepmania/ssq/<b>[_N].ssq` (`core::ssq::check::check_ssq` is the
walker; `declared slots` come from `stepmania::entry_by_mcode(..).levels`). E8 (radar maxima
are library-global) is inferred from the fold code — confirm from `fold_radar`/the
completion block while in there and record the finding in the module header.

## Technical Requirements
1. Pre-flight (stock path, injected items only): read the item's SSQ bytes from the LayeredFS-resolved host path (the same `identity`/resolution fast_bootup already performs), `check_ssq(bytes, declared_slots_for_this_file)`; on failure (or unreadable file): flip the file record to the complete-empty shape exactly as replay does, set `entry+0x1B0 = 1`, WARN `FastBootup: injected '<b>' quarantined -- <reason>` (one per song), advance the cursor like a replayed item; never let the stock analysis run on it. On success: fall through to stock. Cost: one SSQ read + walk per injected item on a cold boot only (replayed items are already proven).
2. Radar exclusion: around a stock injected item, snapshot the actor's two per-side accumulator blocks (`+0xA8..+0xB8`, `+0xBC..+0xCC`) before the original and restore them after; on replay, skip `fold_radar` for injected items. Document the E8 finding (what the accumulators feed) in `fast_bootup/mod.rs`'s header.
3. Capture still records injected items (so warm boots replay them) — unchanged.
4. Pure tests where possible: the quarantine decision (`check_ssq` outcome → action) and the accumulator snapshot/restore arithmetic in a `crate::`-free file mounted by `scripts/validate_fast_bootup.sh` (extend it) or `validate_stepmania.sh`.
5. Gates: `cargo check --target x86_64-pc-windows-msvc`, `cargo fmt`, `./build.sh`, `./scripts/validate_fast_bootup.sh` + `./scripts/validate_stepmania.sh` green, path-leak grep.

## Acceptance Criteria
1. **Quarantine** — Given one materialised injected SSQ hand-corrupted (step rows removed) after indexing, when the cabinet boots cold, then boot succeeds, the song is hidden, one WARN names it, no `ME1529`.
2. **Radar** — Given an extreme injected chart, then a stock song's groove radar is identical with and without the pack present.
3. **No regression** — Stock songs' boot analysis, replay and the `ME1529` guard for stock files unchanged; `validate_fast_bootup.sh` green.
