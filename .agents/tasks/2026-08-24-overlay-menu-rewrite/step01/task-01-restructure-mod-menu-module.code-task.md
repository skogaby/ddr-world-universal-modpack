# Task: Restructure mod_menu into a module directory

## Description
Split the single-file `src/mods/mod_menu.rs` (~1,170 lines) into a
`src/mods/mod_menu/` subdirectory with zero behavior change. This is the structural
baseline for the overlay-menu rewrite: every later step adds files to this directory
instead of growing one monolith.

## Background
The overlay mod menu (triple-press 0) is being rewritten into a tabbed, themed modal
(see the design). Step 1 of the plan is a pure mechanical restructure so that the
rewrite lands as reviewable increments. AGENTS.md rule 7: mods that outgrow a single
file get a subdirectory (reference layout: `src/mods/note_types_expansion/`).

Five mods register overlay rows through this module's public API and must compile
untouched: `src/mods/timing_offsets.rs`, `src/mods/fps_unlock.rs`,
`src/mods/quick_restart_or_fail.rs`, `src/mods/music_wheel_song_length.rs`,
`src/mods/shader_fixes.rs`. `src/lib.rs` references `mods::mod_menu::ModMenuMod` and
`MOD_MENU_STATE`.

## Technical Requirements
1. New layout (target responsibilities from design §4.1, applied to the EXISTING code):
   - `src/mods/mod_menu/mod.rs` — `ModMenuMod` (Mod impl), gesture buffer
     (`on_zero_pressed`, constants), `open()`/`close()`, `ModMenuState` + `MOD_MENU_STATE`,
     `pub use` re-exports preserving every existing public path
     (`ScalarRowSpec`, `EnumRowSpec`, `RowChangeCallback`, `register_scalar_row`,

   the split.
3. `src/mods/mod.rs`'s `pub mod mod_menu;` continues to resolve (directory module).
4. All five registrant mods and `src/lib.rs` compile without modification.

## Implementation Approach
1. Create `src/mods/mod_menu/` and move the file to `mod_menu/mod.rs` unchanged; verify
   `cargo check --target x86_64-pc-windows-msvc` passes.
2. Extract `rows.rs`, `input.rs`, `render.rs` in that order, re-checking after each
   extraction; keep `mod.rs` re-exporting the public surface.
3. Run the full readiness gate: `cargo check` → `cargo fmt` (whole crate, no file args)
   → `./build.sh`.

## Acceptance Criteria

1. **Public API stability**
   - Given the five registrant mods and `src/lib.rs` unmodified
   - When the crate is checked for `x86_64-pc-windows-msvc`
   - Then it compiles with no errors and no changes outside `src/mods/mod_menu/`.

2. **Zero behavior change**
   - Given a diff of the split files against the original `mod_menu.rs`
   - When reviewed
   - Then every function body is byte-identical apart from module paths/imports/visibility.

3. **Readiness gate**
   - Given the completed split
   - When `cargo check`, `cargo fmt`, and `./build.sh` run
   - Then all pass cleanly (fmt produces no unrelated churn).
