# Task: Command-list record encoder (pure layer)

## Description
Create the pure record-encoding layer of the new `overlay_draw` service: functions that
build byte-exact game command-list records (scissor, SetShader, SetVSConstantF,
SetTexture, quad geometry) into a caller-owned buffer, with host tests validating every
layout and the size-chaining across a multi-record emission. This layer has zero game
dependencies and is fully `cargo test`-able on the host.

## Background
The game's renderer consumes command lists of `{u16 tag, u16 size}` records on a worker
thread. The DLL already emits records in gameplay (`src/mods/note_types_expansion/mine_render.rs`
appends SetTexture/SetShader/quad records; `src/mods/player_perspective/pass_rewrite.rs`
emits SetVSConstantF) — but those encoders write directly into the live arena inline.
The overlay-menu spike (and later the theme backgrounds) needs the same encodings as a
reusable, testable layer: one wrong `size` field desyncs the walker (crash class), so
byte-exact layouts deserve host tests.

## Technical Requirements
1. New module `src/services/overlay_draw.rs` (or `overlay_draw/` with an `encode`
   submodule if cleaner) containing a pure encoder that appends records to a
   `&mut Vec<u8>` (or equivalent) — no raw game pointers in this layer:
   - scissor on/off (tag 0x0C)
   - SetShader (tag 0x13: shader object as u64 + program index) — the pure layer takes
     the pointer as a plain `u64`
   - SetVSConstantF (tag 0x14, base register c48+, inline float4 payload, self-contained)
   - SetTexture (tag 0x11) — included for completeness/theme use
   - untextured quad (tag 0x03) and textured quad batch (tag 0x04) with the documented
     per-quad stride; pixel-space corner coordinates
2. Every record's `size` field must exactly match the documented layout; a
   `records_len`/walk helper validates size-chaining over a buffer (used by tests and
   later by the emitter's paranoia checks).
3. Host tests (this repo's pure-layer pattern, `#[cfg(test)]` in-module):
   - per-record byte-layout tests against hand-computed expected bytes
   - size-chaining integrity across a full POC sequence
     (scissor-on → constants → SetShader → quad → SetShader-restore → scissor-off)
   - payload alignment/self-containment of the constant record
4. Keep the API shaped for the impure emitter that follows (task-02): the emitter will
   copy the finished byte block into the live arena and bump the cursor in one place.

## Acceptance Criteria

1. **Byte-exact layouts**
   - Given hand-computed expected byte sequences for each record type
   - When the encoder builds each record
   - Then the output matches byte-for-byte (tests prove it).

2. **Chain integrity**
   - Given the full POC record sequence in one buffer
   - When the walk helper parses it by size-chaining
   - Then it visits exactly the emitted records and ends exactly at the buffer end.

3. **Host-testable purity**
   - Given the module
   - When `cargo test` runs on the host
   - Then the encoder tests compile and pass without any game/hook dependency.
