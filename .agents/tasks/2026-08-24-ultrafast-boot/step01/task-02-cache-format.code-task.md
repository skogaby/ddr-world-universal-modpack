# Task: Cache bin format layer (cache.rs)

## Description
Implement `src/mods/fast_bootup/cache.rs`: the pure, host-testable
serialization layer for `data_mods/_cache/step_data/v1.bin` — parse and
serialize per the design's Data Models section, with fail-open tiers.

## Background
The cache stores the boot-time analyzer outputs per file × difficulty × mode
so later boots can replay them. The format is hand-rolled little-endian (no
new crates), fully bounds-checked, and versioned. Any whole-file malformation
must degrade to "empty cache" (full stock boot + rebuild), never an error the
caller has to handle beyond logging.

## Technical Requirements
1. Types: `CacheFile { header, entries: Vec<FileEntry> }`;
   `FileEntry { game_path: String, identity: Identity, payloads: Vec<SlotPayload> }`;
   `Identity::File { resolved_path: String, size: u64, mtime_secs: u64 } | Absent`;
   `SlotPayload { difficulty: u8, mode: u8, ret: u8, result: [i32; 14], radar: [i32; 5] }`
2. Header per design: magic `DDRSSQC1`, `format_version: u32 = 1`,
   `gamemdx_stamp: u32`, `gamemdx_size: u32`, `entry_count: u32`
3. `parse(bytes, expected_stamp, expected_size) -> CacheLoad` where
   `CacheLoad::Loaded(CacheFile) | Empty { reason: &'static str }` — bad
   magic, wrong version, stamp/size mismatch, truncation anywhere, or counts
   exceeding remaining bytes all yield `Empty` (never panic, no `unwrap`)
4. `serialize(&CacheFile) -> Vec<u8>` — exact inverse
5. Sanity caps during parse (e.g. entry_count ≤ 65536, payload_count ≤ 10,
   string len ≤ 1024) so corrupt counts cannot cause huge allocations
6. Pure: no I/O, no game types, no statics — file I/O belongs to identity.rs
   and the writer (later steps)

## Implementation Approach
1. Small internal `Reader<'a>` cursor with checked `u8/u16/u32/u64/i32/str`
   reads returning `Option`; parse is a straight-line decode over it
2. Serialize via a `Vec<u8>` writer with the same field order

## Acceptance Criteria

1. **Round-trip fidelity**
   - Given a `CacheFile` with mixed entries (file + absent identities, 1..10 payloads, doubles stored as raw i32 pairs)
   - When serialized then parsed with matching stamp/size
   - Then the parsed structure equals the original

2. **Fail-open on malformation**
   - Given a serialized cache truncated at every field boundary (loop over prefix lengths), or with bad magic, wrong version, wrong stamp, wrong size, or absurd counts
   - When parsed
   - Then the result is `Empty { reason }` for the whole-file cases — never a panic, never a partial `Loaded`

3. **Host tests in-module**
   - Given `cargo test`
   - When run on the host
   - Then round-trip, truncation-sweep, and invalidator tests pass
