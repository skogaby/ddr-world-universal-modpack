# Task: Replay arithmetic layer (replay.rs::compute_slot)

## Description
Implement the pure replay computation `compute_slot` in
`src/mods/fast_bootup/replay.rs`: given one cached `SlotPayload` (result[14],
radar[5], ret) plus `has_chart` and the variable-BPM threshold, produce the
exact set of music-DB slot writes the game's onUpdate would make. Pure and
host-tested; the unsafe applier that writes them into game memory is a later
step.

## Background
On a cache-hit boot the replay must reproduce, byte-for-byte, what a stock
analysis pass writes into each music-DB entry. This task captures ONLY the
arithmetic (the transcription of onUpdate's post-Analyze math from the RE),
isolated from any game pointer so it can be fixture-tested.

## Technical Requirements
1. Define `SlotWrites` capturing every per-slot output: max/core/min BPM ints
   (`result[12..13]/[10..11]/[8..9]` reinterpreted as f64 then `as i32`
   truncation-toward-zero), shock flag (`result[2] > 0`), variable-BPM flag
   (`abs(maxBPM_f - minBPM_f) > threshold`), the `result[4] > 0` flag, EX
   score (`(result[0]+result[1]+result[2]) * 3`), corruption flag
   (`has_chart && (ret == 0 || result[0]+result[2] == 0)`), and the u16
   min/max-BPM accumulator contributions (the int values, with the skip-zero
   rule surfaced so the applier can honor it), plus the radar 5-tuple passed
   through for the actor accumulators.
2. Doubles are stored in the payload as raw i32 bit-pairs; reconstruct via
   `f64::from_bits((lo as u32 as u64) | ((hi as u32 as u64) << 32))`.
3. `compute_slot(payload: &SlotPayload, has_chart: bool, threshold: f64) -> SlotWrites`
   — no unsafe, no game types.
4. Provide the accumulator fold as a pure helper too (max for radar[2..4] and
   the sota/thr8-gated radar[0]/[1]; the filename gate is decided by the
   caller and passed in as a small enum/bool pair).

## Implementation Approach
1. Mirror the design's write-set table one row at a time.
2. Keep the skip-zero semantics for the u16 accumulators explicit in the
   returned struct (e.g. `Option<u16>` contributions) rather than baking a
   memory read into this layer.

## Acceptance Criteria

1. **Write-set matches the table**
   - Given fixture payloads (normal chart; zero-BPM; variable-BPM on both sides of the threshold; shock present/absent; failed-chart zeroed payload)
   - When `compute_slot` runs
   - Then every field equals the design table's specified value, including truncation-toward-zero for the BPM ints and the corruption truth table over (has_chart × ret × steps+shocks)

2. **Double reconstruction**
   - Given known f64 BPMs encoded as i32 pairs
   - When decoded and truncated
   - Then the ints match `value as i32` for representative values (incl. exact-integer and fractional BPMs)

3. **Host tests in-module**
   - Given `cargo test`
   - Then all fixture cases pass
