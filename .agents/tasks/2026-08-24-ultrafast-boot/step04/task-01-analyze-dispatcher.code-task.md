# Task: Analyze dispatcher service + NTX migration

## Description
Create `src/services/analyze_hook.rs` — a shared single-detour dispatcher for
`IStepReader::Analyze` (judge_hook pattern) — and migrate NoteTypesExpansion's
mine injection from its own detour to a registered post-subscriber. No
fast_bootup consumer yet; NTX is the proving load.

## Reference Documentation
**Required:**
- Design: .agents/planning/2026-08-24-ultrafast-boot/design/detailed-design.md (§Components → 1)

## Technical Requirements
1. Service owns one `GenericDetour<AnalyzeFn>` (OnceLock, store-before-enable);
   `init(&SignatureStore)` resolves `step_reader_analyze` and arms it;
   `register_post(fn(&AnalyzeArgs, u8))`; `is_available()`.
2. Dispatcher calls the original, then every post-subscriber in registration
   order, each under `catch_unwind`; returns the original's `u8`.
3. NTX: keep SYMBOLS + actor-offset detection; drop its detour; register
   `analyze_post`. The injection body is preserved verbatim.
4. lib.rs inits the service right after judge_hook (before mods enable).

## Dependencies
- `step_reader_analyze` signature (already resolved)

## Acceptance Criteria
1. **No NTX regression**
   - Given a boot + a mines chart
   - Then boot-time `NoteType 'mines': injected …` lines appear and in-song
     mine behavior is unchanged; log shows `AnalyzeHook started` + NTX
     `registered Analyze post-subscriber`; exactly one detour on Analyze.
2. **Ordering independence**
   - Given capture (later) + NTX both registered
   - Then both fire post-original regardless of order.
3. **Fail-open**
   - Given `step_reader_analyze` unresolved
   - Then the service logs unavailable and subscribers no-op; mod unaffected.
